# 消息提醒细节补齐：231

本轮对照本地 Pro 消息页、MsgNotice/Qqbot 实现及已登录参考站的字段和操作。
外部商户处罚插件仍按先前约定暂缓，不制造处罚事件。

## 已接通的业务链路

- 余额不足、交易投诉、会员到期短信各用独立模板，三个网关各有对应模板，
  不覆盖登录验证码模板。会员到期保留独立追加短信的规则。
- 商户短信使用已验证绑定手机或已验证注册手机；普通资料联系电话不授予
  发送权限。中国大陆号码支持规范化的 `+86` / `86` 前缀。
- 管理员全部交易投诉支持独立短信路由，使用超级管理员明确保存的收件手机；
  可以只保存手机号，无需先配置群机器人 Webhook。
- 管理员群机器人、Telegram、QQ 凭据均可编辑、停用和清除，加密存储并使用
  revision CAS。页面不回显 URL 密钥、Token 或 AppSecret。
- Telegram 可以复用快捷登录的加密 Token；通知使用同一可信来源，轮换后
  历史任务不能使用新机器人身份。
- QQ 保存凭据与开始绑定是独立操作。绑定码只在当前组件内存中保留五分钟，
  回调必须签名正确、匹配一次性窗口且原管理员会话仍有效。支持取消和解绑；
  替换凭据撤销旧绑定。保存和回调均不主动发送“测试成功”消息。
- 发送器使用原领取事务内冻结的凭据和收件人；先提交永久 claim 再进行 I/O。
  未知结果不产生第二次发送机会。邮件也复用原事务连接，避免连接池嵌套获取。
- 首次可信投诉、通道当日金额/笔数限额、微信待确认收款接入实际出生点，
  详见 [通知来源核对](notification-sources231-2026-11-02.md)。微信确认不依赖
  商户是否保存过个人消息配置，冻结原 payee/AppID、模板摘要和固定签名路径。

QQ 事件验签按[官方安全文档](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/sign.html)
对时间戳与原始正文验证 Ed25519。未签名的接入验证仅允许短期不透明 challenge，
拒绝将 JSON 事件正文作为待签名 token，避免验证入口变成事件签名接口。

## 验证与发布凭据

最终凭据保存在本机 `.tools/notice231-20261102/acceptance.json`；部署凭据保存于
`.tools/deploy231/FINAL.json`。仅最终 completed/success 凭据代表验收或部署完成。
中途失败、跳过或被后续源码修改影响的记录均保留，不改写为通过。

测试只使用现有 PostgreSQL 与已存在的隔离 PHP 兼容运行器，每批/每文件独立
数据库，确认连接归零后清理。保留当前预览，不创建容器。真实服务的浏览器
业务测试在 loopback 模拟环境执行；生产仅做只读核验、备份及已授权的发布。
不发起真实资金交易，也不发送生产测试短信、机器人消息或绑定请求。

部署仅增加 188–191 四个迁移，已有 152 个迁移内容不变。停止 API 与 worker 后
迁移，新程序 33 项只读核对全零后切换。新配置、绑定或新版本事件已经产生时，
禁止回退到不认识这些授权记录的旧程序；不通过恢复旧数据库实现回滚。
