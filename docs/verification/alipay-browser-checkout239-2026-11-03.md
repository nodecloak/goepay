# 支付宝桌面二维码与手机跳转验收

目标版本：`2026.11.03-239`。本文记录发布前本地验收范围；生产发布结果以独立发布回执为准。

## 行为

- 原付款方式为 `page`：电脑端自动展示支付宝内嵌二维码收银台，手机端自动提交原支付宝表单，并保留手动继续按钮。
- 原付款方式为 `wap`：电脑端展示同一原订单的手机继续支付二维码，手机打开后按原 `wap` 方式跳转。不会改为另一种支付产品。
- 支付成功后，仅在本地订单确认已支付时返回商户。关闭、失败及状态待核实的订单不再展示可提交表单或二维码。

恢复原通道账户后，先验证存储表单的签名、应用、网关、订单及原付款方式。桌面 `page` 仅在内存中的展示副本增加 `qr_pay_mode=4`、`qrcode_width=230` 并重新签名。存储的表单、原订单、金额、商户、通道、账户和付款尝试保持原样；不重新下单，不切换为 `precreate/native`。

仅明确支持该能力的原生支付宝适配器使用新交互，其他插件维持原处理路径。采用带 nonce 的脚本、受限 iframe/CSP 和原有带签名过期时间的收银台授权。

可读取的本地原版参考为 `epay_release/plugins/alipay/alipay_plugin.php` 的桌面内嵌二维码模式；PHP 参考文件没有加入本次提交。

实际 Chromium 测试使用1280px桌面和375px手机视口，覆盖桌面/手机各自的 `page`、`wap` 四个场景。测试启用真实受限适配器，使用生成的 RSA 密钥及两个本地 TLS 网关/收银台：浏览器仅将模拟支付宝域名定向到这些本地端口，其他外联被拒绝，不修改系统证书或生产配置。

本地链路实际验证了3次 RSA2 表单提交、跨域303跳转、2次 RSA2 异步回调、4次签名商户返回、订单状态轮询，以及原有2笔订单/2次付款尝试的身份与金额不变。桌面页面模式为二维码模式4，手机不添加桌面参数；二维码230×230px完整位于320×300px的内嵌视口中，四边静区未裁切。四张最终截图及产品源码均经过独立复核。

这里没有验证真实支付宝 App、真实扫码或真实资金交易；全部资金链路仅为本地模拟，实际外部网络请求为零。
