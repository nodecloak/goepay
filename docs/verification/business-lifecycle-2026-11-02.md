# 管理端与商户端业务串联验收

本轮使用同一个新建商户串联用户组、商户创建、本人登录、签名下单、支付机构回调、退款和结算。资金操作均在 loopback 本地模拟环境执行；线上只进行发布及只读检查。

## 修复

- 本地模拟通道原先只允许种子商户 `1000`，无法验收新商户。增加 `GOEPAY_SIMULATION_MERCHANT_IDS` 明确白名单，默认仍只允许 `1000`；拒绝非规范 ID、重复项、通配符及超过 100 项的名单。仅 sandbox 的 loopback simulation 使用，configured 通道不读取此配置。
- 结算出款条件不满足时，原先直接显示英文原因。现在提示管理员核对执行开关、商户“允许代付 API”、审批、原冻结资金、收款快照或匹配通道；保留原权限判断与资金操作规则。

## 串联步骤

1. 管理员在页面新建用户组，设置统一支付费率 200 万分比，并明确选择支付宝、微信通道继承路由。配置 T+0、手动结算、结算费率 2.5%。
2. 管理员在页面新增邮箱账号商户并选择该组。通过一次性凭据接口配置测试 MD5 密钥；商户在独立浏览器会话使用邮箱和密码本人登录，核实初始余额为零。
3. 使用商户签名分别创建微信 10.00 元、支付宝 20.00 元订单。篡改金额的回调先被拒绝；模拟付款后，通过真实 HTTP 回调入口并发重放每笔通知三次，核实只有一笔入账且订单保留正确用户组费率快照。
4. 另一商户查询及退款该订单均返回 404。新商户通过页面申请支付宝部分退款 2.00 元；相同请求重放返回原退款，原号改金额被拒绝。退回剩余 18.00 元后，再超额退款被拒绝。
5. 商户在页面保存收款资料并申请 1.00 元结算，管理员拒绝，原预占资金退回。
6. 商户在页面申请 5.00 元结算，核对手续费 0.13 元、净额 4.87 元。管理员核准后，未开启代付权限时不能准备出款，页面显示具体中文设置项。
7. 管理员在商户编辑页面开启“允许代付 API”，回到原结算准备唯一出款绑定并发送。重放同一 `/execute` 请求仍返回同一出款记录；商户结算列表显示已完成。
8. 独立 CLI 核对固定的 33 项账务检查及检查键集合，全部为零异常；各文件测试数据库均在零连接后删除。

| 检查点 | 商户可用余额 | 商户结算预占 |
| --- | ---: | ---: |
| 创建并登录 | 0.00 | 0.00 |
| 两笔支付入账 | 29.40 | 0.00 |
| 支付宝部分退款 2.00 | 27.40 | 0.00 |
| 支付宝剩余退款 18.00 | 9.80 | 0.00 |
| 申请结算 1.00 | 8.80 | 1.00 |
| 拒绝原申请 | 9.80 | 0.00 |
| 申请结算 5.00 | 4.80 | 5.00 |
| 出款完成并重放 | 4.80 | 0.00 |

退款费用承担方为平台：部分退款优先使用原商户净收入，最后一笔退款使用剩余商户净收入及原平台手续费；不能将部分退款按支付费率等比例扣除商户余额。

## 测试范围与隔离

永久回归位于 `web/e2e/live-business-lifecycle.spec.ts`，使用真实 Go HTTP 服务、PostgreSQL 和浏览器会话。脚本必须显式启用本地验收标识及环境文件，核对独占 GUID 数据库、loopback 地址、simulation 模式和关闭上游写入，不能直接用于当前本地预览或线上。

复用既有测试 PostgreSQL 容器，每个测试文件使用独立数据库；未创建新容器，未修改预览指针。商户通知地址使用保留的 `.invalid` 域名，未启动本地通知 worker；本轮串联的“回调”指支付机构通知入口，未冒充真实商户通知投递成功。

全量回归包括前端单元测试、类型检查、正式构建、模拟接口浏览器测试及真实本地集成测试。Go 改动仅在 `cmd/api` 的模拟器配置和其测试：重新运行该包全部测试、全仓库 vet 及 Linux 构建，并以逐文件 SHA 核实未改动核心沿用既有通过证据。

发布不执行数据库迁移、不修改通道配置；先核对源代码、产物、现网配置和 151 项迁移摘要，完成备份后替换程序。未知数据库版本或无法确认停机状态时禁止自动重启写入服务。详细测试回执与发布记录保留在本机忽略的 `.tools/business-flow225-20261102`、`.tools/deploy225`。
