# 页面支付错误展示修复

- 问题：浏览器访问 `/api/pay/submit` 时，通道权限等业务拒绝直接展示签名 JSON。
- 修复：仅在页面支付入口 `/api/pay/submit`、`/submit.php` 的浏览器导航或 Accept HTML 请求上增加错误展示边界。JSON 业务错误与 HTTP 错误统一显示中文页面；通道未授权、商户不可用、验签失败、参数错误和结果未知有独立提示。不回显未识别的底层异常、签名或未经验证的回跳地址。
- 保留：正常 HTML 验证页、成功 302 跳转保持原样；显式 JSON 调用及其他 API 不改变协议。没有修改通道授权、订单创建、回调、账务或支付重试规则。
- 页面：适配桌面与手机、禁止脚本及表单、no-store、no-referrer；仅提供固定站内首页链接。已扣款用户应联系商户查询原订单，避免重复付款。
- 验证：新增 Go 测试覆盖 HTML 错误、内容协商、成功跳转、HTTP 拒绝及敏感异常不回显；兼容与文档包测试、server vet 通过。实际本地 Go HTTP 服务使用无数据库、无通道的 Server，Playwright 在 1440/375 两个尺寸访问两个页面入口，4 个视图通过并保存截图。未运行全仓数据库集成测试。
- 原始测试、浏览器和发布证据存于本地 `.tools/submit-page-20261101/`。线上检查只提交无商户凭据的无效请求，核对友好错误页面，不创建订单或真实资金交易。
