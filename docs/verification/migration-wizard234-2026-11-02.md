# 易支付迁移向导验收记录

本次交付管理后台「系统管理 → 易支付迁移」，面向全新的 GOEPAY 安装。上传 UTF-8 MySQL SQL 备份，先核对预检查报告，再明确确认执行，最后查询事务提交结果。操作说明见 [迁移指南](../migration/WIZARD.md)。

## 数据范围与边界

原生转换商户编号、可用余额、普通订单及有明确成功证据的退款历史；期初余额以双边账入账一次。完整原始 SQL 加密保存，配置、用户组、通道、旧密码/API 密钥、实名资料和插件数据等未转换内容只归档，不自动激活。

导入商户默认停用并生成新密钥。向导不切换域名，不连接源数据库，不执行上传 SQL，不补发历史支付通知，不创建退款、出款或结算任务。已有业务的目标、冻结/预授权及其它不能可靠映射的资金义务会阻止导入。不能把完整备份归档理解为所有旧功能均已完成原生转换。

## 修复过的实质问题

- 业务主密钥与结账用途派生密钥区分：最初一次本地流程浏览器完成，但 CLI 检查发现历史退款证明异常。已改为显式注入业务主密钥，缺少绑定返回不可用；不同密钥的回归测试及两次新数据库验收通过。该失败及原始回执保留，不计为通过，未上线。
- 拒绝原生字段中的无效 UTF-8，避免十六进制字面量被 JSON 替换字符静默改写；仅归档的二进制内容仍保全。
- 初始化管理员时对业务表使用非等待锁，遇到并发业务写入拒绝初始化；不重设已有管理员密码。
- 执行中状态查询不等待整个导入事务，业务忙时可读回原任务；已有商户会话和孤立商户身份也阻止导入。
- HTTP 429 使用固定可行动提示，说明繁忙或暂存配额/空间限制，并引导读取记录或联系管理员；不回显任意服务端错误，不自动重试。
- 发布脚本同时核实前序 API/CLI 的版本、提交和源码 SHA，拒绝身份不一致的前序产物。
