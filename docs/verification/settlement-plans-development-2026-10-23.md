# 60 结算申请计划开发证据

开发源码位于 E:\GOEPAY，schema60。全部测试使用本地随机 PostgreSQL schema、合成账户与本地假通道。此文不是完整候选通过或生产兼容签署。

## 已实施范围

计划固定 1–100 个商户，由商户明确选择当前加密收款配置版本并主动加入。定义更新使用 CAS 并停止旧定义；授权必须经过超级管理员资金密码，即使全局逐动作确认开关关闭也不豁免。授权固定定义、商户/收款版本、现有费用/留存/成熟规则、期限以及每项/每次/每日金额和每日项数。撤销和到期阻止新增申请，原已预留申请仍按不可变来源审核。

每个计划时段只有一个原运行/任务；同一商户业务日只有一个自动生成意图。所有预算、原申请、原资金预留、不可变来源和审计同事务提交，共用申请助手在子事务内执行，失败必须回滚子事务后才能记录跳过原因。独立执行器默认关闭且不加载支付凭据，只消费 settlement-plan.generate；现有只读支付核对 Worker 不提交付款。CLI 新增 invalid_settlement_plans，全部报告共 15 项；恢复脚本从原父记录检查六个投影及孤立来源。

## 真实失败与修复

| 红测 | 修复及验证 |
|---|---|
| 旧授权 a1 被较小 a2 替换后回退 head 仍可使用，4.026s | SQL 同事务新授权链与 Go 最新版本/授权双重验证；正常 SQL 拒绝回退，单独损坏恢复夹具也被 Go 拒绝 |
| 来源 item HMAC 损坏后原 run/checker 拒绝但人工审核仍批准，6.235s | 申请重放、审核、payout 读取及 prepare/claim/cancel/query/resolve 共用入口均验证不可变原来源 |
| 等待账户锁时 D1 被改为 D0，旧授权继续生成，5.027s | 锁定成熟配置、取得资金锁后和请求私有 guard 再核验；4.771s 通过 |
| 共享申请助手在预留后晚返回冲突，外层提交孤立请求，4.639s | 原 helper 在精确绑定的 pgx 子事务内运行，失败先成功回滚再写结构化结果 |
| 全局日次数用尽造成重试循环，4.900s | 回滚子事务后记录 daily_limit，相关两项 11.180s 通过 |
| 收款偏好更新的 UPSERT 先触发新增校验，3.968s | 首次 INSERT 与后续 CAS UPDATE 分开；6.837s/HTTP4.534s 通过 |
| 授权时间 pgx 时区与 HTTP Z 格式不一致导致撤销 409，4.324s | HMAC 时间统一 UTC，微秒精度约束；4.530s 通过 |
| 挑战摘要没有实际商户/掩码收款与政策，3.648s | 只从同一可信快照展示范围和费用，真实 HTTP 4.484s 通过 |

独立生成器最终测试 15 项及 6 个子场景，80.112s 全通过，payment vet exit0。证据目录 `.tools/checkpoints/60-generation-review-evidence-c78245af-419d-4342-8ecd-87ca9748a236` 保留三个 P1 原失败、原断言及最终源码哈希。其他证据：`60-authority-review-evidence-5c991d82-3606-4bfd-965b-e846406997cb`、`60-funds-review-evidence-0676c683-9d3d-4653-bd27-3dd10eb48fd4` 和 `60-schedule-policy-evidence-a25b4914-c627-48e6-8394-095587f27b70`。

前端和独立执行器专项另见 [控制台](settlement-plans-console-2026-10-23.md) 与 [执行器](settlement-scheduler-2026-10-23.md)。前端 97 单元/86 mock 浏览器通过；队列1.536s、执行器9.216s、命令0.940s及 vet/Linux 构建通过。以上必须由固定候选全库与部署后验收补充。
