# 管理端与商户端表单复核（最终本地验证完成）

本记录补充 221 版本之后的浏览器复核。参考站为 p.ma3fu.com，Go 实例为 go.ma3fu.com。页面读取、展开弹窗和本地写入测试分别记录；不会把进入菜单、加载中的空表或旧报告当作完整功能通过。

逐节点覆盖见[本轮节点与交互核对矩阵](production-node-ux-matrix-2026-11-01.md)。该矩阵明确区分线上读取、本地写入和暂缓上游，不把生产页面读取作为真实资金操作验收。

生产环境只读取菜单、筛选、列表和未提交表单。新增、修改、失败恢复及账户登录使用独立本地合成 PostgreSQL；复用已有容器，保留冻结预览。未发起真实付款、退款、补单、分账、转账或结算。

## 读取覆盖与边界

本轮已读取参考管理端的仪表盘、交易与五类统计、分账、转账与三类统计、结算、商户与用户组、支付配置、进件、投诉、风控、用户标识、应用、系统等可见主节点；系统设置逐一切换 17 个分类。新增弹窗另读取商户、用户组两类配置、黑名单、分账规则、付款、域名、支付通道、支付方式、轮询、公众号和管理员。未提交这些生产表单。

商户端已读取双方账户/API、订单/退款/日统计/地区统计、结算记录/设置、资金明细、聚合收款、仪表盘与充值；参考站另读取进件/管控。Go 另读取会员、保证金、站内转账、消息、打印、自动结算参与、授权域名、投诉、分账规则/记录、子通道、单笔付款、红包、批量付款、邀请、实名认证和提现。读取及未提交表单不等于真实资金写操作验收。

进件、投诉、实名认证、OCR、应用下载等外部业务插件继续沿用用户“其它插件先不做”的范围。它们的本地列表不代表上游已接通。参考站不可用或当前配置未开启的节点单列，不以虚构返回补齐。

本轮用户组的结算方式限制、代付费率/红包、保证金、商品名/域名及微信合单已有实际消费者与定向验证。邀请策略保持现有独立、类型化版本页面；随机增减金额、商户每日额度、商户自有资金源代付等缺少相应资金模型，不以同名表单或已有不同口径字段冒充。付款通道的授权来源与凭据配置采用独立受控模型，新增通道字段仍与参考站有差异。

`settle_set_hour` / `settle_hour` 暂不映射为 D+1 余额成熟边界。本地 Pro 明文 `app/cron/Settle.php:76-85` 证明它在启用后按组/全局小时与当前小时比较，限制自动生成结算列表，并检查商户当日是否已有结算；生成金额使用商户当前 `money`。前端静态资源将其标为“D1日切时间点”，但商户和管理员 Settle 控制器为 Swoole 加密，无法据此核实手动申请的余额边界是否也随小时移动。本轮浏览器在参考站选择 D+1 后仍未出现小时字段，说明还受全局开关等条件控制。Go 现有 D+1 使用上海时区午夜，计划执行时点由已有 Plan Schedule 决定；本轮保留这两项既有行为，不以标签推断资金语义，也不新增与 Plan 重复的生成时点配置。该差异仍为未完成项。

## 验证记录

最终前端快照包含 954 个输入文件：313 个单测文件、1,753 项测试全部通过，类型检查及生产构建通过。独占静态服务器使用同一份 113 个生产构建资产，桌面和手机浏览器完整回归 638 项通过。另以最终源码重新编译程序，9 个文件、15 项实际本地后端联动全部通过；每个文件使用独立合成数据库并在零连接后清理。回归前后重新核对输入与构建哈希，不使用重试掩盖失败。

较早尝试中的允许方式夹具缺失、旧微信元数据夹具、共享 Vite 被相邻 runner 清理中断，以及 Python 静态服务器的一次连接失败，均保留原始结果。夹具补全实际 typed API 后保留原业务断言；连接问题先以 2,048 次本地并发请求及原扫描用例重复诊断，再改用独占 Node 静态服务器。以上失败结果未改记为通过，最终完整结果来自新的独立运行。

实际本地联动包括用户组新增/编辑/持久化/删除、联系账号创建后本人商户会话与资料读取、加密微信应用草稿新增/保留原凭据编辑/归档、黑名单、公告、订单、逐菜单读取、权限及结算授权等操作。Linux API/CLI/Worker 构建及全项目 `go vet` 通过。完整 Go 回归及额外浏览器、客户端互通验证也已完成，结果如下。

首次 Go 全量在旧会员基线修复场景发现真实回归：已购买且仍有效的会员，被新的有效组读取器提前以“管理员基线未决”拒绝，进而无法创建订单。执行 122 批后停止，其余批次和发布均未启动，原失败及清理回执完整保留。修复将未决基线检查限定到实际回落基线时，仍拒绝过期、无效会员组和禁用商户；永久测试另覆盖真实组锁等待期间到期。该修复后的全部 Go、实际本地浏览器及 Linux 构建已使用新的输入快照重新验证，首轮结果不计入最终通过数。

随后完整观测快照执行 71 个包、3,029 项测试和 1 个示例：2,984 通过、41 个条件用例跳过、5 个失败，未改记为通过。失败分别涉及结算模式拒绝的错误优先级、停用组能力读取、关闭功能后的历史读取旧断言及 D+0 展示旧断言；独立界面复核还发现显式管理员权限缺少收款资料路由。修复保留原资金授权与重放边界，新增真实并发管理员、非空历史余额、未知批次和零资金预留回归，47 项定向用例全部通过。

最终 Go 快照为 2,452 个输入文件，相对完整观测快照恰好 16 个已复核文件变更，无删除或域外修改。最终源码重新执行全部 3,036 项测试和 1 个示例，303 批全部完成。新增用例及原 5 个失败场景优先执行通过后，再执行完整套件；没有用旧快照定向结果代替全量。标准运行的条件用例随后以专用环境实际执行：12 项 Go 浏览器、1 项 Node 客户端和 16 项 PHP 接口互通全部通过。最终 3,037 项通过、0 项失败，剩余 0 项条件跳过。
