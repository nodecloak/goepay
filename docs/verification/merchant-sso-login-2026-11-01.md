# 排查报告：商户代登录缺少后台账号

## 现象摘要

管理员商户列表“一键登录”返回 `enabled merchant login account required`，界面却提示代登录结果未知。

## 入口与调用链

`MerchantDelegationPanel.consume` → `POST /console/v1/admin/sso/grants` → `Server.ssoConsole` → 查询启用的商户及其启用的 `console_users` 账号；成功后才可单次消费授权、建立带管理员归属的商户会话。

## 关键逻辑

商户可以只配置 API 而不设置后台账号。代登录要求已有启用的后台账号；这项前置条件不应绕过。旧前端将授权签发拒绝、消费拒绝与消费网络结果未知混为一谈，并读取可能无关的旧商户会话。

## 查库验证

仅通过 `BEGIN READ ONLY` 查询商户 ID、启用状态及后台账号计数，最多 50 行；未读取密码、密钥或会话值。目标商户 10002 已启用，后台账号数为 0；另一个商户账号状态正常。未修改生产账号或资金数据。

## 结论

- 数据条件：目标为尚未配置后台账号的商户，授权签发按既定规则拒绝。
- 交互问题：明确拒绝被误报为未知结果，没有直达配置入口。
- 下游：授权尚未签发，无支付通道调用，也没有资金操作。

## 修复与验证

- 将签发前失败、明确的请求拒绝、消费结果未知分别处理；签发前失败和明确拒绝不读取旧商户会话，不自动重复写请求。
- 缺少账号时显示中文原因，具有商户编辑权限时提供“设置后台登录”入口，打开已有商户编辑表单。后台拒绝条件、会话时限、单次消费与撤权机制保持不变。
- 会话回读确认成功后清除未知提示，显示已确认的商户后台入口。
- 12 项组件测试、5 项 Playwright 测试及 TypeScript/Vite 构建通过；新增测试先复现旧逻辑失败。浏览器覆盖明确拒绝后的配置入口、正常代登录和未知结果回读。
- 本次不自动创建账号、设置密码或启用停用账号。需管理员在编辑表单中明确配置，再重新发起代登录。

原始日志位于本地 `.tools/sso-fix-20261101/`。没有重跑全仓后端测试；本次仅改前端交互。
