# 默认收款通道修复验收（2026-11-03）

## 问题与行为

原先普通收款直接使用服务器的显式商户授权映射。新建商户只写入商户、登录账户和用户组，没有该映射条目，因此商户仪表盘没有通道，下单也被拒绝。

增加独立的 `GOEPAY_DEFAULT_PAYMENT_CHANNELS` 公共收款来源池。仅未配置显式授权的商户可以继承，且继续受商户启用/收款状态、当前有效用户组、支付方式、专用通道和轮询规则限制。显式空列表仍禁止继承；私有别名仍要求原商户授权。默认池不扩展转账、自动结算或预授权冻结权限。

原订单恢复使用已经封存的上游账户与请求，不因当前用户组、默认池、轮询开关变化而重新发起支付。新增只读主机诊断命令，独立于 API 正常启动流程，不执行搜索索引重建、默认样式初始化或服务商请求。配置说明见 [默认收款通道](../deployment/default-payment-channels.md)。
