# 新商户默认收款通道

`GOEPAY_DEFAULT_PAYMENT_CHANNELS` 是独立的公共收款来源池。例如，实际注册的微信、支付宝来源分别为1、2时：

```dotenv
GOEPAY_DEFAULT_PAYMENT_CHANNELS=[1,2]
```

只填写已经加载且准备向普通商户开放的通道来源 ID。未配置或 `[]` 关闭默认继承；未知来源、重复 ID、非整数或无效 JSON 会阻止 API 启动。新增这个配置后重启 API；以后新建商户自动按当前有效用户组继承，无需逐个修改服务器配置或重启。

`GOEPAY_MERCHANT_CHANNELS` 的显式商户条目仍优先：已有列表保持原义，显式空列表禁止继承。只有未出现在该映射中的商户才尝试使用默认池。用户组可以关闭支付方式、选择池内通道或轮询策略；选择私有来源不会获得额外授权。私有父通道别名仍须原有经过认证的商户授权，后台用户组编辑不能代替它。

商户必须已启用、收款状态正常，用户组须有效，会员到期后按原规则回到基础组。用户组、支付方式或具体通道关闭后，新订单继续被阻止；已形成上游操作的原订单按原请求和原账户恢复，不重新发送支付，不切换账户、不重新计费。

默认池用于普通收款。预授权冻结仍要求显式商户通道授权，避免仅开通冻结、却没有后续扣款授权。默认池不会扩展转账、分账出款或自动结算的通用通道授权；退款继续核实原订单账户及独立退款权限。

管理员可在服务器使用同一 API 二进制做只读诊断，不监听端口，不创建订单，不请求服务商：

```sh
/opt/goepay/current/api check-payment-admission 10000,10001,10002,10003
```

命令需要与 API 服务相同的受限运行环境和主密钥。不要在命令行粘贴凭据；通过已有服务环境或受控运维包装器执行。输出只含商户编号、是否存在、授权来源、收款通道 ID/类型及原显式通道 ID，不返回密钥或收款账号。`operator_channels` 是原显式通道范围，不表示已经开通出款。

修复已有商户时，应先备份环境文件，仅新增该默认池配置，保留原显式白名单、用户组费率、商户状态及所有资金记录。对配置变更前后分别做只读诊断与账务核对；资金流程在本地模拟环境验收。
