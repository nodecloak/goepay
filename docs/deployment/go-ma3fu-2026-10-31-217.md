# Go 开发文档与 Go SDK 发布记录

日期：2026-10-31。版本：`2026.10.31-217`。文档：<https://go.ma3fu.com/doc/index.html>；Go SDK：<https://go.ma3fu.com/doc/sdk/GoEPay_Go_SDK.zip>。

## 用户反馈与实际修正

当前服务器运行的是 Go 后端，但此前公开文档从旧版整理而来，SDK 页仍只介绍、提供 PHP 客户端。上轮官网模板改版增加了文档入口，没有同时完成文档重写，导致定位和客户端语言不清晰。本轮按当前 Go handler、签名投影和通知代码重写 17 个正式页面，保留其已有路由及锚点，加入 Go 服务身份、Go 快速接入、实际参数和返回边界。

Go SDK 现在是主要下载和示例入口。新源码包包含标准库客户端、签名及响应解析、可运行的离线例子、本地测试、README、独立 go.mod 和文件清单。已实现离线 `SubmitURL`、五个 V2 支付 JSON 接口 `Create/Query/Refund/RefundQuery/Close` 以及 `VerifyNotification`；不包装商户列表、转账或 V1。模块名 `example.com/goepay-sdk` 是保留示例，明确通过本地 replace 引用，没有编造公开模块仓库或发布版本。

Go 客户端分开处理请求及返回的空白签名规则，验证平台 RSA 与 300 秒时间窗，拒绝重复参数/JSON 键、嵌套回包、无效 UTF-8、无签名成功、超大响应和重定向。金额与数字不经过浮点转换。使用独立 HTTP transport、HTTPS、上下文与超时，不继承宿主全局 dialer/代理，不自动重试资金请求。验签不代替订单、金额、商户及持久化业务幂等核对，代码和文档均说明此边界。

旧 PHP 客户端的两份 ZIP 保留原字节，明确标为维护已有 PHP 商户的兼容下载；没有将 PHP 文件改名冒充 Go SDK。`submit.php/mapi.php/api.php` 也是 Go 服务保留的兼容 HTTP 路径，文档说明它们与服务器实现语言的区别。

协议审计同步修正文档中的实际错误：退款处理中返回 `code=-1`，V2 业务错误通常也签名而裸 HTTP 错误可能没有签名，请求必须唯一标量，数组/对象不在顶层签名内，时间戳为正整数 Unix 秒、窗口含边界，通知确认必须 HTTP200 及精确正文 `success`，金额、转账能力与未知结果处理按 Go 实现描述。

## 收银台协议修复

审计发现 V2 请求进入收银台后，原签名意图未保存协议版本，选择支付方式时固定传入 `legacy=true`，实际把订单记为 V1 并生成 MD5 通知，导致 Go V2 客户端无法按 RSA 验证。

本轮在已有 HMAC 签名意图中保留认证入口的 V1/V2 协议，创建订单时使用原协议，页面输出继续由收银台路径控制。历史无版本字段的签名令牌仍按 V1 处理；显式空值、null、数字、未知版本和篡改被拒绝。没有迁移旧订单、改变资金逻辑或重新发起历史交易。新增回归使用实际隔离 PostgreSQL 和本地假通道，覆盖 V2 空类型、强制页面/接口收银台，V1 MD5/RSA 入口、重放、旧令牌和实际通知签名。
