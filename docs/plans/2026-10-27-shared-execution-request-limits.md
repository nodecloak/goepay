# 支付执行视图共享请求限流状态

全仓vet发现子通道执行视图按值复制Server中的互斥锁；在请求计数map尚未初始化时，各视图还会建立独立预算。修复只处理进程内状态，不改支付账户、费率、旧事实、数据库结构或原权限来源。

采用共享指针状态持有锁、登录与收款计数及清理时刻；零值Server安全延迟初始化，执行视图复制前固定原状态。登录、收款和后台缓存清理均使用同一状态，保留原作用域、次数、期限和容量上限。后续父通道执行视图复用同一clone入口。

先用实际PG子通道订单恢复执行视图，复现视图不能共享预算的问题，再补并发竞态与过期/容量/作用域回归，运行全仓vet/build和受影响支付、查询及后台清理测试。非作者审查、冻结和部署仍分别验收。
