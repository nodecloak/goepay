# 父子通道组合集成（开发中）

在已有不可变子通道账户、费用报价、全局限额和风险来源之上，合并可管理父通道账户、微信应用关联和后台原版操作。此文档不代表全部后台兼容或部署验收完成。

## 执行与权限

原费用锚、实际子账户和当前父通道权限分开验证。父通道账户恢复不得覆盖已有子通道 SDK、网页授权或小程序资料；当前父通道开关、签名授权、管理员商户白名单及原进程写入开关仍约束新操作。历史查询和签名回调恢复原账户，不以当前账户替换。

恢复视图共享原进程限流状态和权限引用。页面和回调恢复只修改请求内的 SDK 映射。小程序、网页授权的旧意图在交换一次性代码之前重新验证当前授权；最终首次支付再次检查，拒绝时事务不保留付款尝试或频率消耗。

## 新父通道作为子通道来源

只有已配置的闭合子通道模板能够派生新父通道的账户输入。派生使用已认证的父账户快照并保持真实父通道 ID。子账户自己的 AEAD 内保存可选的原授权来源与快照；旧子账户缺省字段省略，原 MAC、原 JSON 和历史数据库行不回填。

历史恢复依赖子账户保存的原构造来源，不能借用最新父账户秘密。新父通道付款来源缺失时，即使子账户来源完整也必须拒绝；真正早于父账户版本管理的完整子通道历史则继续恢复。

## 验证安排

固定开发副本运行原父通道、子通道、限额、账户轮换、回调及风险回归。新增本地 mTLS 用例覆盖新父通道建子通道、父子独立轮换、历史查询与退款、准备后关闭或撤销权限、新付款来源丢失等场景。后台保留原费率确认、未知结果只读核对、冲突刷新和键盘焦点回归。

完整最新源码的测试、竞态检查、构建、迁移恢复演练及独立代码审查仍须全部通过后才能交付。整个流程使用本地合成数据及模拟上游，不访问生产或发起真实资金交易。
