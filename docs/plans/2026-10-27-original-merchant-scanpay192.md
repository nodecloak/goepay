# 商户扫一扫收款

本项从191累计开发源码继续，不表示已部署，也不表示其它剩余核心功能完成。现有主源码188、本地预览151及私有Git151保持原状态；所有新增验证使用本地合成数据库、签名和mTLS上游，不访问生产或发起真实资金交易。

## 本地原版依据

Pro `app/controller/user/Scanpay.php` 为加密控制器，未解密或执行。公开前端 `index-Kun9uPxi.js` 的原入口是独立 `/scanpay`，从聚合收款页进入，不是新增侧栏一级菜单。微信/支付宝内直接跳转，桌面聚合收款入口显示可用手机打开的收款页面二维码（不携带会话）。它有最多6位整数/2位小数的金额键盘、备注编辑/确认/取消；微信JSSDK、支付宝JSAPI或摄像头扫码后，以 `auth_code/money/remark` 请求收款，展示服务端实际金额和结果。`index-_K93c9Ev.js`、`result-YvUSs2mb.js` 的路由/结果页与本轮只读审计相符。`app/sql/install.sql` 的原 `scanpay_open` 缺省明确为1；原后台商户相关tab的“开启付款码支付”0/1开关、用户sys布尔能力控制入口。原公开前端只作为行为和样式对照，不复制厂商脚本进发布源码。

## 行为

1. 商户在聚合收款页进入独立收款页面，输入金额、编辑备注，调用用户主动打开的扫码能力。摄像头/扫码枪或手动输入作为可验证的本机方式，付款码只保留在内存；退出、取消、提交结束均清除。未经用户操作不访问摄像头，不从生产加载SDK。
2. 保留原金额键盘、扫码取消、结果页和返回入口。桌面与375px均验收；超限金额、重复小数点、备注取消、二维码格式和支付产品不匹配应有明确反馈。
3. 使用当前商户本人持久会话、CSRF和当前有效权限。代登录不得发起新扣款；所有权、会话过期/撤销及商户停用必须在事务最后及实际上游I/O前重新验证。
4. 共享现有真实通道路由、用户组、父子通道、费率/最低费/买家承担、额度、风控、订单快照和SDK执行链。不得将商户密钥交给浏览器，也不通过构造签名和重新请求HTTP接口绕过领域校验。
5. 采用准备与提交分开的稳定请求号。准备阶段固定原订单、路由和M/C/N/F，只有可确认的准备结果才允许发送付款码。响应丢失后恢复同一原单，不能凭一次404或超时自动新建第二笔扣款。未知结果保持处理中，查询原渠道、原账户和实付金额；摄像头取消与上游撤销为不同动作。
6. 付款码、验证码、会话和SDK私钥不进入日志、URL、浏览器持久存储、通用记录或公开响应。恢复仅持有商户范围内的请求号；服务端再次验证归属及不可变来源。
