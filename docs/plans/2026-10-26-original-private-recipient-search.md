# 原账号、姓名和备注搜索

本机Pro结算模块index-Cpj26fBW.js使用value搜索结算账号/姓名；付款模块index-CYTHVGS4.js的column选项包括account、username和desc。Go已恢复非私密编号/金额搜索，但这些原选项仍缺失，相关值位于原申请收款快照或转账意图的加密载荷中，不能用当前商户资料代替，也不能把脱敏展示值当完整搜索来源。

158增加独立、可重建的私密搜索投影，保留原加密载荷及其身份/财务证明不变。纯模型负责Unicode小写、字面子串、按字段隔离的带密钥字符/双字符索引和投影证明；PostgreSQL只保存不含原文的令牌和源密文摘要，用GIN候选查询。返回前按原加密载荷核实真正包含关系，防止令牌候选的顺序误匹配。索引仅用于只读筛选，不作为身份、金额、授权或出款依据。

新配置/转账意图与投影在同一事务持久化。迁移只新增投影表，启动时从实际旧密文和已验证原来源构建缺失投影，完成前不接受请求；GET不补写。历史查询结果、统计、分页及CSV使用同一候选集合，独立认证商户范围始终保留。宽泛查询超过候选预算必须明确提示缩小范围，不返回截断结果。新增结算搜索框和付款原三选项，草稿/已应用、跨上下文取消、错误清空与完整字段别名保持既有规范。

先写纯索引测试和实际PG/HTTP红色测试，覆盖中文、大小写、原快照与后改配置、两角色隔离、字面特殊字符、令牌假阳性验证、事务失败回滚、旧密文回填但原行不变、GET只读及列表/统计/CSV同范围。只使用本地合成账号和内存模拟通道，无生产访问或资金交易。冻结后进行前端、双平台、迁移/账本、PHP及独立部署验证；不将本项等同全部UX完成。

实现补充：查询最多核实2000个候选，超过上限明确要求缩小范围，不返回截断结果；同批候选的原始密文采用一次批量SQL读取。API启动先补齐缺失投影，并分批验证已有投影的来源摘要、商户和证明；发现篡改则启动失败，不重签已有数据。CLI migrate保持独立，迁移SQL仅建表与索引；旧版本测试数据库写入可保留其真实旧表结构，检索接口本身始终要求92迁移完整。备份恢复部署必须包含启动回填和完整索引验证。
