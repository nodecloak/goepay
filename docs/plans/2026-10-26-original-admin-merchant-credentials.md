# 管理员商户密钥操作

本机Pro商户编辑的“密钥信息”有重置MD5密钥、生成/重置商户RSA密钥对、单独展示私钥，以及签名方式设置。当前Go只允许手工填写新密钥；商户本人已有安全RSA生成流程，管理员缺少对应入口。先恢复管理员的两种生成动作，继续单独核对原MD5+RSA兼容模式，不将现有MD5/RSA单选伪称为已等价。

复用现有2048位RSA、PKIX公钥与PKCS8私钥格式，以及商户API密钥的AEAD存储。只在本人super管理员的原会话、CSRF和真实数据库权限复核后操作；普通管理员已有手工字段权限不自动扩展成新的生成授权。后台和事务均核验同一目标完整ID，禁止代登录、商户调用、query覆盖、未知或重复JSON字段。

新增管理员GET `/merchants/{id}/credentials` 仅返回当前算法、公钥、配置修订与不包含秘密的不可伪造指纹；不返回已有MD5密钥。POST子路径 `reset-md5`、`generate-rsa` 精确接受expected_fingerprint。生成前校验当前原会话与指纹；最终事务再次锁商户、管理员/会话，校验指纹，更新单个密钥及config_revision，写不含秘密的审计，再按数据库时钟复核会话才提交。RSA私钥不进入Store、数据库、审计或日志；MD5为16随机字节的32位十六进制，只存AEAD密文。已有算法不因生成动作而切换。

并发同指纹仅一次成功；丢响应重试旧指纹必须409，不能悄悄生成第二套密钥。新的明文只在提交成功后返回一次；浏览器只在当前弹窗内存显示，关闭或切换商户清除，不持久化、不自动复制。原编辑页密钥页签放两个按钮与明确确认，展示目标商户ID；取消不发送写请求，关闭保持焦点，375布局可用。既有普通资料草稿与原单查询不受影响，保存草稿不能覆盖刚生成的密钥。

先用真实PG/HTTP红色测试覆盖权限、CSRF、并发CAS、过期/撤销/降权、审计失败回滚、密文及原算法不变、RSA真实签名、丢响应与秘密不泄露。再验桌面/375动作、取消/焦点、跨商户迟到响应、关闭清除和只读管理员。全部只用本地合成商户，无上游请求、生产或真实资金。

专项验收：6项真实本地PG/HTTP根测试、478项前端单元、16项相关浏览器用例及vue-tsc --noEmit通过；1280/375截图已实际查看。独立复审发现的失响应覆盖新密钥问题，先由abort/malformed提交后失响应两项RED复现，再在POST前按完整目标ID清除两类旧密钥草稿；取消保持草稿，普通资料草稿不变，两项GREEN及既有边界均通过。原密钥生成不切换签名策略。冻结后的全量前端、PHP、双平台受影响Go与最终累积全仓库测试/部署另行记录，本专项不代表全部UX完成。
