# USDT 通道按用户组分配

目标：新增、编辑 USDT 通道不再维护反向的“授权商户 ID”名单。商户通过已有用户组配置获得收款通道。

## 行为约定

- 通道定义仅包含名称、网络、状态、费率和限额，移除 `merchant_ids` 输入和输出。
- 有效用户组指定通道时，只允许该通道；明确选择“首个可用”时使用启用的 USDT 通道池；关闭时拒绝。
- 继承时读取默认用户组 0 的 USDT 路由；默认组也未配置时无可用通道。用户组自身费率仍优先于通道费率。
- 新建订单在事务内重读、锁定商户及组配置；显式通道不能绕过组分配。历史订单继续绑定原通道、网络和金额。
- 旧授权表保留，不再参与读写；不修改已发布迁移、不自动修改线上用户组或商户配置。

## 执行与验收

1. 后端移除重复授权，补齐无名单创建、组分配、默认继承、关闭和跨组拒绝回归。
2. 前端移除字段与提示，验证通道保存、用户组选择、商户切组与移动端布局。
3. 使用已有本地测试 PostgreSQL、独立测试数据库验证收款入口及模拟资金流程。
4. 代码复核、构建和测试通过后提交、推送；备份并更新现有线上服务。
5. 部署后核对版本、静态资源、账务和 USDT 主网关闭状态。不发起真实资金交易，不新建容器。
