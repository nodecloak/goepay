# 消息提醒配置细节复核与修正

本轮重新对照 `p.ma3fu.com/admin/#/system/settings?tab=notice`、本地参考源码和 Go 的配置消费链路。此前只核对标题与开关，没有确认凭据编辑、打印配置入口和实际发送前置，不能据此认定消息提醒已经完整对齐。

## 本轮处理

1. 消息提醒页内显示云喇叭开关、agent_id、agent_secret，以及订单小票打印开关、APPID、APPSECRET，复用已有打印业务接口。
2. 云喇叭开关和凭据原子保存、加密存储、版本校验、本人超级管理员鉴权、审计及未知结果回读；停用后才可清除凭据。
3. 托管语音事件在原支付事务冻结开关及版本。停用期间不创建语音路由；新版本不能接管历史事件。发送领取事务复用数据库连接；托管事件使用 v2，旧 worker 拒绝读取新授权格式。
4. 补公众号、邮件、机器人、短信渠道配置的实际能力表达。已有渠道总开关参与发送前检查和商户可选性；尚未接通业务短信发送器的入口不可用。
5. 微信模板按完整快照原子保存，支持合法参数交换，拒绝重复目标参数、并发覆盖、null 隐式清除；允许显式清空模板 ID，商户端显示模板是否完整。
6. 修正已保存管理员邮箱之间的非空回退，以及核心风控提醒对后台 SMTP 配置的使用。

## 验证与发布

- 前端单元、类型检查、生产构建、全量浏览器模拟回归。
- 通知、打印、后台配置和 worker 的 Go 回归，以及本地 PHP 模板互操作。
- 管理端、商户端与支付/回调/退款/结算链路在既有本地 PostgreSQL 池的独立模拟数据库中实测。运行后只清理本次拥有且无连接的数据库。
- 独立复核代码及部署恢复路径；只执行一项新增凭据表迁移，保留生产业务配置，不发起真实交易或设备发送。

## 不作完成承诺的范围

业务短信尚无独立通知模板、绑定接收人及发送器链路，不能以验证码网关启用代替。管理员群机器人、Telegram、QQ Bot 的部分凭据仍使用部署配置，尚不能认定已具有原版全部后台凭据编辑/绑定交互。微信转账确认模板存在配置/渲染契约，不能由此宣称相应业务事件已经接通。此前暂缓的外部业务插件继续暂缓。这些差异必须在验收记录中保留，不能用“页面可打开”或“字段可保存”计为功能完成。
