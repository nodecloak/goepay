# 原用户组代付功能

本地 Pro 用户组“代付配置／代付功能”只有缺省和开启。Release getGroupConfig 对 user_transfer 的空/0 不覆盖系统配置；Transfer API 同时检查有效组配置和商户自身权限。现 Go 把该字段仅标成日报提醒，并把组0解释为关闭，与来源不符。

1. 先写真实PG RED：组1在全局普通代付关闭时启用新普通代付；空、_、旧0继承；有效会员到期后回退基线；旧同号/未知核对不重复发送；组权限不能越过商户API权限、ProviderFlow.AllowLive、金额/次数、原通道证明与资金授权。独立全局自动结算出款不消费组普通代付授权。
2. 新 internal/merchantpolicy 共享精确权限解析及有效组读取，供 payment 和 merchantnotice 使用，避免循环依赖。明确 canonical transfer_enabled 存在时优先，否则兼容原 user_transfer；组1只覆盖普通业务权限，不修改全局实际状态。新单及批次未发送执行持有原商户锁，锁会员／配置并在组锁等待后重查到期；缺组/非法值/未确认有效基线失败关闭。
3. TransferPolicy 签名结构不加字段，旧政策及意图HMAC保持。仅普通下单／未发送批次改读有效权限；原 settlement payout 继续全局政策。能力接口独立返回平台与有效开关／来源／gid，不因启组而冒称真实通道可外发。
4. 日报采用同一权限决策；替换旧0关闭的错误测试，保留0继承和全局关闭的正反例。用户组字段改“代付功能”，缺省/开启，并保留旧0的继承显示；设置页原 user_transfer 归“代付配置”，说明 canonical 优先。前端整套回归须等143冻结测试结束再改。
5. 固定新源后专项双平台PG/race、合同、完整前端及全仓vet/build，最后按已有部署/恢复/账务流程更新独立本地预览。其余原页面继续复核，仍不声明全部UX已齐全。
