# 原用户组按支付方式分成比例

Pro index-CCjDRx0B.js 的通道费率表包含“支付方式”“分成比例”，保存 info[type] 的 rate；Release includes/lib/Channel.php:get 证明其含义为商户保留比例，非平台手续费。空或0使用既有费率。现有统一 rate_bps 为平台手续费，不能直接把99.5写成9950手续费。

本阶段为 Go 管理API扩展 info 的逐方式 rate：使用实际订单稳定类型 alipay/wxpay/sandbox 作键，值只允许 {rate:字符串百分数}；旧PHP的数字类型ID和通道目录ID不能冒认运行通道，导入和路由配置另行映射后实施。本阶段不接受尚未消费的channel/type绑定字段。对外支付协议和原统一费率字段保留。

先写隔离PG失败测试：支付宝/微信独立比例、空与0继承、100%保留、按原保留金额四舍五入、大金额无浮点、当前配置不能重价历史订单和退款。后台拒负值、超过100%、小数基点、未知键/数组/路由字段；新单读取原有效组，使用原fee_rate_bps/merchant_amount/platform_fee快照。全局手续费关闭仍为明确开关。

表单恢复支付方式/分成比例表格，用百分数输入、原值字符串和空继承。未知已存结构不能自动丢字段覆盖保存。完整前端及后台定向验证后，和全仓140基线明确组合，不把未执行的新源码全量测试写成通过。
