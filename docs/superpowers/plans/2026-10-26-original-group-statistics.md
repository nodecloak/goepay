# 用户组今日／昨日支付统计

目标：恢复 Pro group-stat-dialog 的“统计”入口、标题、今日数据／昨日数据、支付方式／订单金额／订单数量／成功率四列及总计。参考本地 Pro index-CCjDRx0B.js 和 group-JyxuqdgF.js，原 groupOrderStat 控制器加密，不能把推断的聚合算法声称为已验证的 PHP 逐条等价。

1. 为 GET /console/v1/admin/reports/groups?gid=完整十进制ID 写 HTTP RED：管理员范围、严格参数、空组、今日昨日边界、当前有效会员组和过期基线、未确认基线排除、跨商户聚合、超过 JS 安全整数的金额、加权成功率、零写入。gid=0 对应已有默认组语义，正数须为真实 groups 记录。
2. 独立 group_statistics.go 使用参数绑定、RepeatableRead 只读事务、12秒超时和4个并发槽；一次聚合只连接 merchants/memberships/orders，避免退款与通道明细放大。订单金额为创建日内当前 paid 的原始订单金额，订单数量为全部订单，成功率为 paid/全部，保留精确元字符串；页面显示计算口径。归组与既有商户列表相同，为查询时有效组，不冒称历史组快照。使用既有固定金额和百分比辅助器，拒绝未知支付类型而不悄悄漏算。
3. 冻结142全前端结束后写桌面和375浏览器RED，再加独立只读 GroupStatisticsDialog：两页签、四列总计、空/失败/重试、关闭取消请求和资源切换隔离、焦点恢复。用户组行回归原“用户、统计、编辑、删除”四操作，保留既有编辑校验与删除确认。
4. 正负例通过后制作143不可变源快照，跑完整前端、受影响 Windows/Linux race 和 HTTP 回归；当前141完整仓库回归保留原结果和基础设施失败证据。最终本地 Docker 构建部署、82页只读巡检、资金账核对和私有仓库同步。所有样本为本地合成，不访问生产或真实支付上游。
