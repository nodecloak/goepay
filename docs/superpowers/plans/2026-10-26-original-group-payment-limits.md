# 原用户组单笔支付金额限制

复核证据：Pro 用户组 index-CCjDRx0B.js 的 pay_maxmoney / pay_minmoney 字段及“留空则与系统设置一致”；Release includes/lib/api/Pay.php 先合并组配置再检查全局上下界，商户自己的限制另外检查。includes/functions.php:getGroupConfig 仅空值继承，金额字段 0 可明确关闭对应组限制。不得只加表单却让支付创建忽略字段。

实施顺序：

1. 对真实隔离 PostgreSQL 先做失败测试：全局继承、用户组逐字段覆盖/0关闭/空继承、有效会员组及到期基组、整数分边界、大整数精确与非法配置。
2. 在统一新订单事务读取已持久配置，金额用 ledger.Parse；拒绝发生在新订单/上游尝试之前。原同号同参订单重放保持原结果，不能用新配置重算历史订单或创建第二单。
3. 后台暴露同名最大/最小支付金额，单位元，允许空继承与 0。上下界矛盾和负数/指数/溢出不得保存；持久旧异常值应拒绝新单并保留原审计，而非悄悄忽略。
4. 原组支付页及系统设置补原标签、说明、精确字符串保存，验证查询/保存失败/焦点/375布局。不新增日限额字段，日限额消费口径与并发保护另外验证后实施。
5. 跑付款核心及兼容 HTTP 回归，再执行完整 Windows 与 Linux 竞态测试。只使用本地模拟环境和模拟通道。
