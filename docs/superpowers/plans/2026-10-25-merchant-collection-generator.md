# 商户直接聚合收款 Implementation Plan

**Goal:** 将商户`/onecode`恢复为原直接生成表单：收款方名称、选择域名、选择收款码风格、自定义收款金额、显示/复制链接与下载；保留原记录的历史查看入口。

**Spec:** 本地`index-DVR_b5pg.js`和`onecode-DIYKuVAe.js`，全页面复核UX-004。原脚本将money直接追加到链接，Go实现需让固定金额在实际下单时也受约束。现有管理员样式编辑、样式目录与Canvas渲染继续复用。

**Architecture:** 专用商户GET仅返回本人档案、可用样式、部署可用收款origin、最近生成配置。明确POST以稳定请求号生成不可变的收款配置和原backoffice collection-code记录，返回长期、可停用的签名链接，以支持原版固定打印码用途。新86表`collection_code_generations`保存不可变配置、请求摘要和私有HMAC证明；旧记录两小时链接不改写。当前只列出部署受控callback origin，不把商户任意审核域名错误视为支付站点；额外收款站点需要后续明确部署支持。

## Constraints

- E:\GOEPAY。仅本地合成资料，不访问生产、不加载真实通道、不发送真实资金。
- 只有本人merchant会话可生成；拒管理员伪装、代登录、body中的owner字段，保留CSRF和明确提交。
- 码ID、owner、原请求号、收款名称、样式ID、origin、已批准域名引用或平台主域标记、固定整数分金额、配置hash必须绑定同一私有证明。API/通用资源响应不得泄露私有证明。
- 平台主origin取现有受控callback base；额外可选origin必须来自显式部署配置且与本人enabled+approved域名相交。默认simulation只提供回环主origin；不探测或抓取远端域名。客户端不能随意改host。
- 新签名链接明确区分新配置模式与旧collect模式，并绑定公开配置hash；删除新配置元数据不能让原新链接退回旧逻辑。旧签名链接保持兼容。
- 生成新配置不下支付订单、不改余额。固定金额在公开页显示，并由POST和`CreateCollectionOrder`事务内持有码行锁时复验；仅改URL或表单amount不得绕过。清空金额表示由付款人输入，不接受0元固定收款。
- 同一请求号同参数找回原记录，不重复生成；改参数409。已停用原码不因重试恢复。未知结果保留原请求和原参数，跨SPA返回仍可核对。
- 生成配置与审计同事务，原收款码/打印来源/账务历史保留。新配置不可通过通用CRUD改写；停用/归档不删除来源证明。
- 风格切换只影响本地海报外观时使用现有Canvas；名称、域名、金额改变需重新明确生成受保护链接。链接bearer不写localStorage，风格偏好可保存非敏感ID。
