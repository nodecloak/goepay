# 原商户关联列表的跳转上下文

原商户更多菜单含订单管理、资金明细等商户上下文跳转；当前 App 通用订单/退款/流水页面只观察route.path，忽略query，因此即使补回链接也会显示全平台记录。这是商户目录uid/pay筛选之外的独立缺口。

先用浏览器与单元用例复现 `?uid=` 无效、同path换query残留及重复/冲突参数被静默忽略。建立独立类型化解析函数：原uid别名归到merchant_id，保留规范十进制int64字符串、明确搜索字段和原q/value、当前已支持状态/日期等，拒未知/重复/冲突、越界分页和非法日期。管理端按目标筛选，商户端不能靠URL换身份；服务器仍独立执行归属。未确认的原数值状态不猜成某个新状态，不用单一pending冒充所有未支付。

App初次会话/登录后应用当前query，同path切换必须中止旧请求、清空旧记录及操作上下文；旧响应不能回写。分页和完整CSV消费同一解析结果，非法上下文不降级为读取/导出全平台列表。清空筛选为显式恢复默认。通过后在商户行恢复已具备真实目标筛选的订单/资金入口；其它原提现、代付、投诉等需各自目标页/业务支持后再补，不放无效链接。

验证375/1280、规范最大ID、跨商户拒绝、链接初次打开/登录后/同path切换、CSV条件和旧响应隔离。仍仅本地模拟，不创建真实交易或触达生产。该增量不代表商户全部专用动作验收。
