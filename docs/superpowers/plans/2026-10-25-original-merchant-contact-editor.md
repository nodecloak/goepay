# 原商户基本信息与编辑分区

原Pro商户编辑器`index-DzbjAsrt.js`的basic页包含phone/email/qq/url，以及账户/支付/结算等独立控制；api页是“密钥信息”，另两页按配置条件展示自定义接口和子通道。当前Go联系方式只暴露email，phone仅能搜索，QQ及网站字段没有真实写入入口；编辑混合API凭证和业务信息。继续逐项实现，不能以本项代表整个商户模块对齐。

先用数据库测试证明phone/qq/url创建、编辑、详情/列表和原搜索缺失。补严格允许字段，不返回任意profile，不改变已审核域名，不执行网站请求；域名字段用原url名称，允许规范域名或http/https站点，拒凭证、脚本、控制符。手机号/QQ保持字符串不经浮点，空串可清除。只校验本次显式修改，既有无效迁移值不能阻塞无关编辑。原始资料与认证登录身份独立：这一步不把未经验证联系电话自动添加为登录别名，已存在登录账号保持身份约束。界面明确说明联系方式不会自动改登录账号/授权域名。

增加专用商户编辑组件，在已有schema内呈现原“基本信息”“密钥信息”页签；基本信息按基本、结算/代付、状态分组，密钥页只放真实可写入API算法/密钥/公钥，不回显既有秘密、不假造RSA密钥生成能力。新增商户需填写API身份信息，提交应检查所有页签，错误自动切到相关页签且保留草稿。关闭/换记录重置页签和凭证草稿；已有登录名只读。收款资料沿用现有加密/CAS专用面板，不新增明文账号profile。未有后端的自定义接口/子通道不显示空页签。

联系人列表按原手机/邮箱/QQ呈现；原url与已审核支付域名有独立标记，搜索列增加qq/url，不替换原有domain的审核含义。所有渲染为文本，不根据URL读取远端。前端元字符串/ID约束保持，桌面和375px验证页签、字段保存/清空、错误定位、敏感字段不回显、迟到请求不覆盖新商户、0非预期HTTP写入。

验证包括角色隔离、嵌套private profile不泄露、未知字段拒绝、事务失败回滚、未修改凭证/会话、配置CAS、已有审核域名不被url修改影响。冻结源码后全前端与受影响Go/contracts回归，再升级独立本地模拟预览并保留完整备份/恢复和账务来源检查；真实通道/资金/外发/自动任务保持关闭。

实施时固定115的双平台全仓回归暴露六个已存在失败：CLI断言仍认为32项，但86已新增第33项生成来源检查；另五个真实旧库升级例都因新检查直接查询不存在的86来源表而中断。CLI用例改为精确33项并验证新增非零计数，不删除检查项；来源检查先识别实际旧模式，只有来源表、独立审计/生成标记与86迁移记录均无时才能作为未引入的旧功能。新模式丢表但独立锚点仍在必须报告异常，不能以缺表为由略过。新增缺表四场景数据库RED，保留五个原升级例不改其数据/断言，复跑这些失败与完整受影响回归。原115全仓失败记录保留，不能把新源码专项通过写回旧全仓为通过。
