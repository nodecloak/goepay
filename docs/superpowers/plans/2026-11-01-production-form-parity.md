# 线上管理端与商户端逐节点表单复核计划

**目标：** 以 p.ma3fu.com 实际可见界面为依据，复核并修复 Go 后台字段、默认值、操作、表单及交互差异，优先新增商户和用户组。

**架构：** 沿用 Go 类型化接口和账务约束。先建立字段到实际业务消费者的对应关系，再补齐表单与有效配置；不增加只保存但不生效的控件。新增账号和配置写入回归使用本地合成数据库，线上查看表单、查询和非资金交互，不提交真实资金交易。

**技术栈：** Go、PostgreSQL、Vue、Vitest、Playwright；使用现有已登录浏览器逐页对照。

## 约束

- 复用现有合成 PostgreSQL 容器，不新增容器、网络、卷；每轮仅清理自己的零连接测试库。
- 保留本地冻结预览及原有用户标签页、草稿。使用独立测试标签，参考站不保存配置或业务数据。
- 不发起付款、退款、补单、转账、分账、结算或其它真实资金动作；不改动生产凭据、权限及实际商户配置。
- 页面读取、展开弹窗、校验、保存、取消、失败、恢复和权限分别记录，不能用访问页面代替功能验收。
- 沿用此前外部业务插件暂缓范围；如界面依赖暂缓能力，明确标注，不假报上游成功。
