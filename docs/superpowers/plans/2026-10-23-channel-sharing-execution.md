# 渠道分账执行与可信完结

继续用户已授权的本地实施。50-boundary-candidate 固定607文件、48/49候选迁移，正在独立测试，不改动该快照或沿用其测试结论。后续50号schema用于PS账务，51号由协作者负责全局关系引用，不改1..49既有文件。

- PS依赖首次支付的不可变正声明、原paid receipt、专属funding与全部金额；不能根据新规则追认。每单一次原操作，PS+120位随机稳定号先持久化、claimed屏障、逐动作资金授权与审计提交，再单次外呼。失联只读查原PS，不以新号重发。
- 每个接收方原金额与账号由加密资料/原条款恢复，返回再次核对完整集合、原号/交易/服务商单号及金额。逐接收方SUCCESS原reserve→clearing恰好一次；CLOSED/失败不扣钱。观测追加去重，已成功不被旧pending/失败回退。
- 持久化原请求unfreeze_unsplit/royalty_finish=true。微信原PS全部终态后还须签验剩余接口明确0；支付宝仅采用原PS有接收方明细的处理完成语义，不能把空明细的独立完结或onsettle剩余额0当成功。完成证明与本地余款释放同事务，不提前释放未知/处理中的部分。
- 每条funding的数据库投影延伸到原reserve journal、逐接收方支出与唯一完成release。所有原资金账户/scope不可变，额外journal不能挪用专属reserve。核对器从parent检查NOT EXISTS(valid)。未完成时拒绝普通退款、按单冻结和站内按单分配；完成后后续阶段按净流出扣减归属。
- 后续PR只针对原成功接收方与未退余额，先原稳定号和屏障，可信返回才clearing→原商户；手工商户垫资退款与PR不自动强耦合。PF单独终态证明未充分的产品保持能力关闭，不制造字段。
- 计划验证：真实适配器本机TLS+隔离PG，首次pending/unknown、并发一次发送、两接收方部分成功、旧观测不回退、错误账号/金额/通道换Mch拒绝、授权与审计故障、余款查询失败/非0保持预留、无凭据/篡改DB、回调重复、资金核对及实际HTTP双后台。

本计划不是完整兼容或生产联调结论；其它插件仍按用户要求暂缓。
