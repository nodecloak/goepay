# 49 渠道分账协议层

范围：既有微信/支付宝直连产品；不启用真实账户，不直接把协议测试接到后台执行按钮。与后续持久化、授权、账本/退款协调阶段分开验收。

1. 明确独立capability开关与产品，不猜测账号前缀。定义完整接收方、不可变分账号/交易号、独立接收结果、独立回退号和完结意图。
2. 微信真实V3临时TLS红测：接收方姓名OAEP加密/serial、两接收方部分失败、错误原单/金额/重复接收方拒绝、回退独立核对、完结只受理后查证。
3. 支付宝真实RSA2临时TLS红测：关系绑定/解绑稳定号、异步提交不作成功、以原请求号查询全部royalty_detail_list、0元退分账与refund.query明确明细、完结独立号。拒绝金额/对象/原号不匹配。
4. 写错误及不完整响应保留unknown，不生成业务号、不重发。服务端授权前须通过本地Validate；包装层透传能力但写操作仍受allowLive开关。
5. 支付冻结声明和产品退款策略留给50原订单快照；没有这些证据的原单不能调用新远端资金动作。四个原分账菜单仍pending。
6. 单元/临时TLS/工厂回归；再做PG持久意图/发送屏障/账本与普通退款协调、双后台与完整故障测试。

依据：docs/design/channel-profitsharing-evidence.md及实施时核对官方SDK/文档。拒绝复制旧代码的随机out_request_no、只看第一个接收方或任何成功即全部成功。
