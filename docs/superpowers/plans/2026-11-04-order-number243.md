# Date and time in new system order numbers

New system payment order numbers use `YYYYMMDDHHmmss` in UTC+8, followed by a
decimal sequence padded to exactly thirteen digits. PostgreSQL transaction time
matches the order's existing `created_at` default. A dedicated noncycling
sequence, capped at 13 digits, keeps ordinary numbers at exactly 27 digits and
combined child numbers at 28–29 digits. ChinaUMS's four-character prefix makes
ordinary bill numbers 31 characters, within its documented QR bill limit; combined
children are used only by WeChat v3. Optional third-party configured prefixes are
preserved and remain outside this task's deferred-plugin scope. Fixed parent width prevents a child
of one order from equalling another ordinary order or another parent's child
when a decimal sequence crosses a width boundary. It is not reset each day.

Existing order numbers, merchant order numbers, provider attempts, payment
materials, callbacks and ledger facts remain unchanged. Replaying an existing
merchant order returns its original system order number.

An imported legacy number can already occupy a candidate. Roll back only the
candidate row insertion savepoint and retry with another sequence value, up to
eight times, only for PostgreSQL `23505` / `orders_trade_no_key`. Other errors
retain their existing behavior. Do not adjust either sequence from import code.
