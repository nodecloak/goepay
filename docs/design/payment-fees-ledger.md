# 支付费用和退款分摊规则

实施日期：2026-10-23。数据库迁移：000015_payment_fees。

## 已核实的原版行为

- `epay_release/includes/lib/api/Pay.php:173`～188：普通商户承担费用时，买家实付 `realmoney=money`，商户所得 `getmoney=round(money*通道留存比例/100,2)`；另有买家加费和最低手续费分支。
- `epay_release/includes/functions.php:606`～612：平台代收订单按 getmoney 入商户余额，realmoney 与 getmoney 的差额为服务费；通道成本再影响利润。
- `epay_release/includes/lib/Order.php:88`～95：refund_fee_type=0 时全额退款通常扣除商户原所得，手续费由平台退；refund_fee_type=1 时商户承担手续费。旧版各笔部分退款独立计算，没有现代预占和累计分摊约束。
- `epay_release/admin/set.php:547`：退款手续费承担方默认是平台。

这些是明文 Release 的证据，不推定加密 Pro 的所有分支一致。本轮只实现明确启用的商户扣费政策，不实现买家加价、最低手续费或直收模式。

## 启用和订单快照

默认不收手续费。仅当管理后台设置 `payment_fee_enabled=true` 时，新订单按所属用户组 `rate_bps` 收取费用。该新字段表示手续费万分比，与旧版通道的商户留存百分比不是同一单位。

商户所得按 `实付分*(10000-rate_bps)/10000` 四舍五入到分，先除后乘防止 int64 溢出；手续费等于实付减商户所得。特意对商户所得舍入：实付 1 分、费率 5000 时商户所得 1 分、手续费 0 分，与原版所得金额舍入方向一致。

创建订单时固定 fee_policy、fee_rate_bps、fee_group_id、merchant_amount、platform_fee、refund_fee_payer。重复订单号返回原快照，后续改用户组或设置不会改变已创建订单。数据库禁止更新这些字段。

付费会员在有效期内覆盖新订单的费率组，到期后恢复独立保存的管理员基础组；购买会员不改写基础组。历史版本曾把购买组写回商户资料，迁移会根据可确认审计证据恢复；无法区分购买结果与人工指定的完整快照时，标记 `group_baseline_unresolved`，到期后拒绝创建启用费用的新订单，直到管理员明确指定基础组。普通资料编辑不能解除该异常，历史订单快照不变。

外部金额、通知及通道校验继续使用订单实付总额，不把商户净所得作为买家付款金额。确认真实支付成功后，在同一事务将净额记入商户可用账户，将手续费记入平台 fees 账户；原实付总额从 clearing 账户减少。

## 退款和并发

`refund_fee_payer=platform` 为默认值：退款先使用尚未分摊的商户所得额度，其余使用平台手续费额度。成功、处理中及未知状态都占用额度；明确失败才释放。各笔退款同时记录不可修改的 merchant_amount 和 fee_amount，两者之和必须等于退款总额。

每次新退款在订单锁下统计非失败退款的总额、商户份额和手续费份额，再分配剩余份额。使用实际已分配份额，而不只看累计退款总额，因此前一笔失败、后一笔仍处理中时不会多退平台手续费。全额退款完成后，累计商户份额最多等于原净所得，累计平台份额最多等于原手续费。

`refund_fee_payer=merchant` 时，每笔退款总额全部由商户承担，平台保留手续费。全额退款可能要求商户补充可用余额；不足则拒绝预占。

预占阶段分别使用商户 reserved 和平台 fee_reserved 账户。未知结果不释放任何一方。成功分别转入 clearing；失败分别返还商户 available 和平台 fees。所有分录、状态和已验证通道退款结果保持在同一事务。

## 已验证范围和限制

测试覆盖最大 int64 金额、舍入边界、配置变更后重复下单、重复支付回调、退款失败形成的分摊空洞、20 路并发部分退款，以及商户承担手续费的退款模式。复式平衡、账户投影和不可变记录约束继续启用。

历史导入若只提供实付金额而没有原版 getmoney/realmoney 费用资料，按零费用快照保留，不推测原手续费；这不是完整费用历史兼容证明。通道成本、买家加价、原版最低费用规则仍需单独契约样本和实施。
