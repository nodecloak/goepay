# 已实施接口约定

范围是当前代码，不把原规划中的全部接口当作已经实现。原商户协议的字段以本地 Pro 文档/SDK及 [方法映射](two-plugin-methods.md) 为依据，后台使用独立版本空间。

## 后台 API

前缀 `/console/v1/{admin|merchant}`。两种身份使用各自 Cookie，不允许跨身份复用；所有写请求携带当前会话的 `X-CSRF-Token`。用户 ID、资源归属和管理员权限由服务端决定，前端传入的 `merchant_id` 不能覆盖商户自己的身份。

```json
{"code":0,"message":"","data":{"items":[],"total":0,"page":1,"limit":20}}
```

- 客户端同时检查 HTTP 状态和业务 `code`。HTTP 200/201 且 `code=0` 表示该操作返回成功，资金最终状态仍看 `status`。
- HTTP 202 且 `code=0` 表示意图已保存、结果待核实。保留原 ID/业务请求号，查询原记录；不能生成新号重新出款。
- HTTP 400/422 表示输入不合法，401 表示重新认证，403 表示权限或 CSRF 拒绝，404 表示不可见或不存在，409 表示幂等/状态冲突，429 表示限流，503 表示依赖或能力不可用。部分业务服务会按既有映射返回 400，不能仅凭状态码判断资金是否移动。
- 资源 CRUD 的字段、只读/只写/仅创建字段、操作权限取自 `/resources/{resource}/schema`。未允许字段拒绝，密码和 API key 不回显。
- 列表默认分页，`page>=1`、`1<=limit<=100`；统计与兼容接口有独立限制。查询关键字按字面值参数化，不作为 SQL 表达式。订单/退款/代付/商户/账本与统计 GET 可用 `format=csv` 导出同筛选完整结果：忽略分页，最多50,000行或8 MiB，超限422而非截断；并发忙时429。响应为带UTF-8 BOM、下载审计和no-store的CSV，公式文本前置单引号；列表金额单位分，统计金额单位元。
- 后台新接口 ID 和整数分金额通常是十进制字符串；展示金额字段 `*_money`、普通退款/转账提交 `amount` 为元字符串。`/channel-sharing` 是明确例外：包括回退 `amount`、规则 `fixed_amount`/`minimum_amount` 的全部金额均为分字符串，比例 `rate_bps` 为万分比，0.10元传 `"10"`。客户端不得把大整数 ID 或金额先转 JavaScript Number。
- 渠道分账专用列表 `receivers/orders/returns` 使用规范 `cursor`（默认0）和 `limit`（1..100），返回 `items/next_cursor`（字符串0表示无后页）；`finishes` 仅按limit返回最新items。管理员必须显式选择商户，商户不得提供 `merchant_id` 字段。渠道分账未知结果返回409；保留原PS/PR/PF业务号，GET恢复本地状态后按原号query，不换号重发。
- 后台时间使用带时区 RFC3339；旧商户协议的 `addtime/endtime/paydate` 使用 UTC+8 格式 `YYYY-MM-DD HH:mm:ss`。

## 商户兼容 API

V1 保留 `/submit.php`、`/mapi.php` 与 `/api.php?act=...`。V2 使用 `/api/pay/*`、`/api/transfer/*`、`/api/merchant/*`。成功代码 V1 通常为 1，V2 为 0；退款等独立旧协议有其原有返回代码，不套用后台的包裹结构。具体处理见契约测试，未支持的操作明确失败。

入站签名保留实际金额字符串、中文和扩展标量。拒绝重复键、歧义 PHP 参数、时间戳越界、弱 RSA 和算法降级。不能在验签后随意改写入站参与签名字段；业务内部使用解析后的值。V2 响应和通知按 SDK 画像签名，详情见 [实施决策](implementation-decisions.md)。

查单在验证商户归属后返回实付 `money`、可信 `api_trade_no`、原始客户 IP、买家标识和 UTC+8 时间。只统计已成功退款：部分退款返回 `refundmoney` 并保持 `status=1`，累计成功全额退款为 `status=2`；未知/处理中退款不冒充已退。已付订单收入独立冻结投影为 `status=3`，不改变已支付事实；已验证授权但尚无实际扣款成功回执为 `status=4`，此时 `api_trade_no` 为授权号，不计商户余额。历史缺少元数据时返回空值，不推测上游流水。订单列表同样支持2/3/4状态过滤。

微信/支付宝的 APP/JSAPI 下单返回 `pay_type` 和真实 SDK 材料字符串 `pay_info`；网页跳转使用到期保护的收银台。调用方必须按返回类型处理。H5 必须有可信站点配置，JSAPI 必须有已签名且绑定可信 AppID 的买家身份；没有 OAuth 时不能捏造 OpenID。

## 幂等、回调和未知结果

- 支付使用商户内唯一订单号；同号变金额或身份拒绝。退款/转账的上游业务号由平台全局 ID 构造，不能直接复用不同商户的外部编号。
- 新支付尝试在同一事务绑定通道、方法、可信 AppID 和付款人 OpenID 的域隔离 HMAC；同号换付款人不能复用旧 JSAPI 材料。24迁移之前缺少该证据的旧尝试不猜付款人，创建重放失败关闭；原记录、查询、回调和已生成的受保护链接仍可核对，不重新发送请求。
- 外部调用前提交意图和核对任务。外部结果必须验签并匹配商户/应用、订单、币种、精确金额及业务号，之后才提交账本。
- 一个可信通道流水只能支付一个平台订单；重复回调核对同一身份，不重复入账。可信回执与资金凭证在同一事务保存。
- 回调在事务成功后 ACK；失败重试仍命中原意图。同步浏览器返回需要只读查证，不能凭浏览器 URL 参数判断成功。
- 退款/转账明确认证的终态失败才释放预占；断连、响应验签失败、系统错误或查询未找到均不代表失败。
- 后台资金操作在上游 I/O 前持久记录操作者意图，写审计失败即阻断调用。结果审计不包含原始密码、收款账号、姓名或凭证下载 URL。

未知结果和人工复核是实际状态，不是错误处理可以删除的临时记录。查询 Worker 和管理员任务重试只能核对原记录，不能再次发送出款。
