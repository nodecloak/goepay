# 微信、支付宝代付账务与接口

本实现以本机 `epay_pro/app/view/doc/transfer_submit.html`、`transfer_query.html` 与可读的 `epay_release/includes/lib/api/Transfer.php`、`includes/lib/Transfer.php`、两个支付插件为依据。仅在本地 PostgreSQL 和假上游中验证，没有生产调用或真实资金测试。

## 已实现

- 保留 RSA 支付接口 `/api/transfer/submit`、`query`、`balance`、`proof`，保持 `biz_no`、`out_biz_no`、`status`、`orderid`、`paydate`、`amount`、`cost_money`。`balance.available_money` 是本地账本经全局出账政策计算后的可出账金额，`ledger_available_money` 单列原账本可用余额；二者均不冒充上游通道余额。
- 新提交同时要求全局 `transfer_enabled=true`、商户 `transfer_api_enabled=true`、商户已授权的通道、明确支持的类型和部署的写入开关。默认关闭。查询已存在的转账无需再次启用写入开关，便于停用后的对账。
- 商户订单号在商户内唯一。平台 `biz_no` 使用全局 19 位序列；给上游的业务号固定为 `TF{数据库转账ID}`，不同商户不会碰撞。相同业务号的收款账号、姓名、金额、备注、类型、通道不可变，相同请求只拥有一次提交权。
- SQL 事务先记录收款快照、冻结本金及手续费并持久化查询任务，提交事务后才调用上游。收款快照使用 AES-GCM 加密并绑定转账 ID。异常、断连、未认证响应、查询未找到均保留冻结资金，禁止自动重发。
- `transfer_rate` 是百分数字符串（`"3"` 为 3%）。使用整数分和定点计算，手续费四舍五入，成本是本金加手续费。成功以平衡分录把本金转入平台清算、手续费转入手续费账户；确认失败全额解冻。所有状态和凭证快照都有不可变约束。
- 单笔最小、最大金额使用旧名称 `transfer_minmoney`、`transfer_maxmoney`，单位元；`0` 或未配置时不限制。`transfer_maxlimit` 限制同一商户、同一支付类型、同一规范化收款账号的每日次数，默认不限制。检查在商户非键更新锁内进行，超过限制时不冻结资金、不调用上游。账号使用独立派生密钥的 HMAC-SHA256 索引；支付宝登录账号忽略大小写，索引与通道无关，无法通过切换通道绕过。历史加密意图在额度检查前按同一商户锁补建索引。
- 每日边界固定为北京时间零点；今日确认成功的转账计数，所有尚未确定结果的转账持续占用名额，跨日也不释放，确认失败不占用。这比旧版仅统计成功 `paytime` 更保守，避免并发待处理或跨日未知请求绕过次数限制。上游到账时间与本地确认时间不同的记录可能延迟释放名额；本地成功确认时间不可改写。
- `transfer_desc` 提供默认备注，`transfer_name` 提供默认付款方展示名称，均最多 32 个字符。不填写微信备注时，仅在配置了默认备注后才允许提交。实际默认值加密固定在原始意图中，并以请求摘要识别重复请求；后续改变默认值、金额限额不会重算或重发原请求。
- 明确认证的 `NAME_MISMATCH`、`OPENID_ERROR`、`PAYEE_NOT_EXIST` 等白名单拒绝才释放资金；系统错误和 NOT_FOUND 不释放。成功结果必须匹配平台业务号、金额及非空上游流水。
- 支付宝凭证先记录申请意图，只申请一次；保存文件 ID 后重复操作只查询。申请响应丢失且文件 ID 未知时不盲目再次申请。下载 URL 加密保存，仅经身份和归属校验后返回。
- 后台 `/console/v1/{admin|merchant}/transfers` 提供分页记录、创建、`capabilities`、`{id}` 详情、`{id}/query` 查询与 `{id}/proof` 凭证。创建、查询和凭证操作在上游调用前记录操作者意图，随后关联结果，审计不记录收款账号、姓名或凭证下载 URL。失败写入意图审计时不调用上游。
- 结果不确定时后台返回 HTTP 202 和原转账 ID，界面应继续查询原记录。没有撤销未知转账的接口。

## 当前边界

微信 V2 零钱转账要求 mTLS。显式银行分支另需可信 RSA 公钥和银行编号，已实现受理/查证/手续费暂存及退票独立账务；银行受理不代表最终到账。支付宝支持公钥钱包及显式三证书模式的账号 uni-transfer，另有默认关闭、显式授权的[支付宝银行卡产品](alipay-bank-transfers.md)，保持原意图、验签及独立退票证据闭环。`bookid`资金账簿分支仍不支持，冻结资金前拒绝；不能据此声称原插件全部产品兼容。批量能力见[持久批量代付](durable-transfer-batches.md)，不等同自动结算。各产品及证书细则见 [两插件方法映射](two-plugin-methods.md)。

全局 `settle_type=1` 已按明文来源识别 `tid=2` 为充值，统一计算北京时间当日已付非充值订单的实付总额 gross，保守扣除后限制出账；默认0维持即时可出账。实际预占在账户锁内重新读取策略和资金，覆盖代付、结算、站内转账与分账，避免先转到其他商户绕过。充值/成功全退、手续费、跨日与历史保守差异见 [T+1 规则及来源](t1-funds-availability.md)。商户 profile 的同名 `settle_type` 是收款账户类别，不是该全局政策。

系统会在意图持久化 30 秒后启动只读对账，且仅处理部署明确授权查询的通道。没有真实配置、权限或证书时不进行上游操作。查询不能自动修复未知申请且没有文件 ID 的电子凭证，需要人工核对。
