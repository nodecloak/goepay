# 结算政策与申请快照

依据可读Release `user/apply.php` 的最低金额、留存和日次数及手续费逻辑。39迁移建立独立不可变 `settlement_request_terms`，新申请与本金预占、快照、操作者事件同一事务提交。费用当前仅为将来结算的约定，不在审批时提前确认为平台收入；审批仍不执行外部付款。

显式全局设置：

| 设置 | 单位/默认 | 语义 |
|---|---|---|
| settlement_minimum_cents | 分，0 | 新申请最低本金 |
| settlement_maximum_cents | 分，0 | 0不设上限，非0不得低于最低本金 |
| settlement_fee_rate_bps | 万分比，0..10000 | 精确整数四舍五入到分；0时不收手续费，也不套最低手续费 |
| settlement_fee_minimum_cents | 分，0 | 非零费率下的最低手续费 |
| settlement_fee_maximum_cents | 分，0 | 非零时封顶，不能小于最低手续费 |
| settlement_retained_cents | 分，0 | 申请后必须保留的可出账资金，不只是账本余额 |
| settlement_daily_limit | 次，0 | 0不限；北京时间当天申请总数，拒绝仍计数 |

金额设置范围0..100000000000分，次数0..1000000。非法持久值或互相冲突的设置拒绝新申请；旧幂等请求先命中原订单/金额/收款主体，不重新定价。所有新申请净额必须大于0。新上限是显式Go设置，不声称与原Pro所有隐藏字段同名同义。

新申请在商户行锁内顺序读取已存在政策行并持有共享锁，检查日次数与资金。留存校验按 `gross+retained` 使用统一T+1可出账视图，实际只预占gross，不另冻结留存。单笔金额、费率、费用上下限、净额、留存及日限额固定在快照；拒绝释放原gross，批准继续冻结gross，未产生外部出款或手续费收入。

`GET /console/v1/{role}/workflows/settlement-policy` 返回policy，可传元字符串amount获得terms/daily_used/can_apply及资金视图。管理员必须传merchant_id，商户仅自己。报价使用只读repeatable-read快照，是估算而非授权；实际提交重新检查所有政策/额度。

新界面在提交前先查询报价并显示手续费、净额和留存，再明确确认。金额、主体或原请求号改变即废弃确认。提交时附 `expected_fee_cents`/`expected_net_cents` 两个整数分字符串；事务实际报价不同或原幂等请求快照不一致返回409，不预占新资金，界面要求重新确认。历史调用可省略这两个字段，保持旧请求兼容。新增字段不能用于改变服务器手续费。

创建、列表与审批响应的 `settlement` 中金额均为整数分字符串；历史无快照返回null，界面显示“历史未记录”，不回填当前政策或虚构零费用。列表的预计净额仍不是到账金额。

本增量只实现明确全局政策。原商户/组优先级、百分比留存、付费注册、完整自动结算时间/分批策略、受款账户与代付绑定和实际出款结转仍独立实施，不以费用报价代替。现有38迁移运行库在39专项及统一回归冻结前保持原镜像，不操作生产环境。
