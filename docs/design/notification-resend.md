# 商户通知重发

管理与商户后台的 `POST /console/v1/{role}/orders/{trade}/resend-notification` 接收唯一字段 `external_no`。共享会话、管理员权限及 CSRF 校验后，事务锁定原订单并验证归属、paid 状态和已保存通知地址。客户端不能修改地址、商户、金额或签名内容。

32 迁移增加持久请求到任务的映射、通知任务查询索引及共享冷却记录。订单内请求号只保存域隔离 SHA256，同号无论任务完成与否均返回原任务；通知状态与任务由现有 jobs Worker 管理。若自动或手动任务仍 pending/running，新请求合并到该任务，不重置租约、次数或覆盖正在发送的请求。事务外 Worker 若同时完成，合并者可能看到刚完成的原任务，这是正常的至少一次投递语义。任务已终结时，新的手动任务至少间隔60秒。管理员死信 retry 使用相同原订单锁、活跃任务检查及冷却，不允许借旧任务绕过并发合并；冷却与任务、审计同事务回滚。

新任务、请求映射、操作者审计同事务提交。审计失败时全部回滚，没有对商户的网络调用。Worker 使用原订单保存的URL、版本、金额及当前签名时间，默认HTTP客户端仍验证协议、DNS和私网地址并拒绝重定向。通知重发不调用支付机构、不新增支付回执、不修改余额、退款或授权状态。

返回 `job_id` 字符串与 `state`。pending/running 为202；succeeded/dead 为200且状态必须分别展示，不能把200或排队成功显示为商户已收到。succeeded仅表示一次HTTP200、正文严格为success的应答，不保证商户内部业务执行次数；接收方仍须按平台订单号幂等。

本地PG合同覆盖未支付拒绝、CSRF、跨租户隐藏、12并发合并、完成后原请求重试不再发、冷却、审计失败回滚、原支付凭证不变，并实际领取任务、向本机httptest商户验签投递及ACK完成。所有测试使用随机schema和临时本地监听器。
