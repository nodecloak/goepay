# 上游订单名称快照

依据可读Release `includes/functions.php` 的 `ordername_replace`、Pro `Payment.php` 的覆盖关系及前端公开字段，实现六个固定字面变量 `[name]/[order]/[outorder]/[qq]/[phone]/[time]`、`|`候选随机名称及金额规则。没有解密Swoole控制器；金额区间重叠的隐藏优先级未知，因此拒绝重叠闭区间，不猜测原行为。

超级管理员额外资源 `/resources/order-subject-policies`，字段scope(global/merchant/channel)、scope_id(global为0，其它为正十进制字符串)、template、rules、enabled。通道ID为实际运行通道ID，不是后台资料记录ID。模板与规则各自按通道>商户>全局继承：空字符串继承，rules显式字符串 `[]` 覆盖为本级无金额规则。相同scope/id最多一条启用。商户范围校验存在；普通管理员和商户不能读取或写入此资源。

rules为JSON文本，如 `[{"name":"小额-[outorder]","min":"0.01","max":"10.00"}]`。金额必须为精确元字符串；拒绝未知/重复键、数值浮点、指数、负值、倒置及重叠区间。最多100条、JSON文本20KB，模板最多1024字节/16候选；没有正则或脚本执行。

首次在订单行锁内读取已有快照，再读取当前有效策略，按金额选择模板、用crypto/rand选择候选，固定次序替换六变量。[time]为首次DB时钟的Unix秒；QQ/phone仅从持久商户资料读取，客户端请求不能注入。未知变量保留字面值，原Release的outorder为空或0时保留字面量。每步替换有限额，显式渲染最终非空、有效UTF-8、无NUL/CR/LF且最多128字节。无有效替换策略仍原样保留既有订单名称及原校验上限，不以新限制改变默认接口。

迁移38的 `provider_subject_snapshots` 固定订单、通道、最终标题及来源策略快照，提交后才允许外呼。普通下单、付款码、预授权冻结与扣款共用Flow.SubjectResolver。已有attempt而缺快照的历史订单一律保留原名，不在重放时重新套规则；有快照的订单不随配置变更或随机值变化。数据库阻止快照修改/删除及通道冲突。

原 `orders.name`、商户入站签名、重放身份、查单及通知保持原名。上游subject/body才取快照。产品预校验仍先遵守原始请求约束，不保证替换能够绕过原始名称的产品限制；组级策略、隐藏Pro重叠/边界和其它扩展规则未宣称兼容。

测试包含严格解析/金额、字面替换和长度、12并发同一快照、配置改变/通道切换、独立继承、可信资料变量、历史原名、不合法结果不落快照及四个发送调用点。实际本地TLS微信请求验证先持久快照再外呼、上游替换标题、原通知名与原签名幂等、重放不再次发送。
