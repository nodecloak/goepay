# 短时、可追溯的商户代登录

参考 `epay_pro/route/admin.php` 的 `admin.User/sso` 与可读 `epay_release/admin/sso.php`。这是新版后台功能入口，不复用原PHP长期用户Cookie。权限有明确收紧：仅super，且目标须有已启用后台登录账号；纯API商户需先开通后台账号。原管理员登录及已开启的MFA仍按正常会话验证。

`POST /console/v1/admin/sso/grants` 接收 `merchant_id` 字符串，返回一次性的 `grant`、到期时间及商户ID。有效期60秒，同一管理员会话及商户最多5个有效未消费grant。数据库只保存哈希，绑定原管理员会话、账号版本与目标登录账号版本。审计记录真实管理员和目标，不记录grant。

`POST /console/v1/admin/sso/consume` 接收 `grant`，仍需**原管理员会话及CSRF**，不能移到另一管理员或同一管理员的新会话。先锁定授权行，再以数据库当前时钟重新核对到期，避免扫描通过后等待行锁跨过有效期。消费、15分钟商户会话、发行者关联与审计同事务；失败不设置Cookie。grant只放POST正文，不进URL、持久浏览器存储或日志。

成功设置 HttpOnly、SameSite=Strict 的商户Cookie，路径限定 `/console/v1/merchant`，正式HTTPS应启用Secure。这会替换该浏览器已有的商户会话，管理员会话保留。目标需正常使用新商户会话的CSRF，不能把管理员CSRF当作商户CSRF。

每次读取代登录会话，除正常目标账号/版本/商户启停校验，还检查发行管理员的原会话未退出或到期、账号仍enabled、版本一致且仍为super。发行者关联不会随管理员会话删除而单独级联消失，否则剩余目标会话可能被误当普通登录。退出、密码/MFA/权限变化撤销原管理员会话后，代登录下一请求失效；普通商户登录不受影响。授权检查不保证撤销能撤回已经完成授权并执行中的事务。

`GET .../session` 增加 `delegated_by`（ID、展示名称或null）。代登录的每个写请求在业务前额外记录真实管理员的**操作尝试**审计，失败返回503并阻断业务；已有业务审计仍记录有效商户及实际结果。尝试审计只记录路径、目标和真实操作者，不记录请求体、密码、收款信息、Cookie或CSRF。代登录不绕过现有当前密码校验，不自动获得商户API明文密钥。
