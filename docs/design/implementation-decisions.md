# 实施决策与运行约定

日期：2026-10-23。此文件说明实际实现，原总体设计保留为规划基线。

| 决策 | 实现和原因 |
|---|---|
| 模块化单体 | `cmd/api`、`cmd/worker`、`cmd/cli`、`cmd/import-legacy` 独立入口；支付编排、账本、身份、兼容、后台资源、通知、核对分别在 `internal` 包内，避免每个控制器各自改余额 |
| PostgreSQL 事务队列 | 账务、通知意图、任务同时提交；租约与失效令牌避免多个 Worker 重复确认。当前没有引入 Redis 或独立消息队列，减少跨存储一致性问题 |
| 显式 pgx SQL | 本轮采用参数化 pgx 查询与数据库约束，没有引入规划中的 sqlc。列/扫描、权限隔离和资金约束通过真实 PostgreSQL 契约验证。查询里的资源名与报表维度来自代码白名单，用户值不拼接为 SQL |
| 整数分 | API 金额字符串转换为 int64 分；手续费定点计算；不经过浮点金额。实付、净额、手续费、承担方在创建时固定 |
| 未知结果 | 发生断连或未认证结果时保留意图和预占，只读核对原业务号。工作人员不能通过“重试任务”重新发送资金请求 |
| 双层外部调用保护 | 工厂客户端默认禁止写入；编排层还检查显式写开关、商户与通道授权。模拟通道独立实现，不具有访问支付机构的 HTTP 客户端 |
| 独立后台 API | 新后台 `/console/v1/{admin|merchant}` 采用统一响应和 CSRF；原商户接入保留 PHP/V2 入口与签名规则，不混用后台会话 |
| 前端组件 | Vue 3 + TypeScript + Vite，自有样式与有类型组件；没有引入规划中的 Element Plus。表单读取受限 schema，前端菜单可见性不替代后端权限 |
| 密钥与会话 | Argon2id 密码、哈希持久会话令牌、会话版本、独立 CSRF、加密 TOTP/通道/收款快照。原始密钥不进入响应、操作审计、镜像或测试报告 |
| 不可变迁移 | SQL 文件按序记录 SHA-256；已应用文件不覆盖，修复追加新迁移。历史数据无法安全推断时保留明确异常，不静默猜测 |

## 兼容画像

服务端入站按 Pro 严格空值语义验签；面向原 SDK 的响应和 V2 商户通知按 SDK 的 trim 空值语义签名。源码对纯空白的处理存在差异，测试分别验证两者；不能声称任意原始 PHP 字符串行为都等价。通知 URL 已有查询参数也参与实际线缆上的签名验证。

拒绝重复参数、歧义 PHP 数组/归一化参数、弱 RSA 密钥、算法降级和签名金额篡改是明确的安全边界。历史商户来源画像由服务器保存，不接受未验签参数切换。

## 本地测试和部署

Compose 是本地模拟环境，默认仅绑定回环地址、没有真实通道配置挂载。模拟上游状态仅在 API 内存中，模拟通道不用于验证重启后的真实上游恢复；真实未知结果恢复使用假上游和持久任务集成测试验证。

PostgreSQL 是唯一资金事实来源。恢复后需检查非空平衡凭证、账户余额与分录投影，以及未知退款/转账义务。CLI `reconcile` 是本地账本结构检查，**不是支付机构账单核对**；返回未知记录计数不代表这些资金已经结清。

默认 Compose 数据库用户具备迁移管理权限。生产最小权限账号、TLS、集中密钥保管、监控告警、真实账单和人工异常处置流程没有因为本地部署而自动完成。
