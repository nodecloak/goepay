# Pro订单搜索字段与通知筛选

2026-10-24。原证据为本地 `epay_pro/public/static/assets/index-lAIAtQd1.js` 的order-search组件：column选择系统/商户/接口单号、商品、订单/实付/分成金额、支付账号/IP、扩展参数等。加密控制器无法证明其精确匹配方式，本增量明确采用以下新API契约，不冒称原RPC逐字兼容。

订单列表及相同CSV条件新增 `search_field`，与现有 `q` 搭配。空字段保持现有综合搜索；系统/商户/接口单号、买家、IP采用精确匹配，商品及扩展参数采用大小写不敏感的字面子串；百分号和下划线不是通配符。金额仍用元十进制输入，服务端精确转换整数分，绝不使用浮点。Pro的money和realmoney均对应当前实际amount，getmoney对应merchant_amount，不凭空生成第二种支付金额。

固定支持 `trade_no/out_trade_no/api_trade_no/name/money/realmoney/getmoney/buyer/ip/param`。接口单号和买家与当前显示投影采用同一优先级，IP使用标准化地址。原bill_mch_trade_no/bill_trade_no、手机号与域名没有可信订单来源，明确拒绝，不显示假选项。字段或金额非法、重复q/字段、格式错误的query均400；商户owner谓词始终独立存在，CSV和总数使用同一WHERE。

另新增 `notification_state=none|pending|running|succeeded|dead`，直接读取同一最新通知任务，付款状态与通知状态分开。未知状态或在非订单入口使用均拒绝。

先通过纯函数RED明确旧接口缺失，再接固定SQL和HTTP真实PG测试，覆盖所有字段、金额int64边界、文字注入/通配符、通知任务最新优先、商户隔离和CSV一致。前端单元及真实mock浏览器验证字段值传递、重置、跨页清除和375px无溢出。变更不涉及资金写入、迁移或提供商调用。
