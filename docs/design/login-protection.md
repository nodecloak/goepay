# 登录限流与密码校验

实际后台登录使用迁移29的 PostgreSQL 计数，不会因 Go 实例切换或重启清空。每15分钟固定窗口，同一真实连接来源最多300次，来源+角色+规范化用户名最多10次；成功与失败均计入预算，修改来源端口或 IPv6 写法不能建立新来源。较宽来源预算限制轮换用户名；具体账号预算不会立即阻止同来源的其他用户。所有实例按来源→账号顺序取得计数锁，原子更新并在返回前提交。

数据库仅保存带域分隔的 SHA-256 索引和计数/时间，不存密码、Cookie 或明文用户名/IP。登录审计另行保存有界账号与真实来源，始终不保存密码和请求体。限流数据库错误返回503，不退回内存计数继续认证；超过预算返回429。来源读取 `RemoteAddr`，默认不信任请求自带转发头；显式配置的直接可信代理可由统一 middleware 校验单一 `X-Real-IP` 后改写来源，详见[可信代理设计](trusted-proxy.md)。未配置时，代理后的来源预算合并到代理地址；从不直接信任任意 `X-Forwarded-For`。

Argon2id 每次校验使用64MiB内存。API进程最多允许4个未认证登录流程同时进入数据库账号读取、密码/TOTP校验与持久会话生成；饱和时直接返回429、`Retry-After: 1`，没有无限等待队列。此限制约束登录路径，不能解释成所有已认证账户操作或整个应用的内存上限。

后台清理保留预览与明确提交：只允许1～365天前的 cutoff；新增 `expired_login_throttle_keys` 统计/清理早于 cutoff 的持久计数，活动窗口不清除。计数删除与意图审计在同一事务。旧 `expired_attempts` 保留表示进程内测试/无数据库回退的计数，实际运行有数据库时以共享计数为准；无数据库时实际API仍拒绝认证。

真实PG回归已复现并修复：新Server绕过原内存计数、301个不同用户名绕过、IPv6规范化、多个Server并发预算、数据库故障失败关闭，以及清理预览不删除/提交只删除旧记录。原密码变更与正在登录的竞态测试继续保留。没有生产压测或绝对防爆破保证。
