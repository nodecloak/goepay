# 批次逐次资金授权（迁移42）

仅在请求具有管理员事务guard时增加此路径；原商户签名及商户后台仍按既有权限工作。批量准备以整批原始幂等号授权一次，与所有预留在同一事务提交，不让每个内部单笔预留再次消费grant。

执行从本批当前未发送明细按原position选取最多limit项。生成请求内部随机execution_no；首个明细仍满足unsent及原通道/AppID/写闸条件时，在同一事务消费41的动作授权、插入不可变transfer_batch_executions（批次、商户、操作者、固定transfer_ids）、插入单笔唯一claim、改变原项为claimed并写审计与核实任务。全部提交后才发往上游。

后续明细从该持久execution证明归属与原操作者，不能扩大范围或再把grant作为会话通行证。数据库唯一claim与原发送屏障共同阻止并发重复发送。部分执行中断后，已经claimed的原号只查询；尚未领取的项可以在下一次明确确认后形成新的执行集合。旧执行集合不存在可被HTTP调用方传入并任意恢复的接口。

取消在同一商户、transfer、item锁序下只处理unsent，首个确有可取消项时消费一次batch-cancel授权，全部释放与审计同事务。已领取、处理中、unknown不释放；银行项沿用平台未发送取消证明，不捏造支付机构失败或退票证据。

42不代替逐条核验支付机构回执。响应200或授权成功均不能表示整个批次成功，也不构成自动结算。
