# 原订单固定奖励的按日发放

本增量沿用邀请注册关系、原支付凭证、手续费预算和逐动作资金授权；不使用生产凭据或真实支付验证。它与 Pro 延后按汇总金额、当前用户组重新计算的行为有明确差异，不能称该隐藏规则已经逐字兼容。其他业务插件仍在暂缓范围。

## 政策与资金来源

管理员本人使用原 `referral-policies` 接口，显式提交 expected/enabled/rate_bps/mode/basis/refund_policy 六字段；mode 为 immediate 或 daily。原 CAS 和资金确认绑定完整请求，改变模式或基数不能沿用原授权。全局、付款商户组、推广商户组按既有顺序继承启用状态与比例，存在的政策明确覆盖模式和基数。旧订单继续使用原政策版本和已封存金额。

fee 基数为原订单平台手续费，gross 为原订单实付金额；按整数分四舍五入计算，每单奖励 R 始终不超过该单原手续费 F。创建订单只产生零余额的订单专属待发账户及版本2来源标记。只有真实可信支付完成的同一事务，才能把原手续费中的 R 转入该专户；推广商户可用余额此时为0。账户属于平台、范围固定原订单，显式要求非负，不能借用清算或其他订单资金。

旧版本条款、发奖、退款回收的 HMAC 及已部署迁移保持不变。版本2来源附加绑定原条款、原政策版本、模式和业务时区。读取原政策版本的已认证事实判断原模式，daily 来源缺失或损坏必须报冲突，不能回退即时发奖。

## 北京时间与调度

激活时间取锁后的数据库 `clock_timestamp()`，封存该时间的 UTC+8 业务日及次日 eligible_day。不使用可修改的订单 paid_at 或事务开始时间。时间统一为 PostgreSQL 微秒精度。

`TickReferralDaily(ctx, through, limit)` 只接受规范日期、through 不晚于数据库北京时间今天、limit 为1..100。逐单先锁原订单，再锁规范顺序的账务账户；并发使用原不可变来源、唯一事件和发奖证明，只能成功一次。停用商户的待发责任保留，审计失败整体回滚。已提交的其他订单不会因后续单失败而再次发放。

独立 `cmd/referral-scheduler` 默认关闭。必须同时选择 Compose 的 daily-referrals profile 并显式设置 `GOEPAY_REFERRAL_SCHEDULER_ENABLED=true` 才会工作；false、空值在连接数据库前退出，其他字符串拒绝。启用后从数据库取得 UTC+8 日期，每分钟最多处理20单，每次工作有30秒期限；异常退出，不自动重发上游请求。它没有支付机构客户端或凭据，不生成付款、退款或新资金授权。

## 未发奖退款

一次未解决的退款固定原手续费退还额 G。尚未发出的奖励 R 中，先贡献 `K=max(0,G-(F-R))` 到原退款手续费资金，剩余 `E=R-K` 转入本次退款专属暂存。全部来源、账户、日志和 K/E 与原退款号绑定。

- 退款结果未知：保留原 K/E 资金，不发奖，不换号重复退款。
- 明确失败：先释放普通退款手续费预留，再将 K 和 E 原路恢复完整 R；新的资金确认必须绑定最后一次失败证明，旧确认不能复活。
- 首次成功：E 回原手续费账户，原单奖励整笔撤销；后续退款不再重复撤销。
- 已发奖：沿原版本1奖励回收规则处理，不能把未发奖来源冒充已发奖励。

后台退款摘要明确显示取消原待发额，不扣推广商户可用余额；内部资金确认包含完整来源和结果证明，公开响应不返回这些私有字节。账务检查器必须同时识别正常待发责任、各退款状态、孤儿账户及缺失父子记录，不能仅豁免“找不到旧发奖记录”。

## 只读界面与验收

商户本人读取 `/console/v1/merchant/referral/daily-queue?after_id=0&limit=20`。推广商户从原会话取值，不接受 owner/promoter_id/merchant_id 选择器；坏编码、重复字段和非规范游标均拒绝。分页使用原 order_id；原付款商户、订单金额、手续费上限、固定奖励、当前待发额、激活时间、两个业务日和来源版本分别展示。所有ID和金额保持十进制字符串。pending/awarded/blocked/voided 与原账户余额一致才返回已验证来源。

前端只有 overview.daily_queue_available=true 才读取队列，只有政策 daily_mode_available=true 才可选择 daily；能力字段不是调度器运行证明。本人身份、会话或客户端改变立即清空并中断旧请求。当前待发额不等于可提现余额，退款暂存为0不能标成已发。

实际专项包含原签名微信回调的8并发一次出资、真实 PostgreSQL、独立资金授权、队列租户与金额来源、未知退款前后授权指纹、UI金额状态及本地浏览器。整体迁移70、检查器、全部旧资金回归、最终固定源码全量及部署结果仍按 `docs/test-results.md` 记录，不以本文设计或局部通过替代最终验收。
