# 付款记录统计

`GET /console/v1/admin/transfers/statistics` 和 `GET /console/v1/merchant/transfers/statistics` 汇总整个已查询范围，使用与付款列表相同的商户归属、状态、通道、支付方式、日期及私有字段搜索条件。管理员沿用 `TransferList` 菜单权限，商户只能统计本人记录。接口不调用上游，不发起付款。

查询字段沿用 `/transfers`：`merchant_id`、`channel_id`、`search_field`、`q`、`status`、`type`、`from`、`to`。拒绝分页参数 `page`、`limit` 和导出参数 `format`，重复、未知及空 ID 筛选同样拒绝。非 GET 方法返回 405。私有搜索仍使用现有受控索引，响应不包含收款账号、姓名或备注。

响应沿用 `{code, message, data}`，`data` 全部字段为十进制整数**字符串**：

| 字段 | 含义 |
|---|---|
| `count` | 符合条件的全部付款记录笔数 |
| `amount` | 原付款金额合计，整数分 |
| `fee_amount` | 原平台手续费合计，整数分 |
| `cost_amount` | 原花费金额合计，整数分 |
| `succeeded_count` | 当前有效状态为成功的笔数 |
| `failed_count` | 当前有效状态为失败的笔数 |
| `pending_count` | 待处理、结果未知及尚未发送的笔数 |

状态使用列表现有的结算出款、批次发送及银行生命周期投影。银行退回、撤销等状态不会算作成功；这些状态不一定计入以上三个状态分组，所以分组笔数可以小于总笔数。

金额为选中筛选范围内所有状态记录的原始汇总，不能当作实际银行净支出或利润。数据库使用精确聚合，前端使用 `BigInt` 转换元，不经过浮点数。整页金额合计可能超过单笔 int64 上限，仍保留完整字符串精度。

页面统计只读取已应用筛选，未提交的筛选草稿不改变范围。重新查询或刷新列表时清除原统计；会话改变、关闭统计、卸载页面或旧响应返回时，过期结果不能重新显示。关闭统计后键盘焦点返回原统计按钮。
