# 管理员渠道分账总览

总览使用独立的只读管理员接口。原有单商户接口仍要求明确商户归属，缺失商户号不能扩大为全平台范围；资金写入继续使用原有授权、原业务号及版本校验。

## 接口与权限

| 方法 | 路径 | 管理员菜单权限 |
|---|---|---|
| GET | `/console/v1/admin/channel-sharing/rule-overview` | `PsReceiver` |
| GET | `/console/v1/admin/channel-sharing/order-overview` | `PsOrder` |
| GET | `/console/v1/admin/channel-sharing/order-overview/statistics` | `PsOrder` |

沿用控制台会话认证及 `{code, message, data}` 响应格式。商户角色不能访问总览；写方法返回 405，`Allow: GET`。重复、未知、空的 ID 参数和超出 int64 的 ID 均拒绝，不会自动改成全商户查询。

## 规则总览

查询参数：可选 `merchant_id`、`channel_id`、`rule_id`、`receiver_id`，均为规范的正整数十进制字符串；`enabled` 只接受 `true` 或 `false`。`limit` 默认 20，范围 1–100；`offset` 默认 0，最大 1,000,000。

返回 `data.items`、`data.total`、`data.limit`。每项包含当前不可变 `rule` 版本以及 `receivers` 脱敏摘要。规则及接收方 ID、金额、比例均沿用原有字符串字段；`total`、`limit` 为 JSON 数字。页面拒绝无法精确表示的计数。

- 只列出每个商户/通道的当前版本，包含关闭状态的规则；按规则 ID 倒序分页。
- 不调用上游，当前通道离线或未配置不影响读取已保存规则。
- 接收方摘要只包含 `id`、`account_masked`、`name_masked`、`state`，不返回明文账号、密文或密钥。
- 当前规则模型按商户与支付通道绑定，没有独立的子通道字段；界面显示“—”并说明原因。
- 规则、条目及接收方在同一个只读可重复读事务内批量读取；校验版本完整性和接收方归属后才返回。

## 记录、统计与导出

两个记录接口共用以下可选筛选：

| 参数 | 取值 |
|---|---|
| `merchant_id`、`channel_id`、`subchannel_id`、`rule_id` | 规范正整数 ID |
| `field` | `external_no`、`out_no`、`share_amount` |
| `keyword` | 指定字段的精确匹配值；分账金额使用整数分字符串 |
| `status` | `unsent`、`submitted`（包含 `claimed`、`pending`）、`succeeded`、`failed`、`partial`、`cancelled`、`unknown` |
| `from`、`to` | `YYYY-MM-DD`，北京时间自然日，包含结束日的全部精度 |

记录列表另接受 `limit`、`offset`，以及 `format=csv`。统计接口拒绝分页及导出参数，统计整个筛选范围。列表 `items` 新增字符串 `merchant_id` 与 `subchannel_id`；无原订单子通道路由时返回 `"0"`，页面显示“—”。子通道来自原支付订单的持久化路由，不能用当前配置推算历史。

CSV 使用相同筛选，增加“用户ID”和“子通道ID”列，继续使用现有行数限制、UTF-8 BOM、公式注入防护与审计。时间统一按 `Asia/Shanghai` 格式化。

页面的查询、翻页、刷新、统计、导出使用同一份已应用筛选；尚未提交的输入只作为草稿。行操作携带该行返回的商户归属，不能借用草稿中的商户号。

管理员和商户列表均可勾选本页最多 20 条记录，确认后顺序查询所选原分账结果。确认摘要保留每条原商户与原业务号，同一业务号在不同商户间不会合并。每次响应都核对记录 ID、业务号、商户及状态；遇到错误停止后续查询，显示已完成数量，并在刷新后保留仍可见的未完成选择。取消确认不发请求，路由或会话变化后不会继续查询下一条。此入口不创建分账或回退请求。

## 配置与回退交互

新增规则先选择配置商户，再进入单商户配置；编辑、启停捕获当前商户、通道及规则版本，版本变化后重新核对。支持按比例和固定金额规则，金额按整数分精确处理。规则写入结果未知时只核对原规则，不自动重复发布。

分账回退先读取原分账明细、选择成功接收方、核对金额并明确确认，再进入既有资金授权。未核实结果时保留原回退请求号，仅允许查询原请求。浏览器持久存储只保存原请求元数据，不保存 CSRF、资金授权或账号凭据。使用同源 Web Locks 防止同一浏览器的两个标签页同时派发不同请求号；不支持该能力或存储不可用时阻止新回退并显示恢复说明。这不替代服务端的归属、金额、幂等及并发校验。
