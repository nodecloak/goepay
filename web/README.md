# GOEPAY 双后台

Vue 3 + TypeScript + Vue Router + Vite。管理入口 `/admin/dashboard`，商户入口 `/merchant/dashboard`。全部原版菜单与隐藏路径保存在 `src/data`；82 个原版叶子路径逐项状态见 `capabilities.json`。新增管理员保证金审批位于 `/admin/merchant/deposit-review`，不计入原版 82 项。

```powershell
cd E:\GOEPAY\web
npm ci
npm test
npm run build
$env:GOEPAY_API_URL='http://127.0.0.1:8180'
npm run dev
```

Compose 中的生产前端端口为 `8181`，Go API 为 `8180`。本地 Vite 默认代理到 `8080`，通过 `GOEPAY_API_URL` 覆盖。生产 Nginx 提供静态资源、SPA 路由回退和同源 `/console` 代理。

## 已实现的交互

- 双身份 Cookie 会话、CSRF、验证码登录、密码修改后重新认证；TOTP 绑定二维码完全在本地生成，绑定密钥不进入浏览器持久存储。
- 管理员账户安全页支持本人独立资金密码设置/修改，核验当前管理员登录密码、已设置的旧资金密码及已绑定的 TOTP；无默认密码，不借用商户凭据。密码仅在组件内存，验证失败、取消或离开立即清除。
- 管理员敏感资金写通过统一授权弹窗核对服务端脱敏摘要，再验证资金密码，最后明确执行同一原始请求与业务号；短授权仅在当次 `X-Payment-Authorization` 头中传输，不进入链接、日志或浏览器持久存储。资金安全状态读取失败时阻止新的受保护写；明确未强制时维持原有流程。HTTP 428 不自动补授权重试，202 或网络未知沿原业务查询，不自动重新付款。界面授权不替代服务端的事务级校验和通道写开关。
- 商户资料、已遮蔽的 API 接入信息、当前密码确认后重置 API 密钥；新密钥仅在当次组件状态中展示，离开或隐藏后清除。
- 仪表盘和交易列表使用真实服务端数据；退款保持金额字符串与业务请求号，界面不凭请求成功猜测支付处理结果。
- 订单详情显示商户入账额、平台费用及通道状态；主动查询与二次确认关单分别调用服务端通道操作，HTTP 202 明确表示结果未核实。退款按返回状态显示成功、待核实或沙箱资金预占。
- 付款先读取商户和通道权限，仅显式支持 `bank` 且产品能力一致时显示银行卡方式：`alipay_bankcard` 要求真实姓名、对私银行卡且不提交微信银行编号；`wxpay_v2` 要求姓名与开户银行编号。产品缺失、未知或与 `bank_code_required` 矛盾时禁止提交。微信银行编号映射来自随附 `epay_release/plugins/wxpay/inc/bankcode.json`，名称取 `epay_pro/app/data/bankname.json` 中对应的 46 项，服务端仍独立核验通道权限。提交前展示金额上下限、同收款方日次数限制、默认说明/标题；金额以整数分比较，剩余次数不凭前端猜测。
- 银行付款详情分开展示有效状态、历史账本状态、银行生命周期、已核实银行手续费、服务费暂存、返还金额与退票流水。`reversal_pending` 不视为到账或已返还，`reversed` 不视为收款成功；未知结果仅查询原记录，不提供银行凭证按钮。支付宝凭证首次申请需确认，后续查询已有凭证。
- 支付宝银行卡的预计银行手续费与实际已核实手续费分别展示；后台详情的两项金额均以分标注，估算从不代表实际已扣或已退费用。支付宝通常缺少金额/身份回显的退票不保证自动闭环；缺少证据时保留待核实状态，界面不会声称资金已返还。
- 预授权详情展示授权金额、捕获状态和解除原请求。仅服务端明确允许时提供全额未扣款冻结解除，并核对授权号、金额及原请求后二次确认。处理中或未知结果只查询原请求；服务端允许且明确尚未发送的原请求可再次显式核对，前端不生成新的解除请求号。解除成功表示买家冻结已解除，不是商户退款，不增加商户余额；已支付订单不能解除，预授权不使用普通关单。
- 预授权扣款仅在服务端许可、订单待支付、尚未扣款且未发起解除时展示，二次确认明确说明“扣取买家授权金额”，与解除确认互斥。未知扣款只查询原订单，不重发扣款；动作后重新读取详情。
- 已支付且服务端允许的订单支持确认后重发商户通知；网络错误、排队或处理中保留原 UUID，通过同号核对/重试。仅明确发起下一次新操作才生成新 UUID，冷却响应显示服务端等待秒数并禁止提交，只有 `succeeded` 显示收到商户成功响应。
- 管理员（含普通管理员）仅在服务端许可时可二次确认冻结订单剩余净收入、按当前冻结批次解冻。网络错误保留原 UUID 或原 hold ID，不切换到新的冻结循环。收入冻结调整平台账本，不是买家预授权；已支付状态不变，冻结期间禁用退款并提示先解冻。列表提供收入状态显示与筛选。
- 超级管理员还需商户 schema 明确提供 `sso` 才能确认代登录。授权仅通过 POST body 消费，不放链接或持久存储；网络结果未知时只回读商户会话。成功后用独立商户客户端核对身份，并提供新标签入口；商户页面显示实际管理员、15 分钟期限及撤权后失效提示。
- 商户登录页提供注册和找回密码表单；先读取公开能力，邮件未配置、注册关闭或能力格式不完整时禁止相应发送。验证码挑战绑定当前邮箱，改邮箱即废弃，重发冷却与有效期可见。密码、验证码、挑战和邀请码只保留在组件状态，成功或离开清除。成功注册不自动登录；密码恢复使用统一文案且保留动态验证码验证。默认部署没有邮件发送器，实际邮件送达和旧商户可信邮箱绑定迁移仍待实施。
- 有类型的资源表单覆盖商户、用户组、授权域名、邀请码、公告、管理员、支付资料、本地进件/投诉资料与系统配置等。字段与创建/编辑/删除权限取自服务端 schema，支持校验、只读、创建时专属字段、密码字段、详情、删除确认、查询和分页。
- 商户可仅创建 API 身份；提供登录名和密码时才开通后台账号。已有登录名不可更名，重置密码使用只写字段，空密码不覆盖已有值。
- 进件与投诉详情支持本地处理历史、沟通备注、提交平台本地审核、管理员本地审核。界面明确表述这些操作不代表外部进件、上游投诉回复或退款。
- 11 个统计路径提供日期过滤、分页、本页 CSV 与服务端筛选结果 CSV 导出；订单、退款、付款和资金流水列表也支持筛选结果导出。筛选导出复用列表参数、忽略分页，最多 50,000 行或 8 MiB，超限返回错误而不截断。下载仅接受 HTTP 200、CSV 附件标识与 UTF-8 BOM，401 或 JSON 错误不保存为文件；读取过程有 8 MiB 上限。可取消导出，改变筛选或离开组件会中止待处理下载，对象 URL 使用后释放。CSV 字段防止公式执行，金额字符串保持原样。
- 结算申请、站内转账、批量账务审批；结算核准仍保留冻结资金，不声称已向银行出款。批量处理遇首个错误停止并显示已完成数量。
- 结算出款详情分别显示审批、原费用/收款快照、独立资金归属与原 TF 结果。管理员明确确认可用的钱包通道后才能本地准备唯一绑定，发送或已证明未发送的取消走独立资金授权；准备不重复预占。已领取发送的原意图只查询，不生成新 TF 重发；202 与网络未知不显示成功。商户只读并查询自己的原出款。银行卡与缺失费用、资金或收款快照的历史记录不使用本钱包出款流程。
- 结算、站内转账与外部付款分开展示 T+0/T+1 政策、可出账金额、账面可用余额和当日实际受限金额。管理员须先显式查询付款商户，修改商户后立即废弃旧结果，迟到响应不能启用另一商户的提交。政策缺失或读取失败时禁止提交，不假定余额为零或默认为 T+0；提交时仍由后端重新核验。按规则生成的站内分账遵循相同出账政策。
- 会员购买使用服务端组价格扣减余额；保证金转入、释放申请和管理员审核；充值创建订单并打开经过 HTTP/HTTPS 校验的付款链接，只有核实支付回调后入账。
- 登录日志、审计日志、任务查看和可重试通知、运行能力信息；过期登录状态清理先预览再显式确认，原样使用服务端回显的截止时间，不清除账本或交易。

`capabilities.json` 中所有已接入页面仍标记为 **partial**。完成资源 CRUD 不代表原版页面全部联动、外部服务、导入导出、按钮及权限已逐项通过验收。管理员身份使用服务端 `admin_class`：显式 `super` 对应原版 `R_SUPER`，`operator` 对应 `R_ADMIN`；缺少类别时前端按普通管理员处理。后端仍独立验证资源与操作权限。

## API 合同

所有后台请求使用 `/console/v1/{admin|merchant}`，成功响应 `{code:0,data:...}`，失败为非零 `code` 与 `message`。客户端同时检查 HTTP 状态和应用状态，写请求带 `X-CSRF-Token`；金额以十进制字符串提交。

- `/session`、`/login`、`/logout`：会话，登录可选 `code`。
- `/resources/{resource}/schema`：字段与操作权限；集合 GET/POST、单项 GET/PATCH/DELETE。
- `/resources/{resource}/{id}/{history|comments|submit|review}`：本地案例流程。
- `/orders/{trade_no}`、`/{query|close|refund}`：订单详情、通道查询、确认关单与退款。
- `/orders/{trade_no}/{release-authorization|query-authorization-release}`：服务端许可的全额授权解除与原请求只读查询，均提交 `{}` 并带 CSRF。
- `/orders/{trade_no}/capture-authorization`：核对并扣取买家授权金额，提交 `{}`；未知结果只使用既有 `/query` 查询。
- `/orders/{trade_no}/resend-notification`：以 `{external_no: UUID}` 持久去重的通知请求，未完成任务合并到原队列。
- 管理员 `/orders/{trade_no}/{freeze-income|unfreeze-income}`：分别提交 `{external_no: UUID}` 与 `{hold_id: string}`，不调用支付机构。
- 管理员 `/sso/grants`、`/sso/consume`：确认后的短时商户代登录授权及一次消费；商户会话独立核对。
- `/transfers/capabilities`、`/transfers`、`/transfers/{id}`、`/{query|proof}`：钱包付款权限、申请、详情、核实及凭证。
- `/reports/{report}`：`from`、`to`、`page`、`limit`，返回真实列定义与统计记录。
- `/workflows/{kind}`：账务申请、会员、保证金、充值；审批为 `/{id}/{approve|reject}`。
- `/workflows/funds-availability`：本商户的出账政策与资金快照，管理员必须提供 `merchant_id`。
- `/settlement-payouts/{request_id}`：读取原申请和独立出款；管理员 `/capabilities` 与 `/prepare` 核对钱包通道，`/{execute|cancel-unsent}` 明确资金授权，所有者 `/query` 只查询原 TF，写请求均使用原申请 ID 和 CSRF。
- `/account/{profile|api-info|password}`、`/account/api-key/rotate`：资料与账户安全。
- `/security/totp`、`/security/totp/{prepare|confirm|disable}`：动态验证码设置。
- 管理员 `/security/payment-password` GET/PUT：独立资金凭据状态和设置；`/security/funds-authorizations/{challenges|confirm}` POST：绑定原动作的预览与密码核验。授权只用于原操作的当次 POST，不保护商户签名 API、查询或回调；各业务后端事务钩子的集成结果须独立验证。
- `/operations/{kind}`：运行信息与受限清理。
- `/orders`、`/refunds`、`/transfers`、`/ledger`、`/reports/{report}` 增加 `format=csv` 导出当前全部筛选结果，仍发送合法 `page/limit`，服务端独立执行权限与行数/字节限制。

公开商户邮箱流程使用 `/console/v1/public/{capabilities|verification-code|register|recover-password}`。JSON 写请求由服务端核验 Origin，不使用后台 CSRF 或管理员客户端。验证码为 7 位，只能通过已配置的发送器送达邮箱，不由 API 回显。

## 验证与部署

```powershell
npm run test:e2e
$env:GOEPAY_WEB_URL='http://127.0.0.1:8181'
$env:GOEPAY_LIVE_E2E='1'
npm run test:e2e
npm audit --omit=dev
npm audit
```

默认浏览器测试使用网络替身验证交互与失败路径，真实 Docker 测试仅在显式设置 `GOEPAY_LIVE_E2E=1` 时执行。真实测试从项目根 `.env` 读取本地 seed 密码，不输出凭据；不会重置种子密钥或更改种子密码。测试前必须应用全部迁移；项目 Compose 通过 migrate 服务自动执行，单独运行 API 镜像仍需先执行 CLI。

单元/组件测试覆盖菜单保留、隐藏页、角色、CSRF、金额、schema 校验、只读字段、清空可选字段、日期范围、CSV 和真实后台角色授权。浏览器测试覆盖资源完整 CRUD、批量部分失败、账户安全、TOTP、会员购买、充值不假入账与危险链接拦截，并另有真实 Docker 会话、资源持久化、报表、日志和结算审批测试。实际执行结果请以当前测试命令与项目集成报告为准。

在项目根更新前端：`docker compose build web`，随后 `docker compose up -d --no-deps web`。静态构建仅包含必要前端文件，开发依赖不进入 Nginx 最终镜像。

补充页 `/profitsharing/internal-orders` 提供站内分账审批；原版 `/profitsharing/internal` 规则详情可针对已支付订单申请站内分账，金额由服务端计算。两者均不表示上游渠道分账已实现。新增页能力另列于 `supplemental-capabilities.json`。任务计划和本地插件页面同时显示持久配置表单与实际运行队列/能力，保存配置不等于已经执行任务或安装代码。

82 个原版页面中，74 个已接入页面标记为 `partial`，仍需逐项验收全部操作语义；渠道分账规则/记录的管理与商户四页、独立获取支付用户标识页、邀请返现页共 6 项标记为 `pending`，属于尚未实现、仍待实施的缺口。仅应用市场和实名认证两页标记为 `deferred`。订单支付 OAuth 不能替代独立获取用户标识页，站内分账也不能替代渠道分账，不能将菜单数量解释为完整功能验收通过。
