# 余额、费用与账务

## 先分清金额

| 字段 | 应如何理解 |
| --- | --- |
| 订单金额 | 商户提交的名义金额 |
| 实付 / 实收金额 | 实际要求付款及被核实的支付金额；订单加费时可能与名义金额不同 |
| 分成比例 | 商户分得的比例，不是同数值的手续费率 |
| 手续费 | 按该笔订单已保存的规则计算的费用 |
| 可用余额 | 当前可以用于相应业务的余额，仍受业务条件限制 |
| 冻结余额 / 预占 | 已为退款、结算或其他受保护流程保留的资金，不是另外一笔收入 |
| 已退金额 | 已被系统确认的累计退款，不包含仅提交但未确认完成的请求 |

界面通常以“元”显示，底层按整数分记账。金额、费用、可退上限请以原订单和原业务记录为准，不要用当前费率倒算历史订单。

## 分成比例示例

当展示的是商户分成比例 **99.50%** 时，不能理解为“收取 99.50% 手续费”。在没有其他计费因素的简单示例中，100 元订单按该比例对应商户 99.50 元、差额 0.50 元。实际结果还受手续费模式、取整和订单保存的规则影响，应核对订单明细。

## 一次业务怎样核对

1. 从订单、退款或结算记录取得原业务号。
2. 打开 **资金明细**，按业务号筛选。
3. 对照可用与冻结变化、费用及最终状态。
4. 如果结果未知，先核对原业务；不要通过余额调整、手动退款或新付款来“补平”。

## 统计数据与实际到账

交易统计、账户余额和结算统计关注的时间及状态不同。比较报表时，使用相同商户、时间、支付方式和状态口径。支付机构已收款不表示运营方已经向商户结算；结算成功也不能仅凭审批动作推断。

订单归档、运行日志清理不会删除或重建支付事实。账本或历史金额异常应保留证据并联系运营方处理。
