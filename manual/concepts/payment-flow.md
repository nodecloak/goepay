# 支付回调时序与订单状态

## 一笔支付怎样完成

<Diagram name="payment-sequence" caption="支付时序：下单、付款、机构回调与商户通知" />

1. 商户业务系统为业务订单生成唯一商户订单号，签名请求 GOEPAY。
2. GOEPAY 校验权限和策略，保存订单与实际通道，返回支付材料。
3. 用户在支付宝、微信等应用完成确认。
4. 支付机构向 GOEPAY 发送回调。GOEPAY 验签并核对订单身份、金额后确认入账。
5. GOEPAY 向商户通知地址发送签名通知。商户验签、幂等更新自己的业务订单。
6. 浏览器回到商户页面，展示服务端已经确认的业务结果。

::: warning 浏览器跳回不是到账凭据
成功页、截图、手机播报或用户口头说明都不能替代服务端结果。只有验签并核对后的支付事实，才能用于更新商户业务状态。
:::

## 常见状态应该怎样理解

| 状态 / 提示 | 含义 | 下一步 |
| --- | --- | --- |
| 未支付 / 待支付 | 本地尚未确认付款 | 核对原订单；需要时按权限手动补单 |
| 已支付 | 平台已确认收款 | 核对金额、资金明细和商户通知 |
| 已退款 / 部分退款 | 已确认的退款影响了订单可退余额 | 到退款记录查看每次原退款 |
| 收入冻结 | 平台对该订单收入做了资金限制 | 查看冻结原因与对应冻结记录 |
| 结果未知 / 核对中 | 请求可能已被上游接受，尚不能确认终态 | 只查询原业务，不创建替代单 |
| 已删除 / 归档 | 管理列表中的运营归档状态 | 财务事实仍保留，按权限恢复展示 |

“改已完成 / 改未完成”属于管理员业务状态操作，不代表向支付机构扣款或退款；详情中的真实支付、退款和账务记录需要分别核对。

## 重复通知为什么不会重复入账

同一订单可能收到多次机构回调，商户通知也可能按策略重试。接收方必须使用唯一业务号和数据库事务保证重复到达只确认同一笔业务。看到重复通知日志时，先检查是否重复入账，不要直接删除原订单。

## 支付异常的最短处理路径

**原订单号 → 实际支付金额 → 原通道 / 上游交易号 → 回调确认 → 资金明细 → 商户通知结果**。沿这条路径排查，见[常见问题](../troubleshooting.md)。
