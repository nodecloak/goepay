# 常见问题与处理路径

先记录商户号、平台 / 商户订单号、原业务号、时间和明确错误。处理未知结果时只核对原业务，不用新订单、新退款或手工调余额代替。

## 新商户没有默认通道

**管理员处理：**商户启用与收款权限 → 当前有效用户组 → 该方式是否关闭 → 商户显式授权 / 公共默认池 → 通道是否可用 → 轮询、限额、时段、认证与保证金条件。

新用户组的方式可能默认关闭；显式空授权不会回退继承。请参照[用户组与默认通道](./admin/groups.md)，不要给新商户直接开放所有通道或代付。

## 能登录，但提交支付提示通道不允许

登录权限与收款通道权限不同。核对订单请求的支付方式、商户有效用户组、通道授权及原请求参数。用户侧应显示可理解的错误，运营方保留原业务上下文排查，不反复换通道提交同一订单。

## 管理员模拟登录失败

核对该商户是否有已启用的登录账号。仅 API 商户资料不等于有后台账号。授权结果未知时只读取当前会话，不自动重试授权或消费。需要本人会话的功能，改由商户本人登录。

## 用户已付款，平台还未支付

从原订单核对上游交易号、实际金额、原账户和回调验签结果。按权限查询 / 手动补单，不用“改已完成”伪装支付证明，不要求用户再支付。见[支付时序](./concepts/payment-flow.md)。

## 平台已支付，商户系统仍未更新

检查商户通知地址、HTTPS / 网络、签名方式、平台公钥及成功应答格式，再核对商户自身幂等逻辑。修复后按原订单重新通知；不更改已确认金额，也不再次扣款。

## 电脑没有二维码，手机不跳转

核对原订单使用的产品与设备环境，查看支付材料是否有效、通道是否支持该场景。公众号 / 小程序和外部浏览器授权不同。保留原单恢复，不用另一通道重建订单；不要把被裁切或无法完整显示的二维码发给用户扫描。

## 分成比例与预期手续费不一样

先确认字段是商户分成比例还是费率，以及余额扣费 / 订单加费模式。用原订单费用快照核对，不能用修改后的当前费率倒算历史订单。

## 退款一直处理中或结果未知

保存原退款号，使用原退款查询 / 核对入口。核对实际金额、原通道和资金预占，不换号再退，不因为查询慢改用手动退款。见[退款处理](./admin/refunds.md)。

## 可用余额大于零，仍不能提现

检查结算方式、账户资料、最低金额、结算周期、费用、预留、保证金及原申请预占。结算申请受理与实际付款完成不同；结果未知的原申请不要重复创建。

## 开启消息提醒却没有声音、短信或小票

检查平台凭据、接收人 / 设备绑定、事件开关、模板、商户个人设置与实际执行条件。云喇叭要完整 agent 凭据；打印要平台 APPID / APPSECRET 和商户设备；业务短信要独立模板与可信手机。见[通知配置](./admin/notifications.md)。

## OCR 识别成功但没有认证

OCR 只预填资料，必须人工核对后走本人认证。回到实名认证页面查看服务端结果；余额不足且有有效通过证明时按原证明完成，不重复调用核验。

## 保存提示冲突或无法确认结果

冲突时重新读取并比较草稿；结果未知时先读原记录。脱敏密钥不是实际值，不重新提交占位符。确认是否使用了该区块自己的保存按钮。

## 菜单缺失或没有编辑按钮

核对登录角色、受限管理员菜单授权、商户功能开关、本人 / 代登录身份、记录状态及服务是否实际接入。页面能打开不等于拥有全部资金或配置权限。

## 更新包已准备，但页面版本没变

准备包与程序部署是两个状态。请部署管理员按可信发布流程完成程序与静态文件切换，再刷新页面核对；不通过重建数据库“重装”已有资金业务。
