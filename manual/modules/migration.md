# 从易支付迁移到 GOEPAY

本模块仅用于将旧系统的一致备份导入符合条件的全新 GOEPAY 安装。由超级管理员本人执行，商户在迁移完成、重新配置与核验后取得新的登录和接入资料。

## 从哪里进入

| 任务 | 管理员入口 | 商户如何参与 |
| --- | --- | --- |
| 预检查、导入与报告 | 系统管理 → 易支付迁移 `/admin/system/migration`，仅超级管理员本人 | 无迁移执行权限 |
| 重建商户能力 | 商户管理、用户组设置、支付接口及相关系统设置 | 本人设置新登录与签名资料，确认余额和历史订单 |
| 完成人工切流 | 由部署方执行域名与业务系统切换 | 更新自己后端的站点地址、凭据与通知验签配置 |

## 迁移前决定三件事

1. **取得一致来源。** 在原系统暂停写入，导出向导支持的 MySQL SQL 备份并离线保存。选择实际来源版本，不混用来源或自行改写金额、状态。
2. **保留全新目标。** 目标初始化管理员后，先运行预检查；不要先创建演示商户、订单或资金业务。已有数据是否符合要求由向导实际检查决定。
3. **安排重配置与切流。** 准备数据库、配置及主密钥备份，明确哪些人负责商户凭据、通道、用户组与验收。导入不会自动替你切流或开放付款任务。

## 执行一次可核对的导入

1. 上传支持的 SQL 文件，单文件上限 64 MiB，选择正确来源版本。
2. 运行预检查，检查来源摘要、表与记录数量、可用余额、原生导入、仅归档、警告及阻塞项。
3. 对照来源核对商户、订单和退款等数量以及总金额。发现阻塞先解决来源或目标条件，不能通过手改余额或删除义务来绕过。
4. 阅读确认范围并执行原迁移任务，保存任务标识。页面中断或结果未知时重新读取原任务，不再次上传执行同一份备份。
5. 查看完成报告，核对导入数量、期初余额和账务结果，保留报告与来源摘要供后续验收。

## 哪些变为原生记录，哪些只作归档

| 来源内容 | 迁移结果与核验方法 |
| --- | --- |
| 可映射商户与可用余额 | 导入商户和期初余额；核对总额及每户余额 |
| 普通历史订单 | 原生历史记录；历史已支付订单不再入账或补发通知 |
| 有明确成功证据的历史退款 | 只读退款历史，不生成新的可执行退款 |
| 完整源备份及未转换字段 | 加密归档，不能直接当作当前系统的可执行配置 |
| 用户组、通道、设置、密码、API 密钥、插件和实名资料等 | 不自动获得当前有效配置或授权，按业务模块重新核实和配置 |

导入商户保持停用并取得新的随机接入凭据。旧密码和旧 API 密钥不能直接用于新站点，旧通道也不会自动接收新订单。

## 阻塞项怎么处理

常见阻塞包括目标已有业务、金额精度或状态无法可靠映射、未决退款 / 付款 / 结算、冻结或保证金义务、孤立记录、重复业务号及不完整备份。以当前预检查报告列出的具体路径和原因处理，再重新检查，不能把只归档误认为债务已解决。

## 导入后的验收与启用

重新配置用户组和通道，为需要后台的商户建立并交付登录资料，完成签名、认证与必要业务条件。先对照来源检查余额和历史样本，再用新模拟订单验证新请求、通知、退款和资金明细。逐个启用商户后，由部署方和商户更新地址与凭据，人工切流。

向导不修改原数据库、不执行外部付款、不自动启用资金任务。准备任务过期也不表示加密归档自动删除；保管好数据库和原主密钥，丢失密钥将无法正常读取归档。
