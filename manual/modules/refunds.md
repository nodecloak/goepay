# 退款与售后退还

商户从自己的已支付订单申请退款，管理员跨商户核对原支付与退款结果。API 退款通过原支付机构退钱；手动退款是线下已经退还后的账务登记，当前要求超级管理员本人操作。

## 从哪里进入

| 任务 | 管理员入口 | 商户入口 |
| --- | --- | --- |
| 发起退款 | 订单管理 `/admin/trade/order` → 原订单操作 | 订单管理 `/merchant/trade/order` → 原订单退款，需开放自助退款 |
| 追踪与核对 | 交易管理 → 退款记录 `/admin/trade/refund` | 交易管理 → 退款记录 `/merchant/trade/refund` |
| 处理未知结果 | 原订单中的“核对原退款”及原退款记录 | 自身原订单中的“核对原退款” |
| 线下退还记账 | 原订单中的“手动退款”，仅在实际允许时出现 | 无管理员手动退款权限 |

## 先选处理路径

| 当前事实 | 选择 | 完成标志 |
| --- | --- | --- |
| 需要由原支付机构向买家退还 | API 退款 | 原退款被机构及服务端核实成功，累计退款和账务更新 |
| 已在线下实际退还买家，有金额、原因和证据 | 手动退款 | 超级管理员本人明确确认线下已退，并记录平台退款账务；不会发送机构退款 |
| 已提交但超时、中断或显示待核实 | 核对原退款 | 读取或恢复同一退款号的原结果，直至有明确结论 |

**手动退款不会替你把钱退给买家。** 不因 API 慢、页面无响应或状态未知改走手动退款，否则可能出现线下退还和机构退款同时完成。

## 完成一次 API 退款

1. 从原订单打开详情，核对商户、支付身份、原通道、实付金额、累计已退和剩余可退金额。
2. 选择 API 退款，填写本次金额与必要原因。部分退款以当前可退余额为界，不按新费率重新计算历史实付。
3. 阅读确认内容，按要求完成资金密码 / TOTP 等本人确认，提交一次并记录原退款号。
4. 到退款记录查看受理、处理中、成功、失败或未知状态。受理表示请求已建立，不表示买家已经收到款项。
5. 成功后返回原订单核对累计已退金额，再到关联资金明细核对扣减、预占结转及费用。

## 线下退款登记的完整步骤

先在既定线下渠道完成实际退还，保留买家、原支付订单、金额和付款证据。超级管理员本人打开原订单的手动退款，填写本次金额及原因，核对页面的操作请求号和资金来源，并勾选“已完成线下退款，本次只记录账务”的确认。完成本人资金授权后提交，成功结果应明确说明通道未发起退款；再核对原退款记录和账务。

若已有同一原 API 退款待核实，先完成其查询；手动登记不能接管未知机构请求。商户或普通管理员看不到该动作时，应由具备对应权限的人处理。

## 退款记录怎么读

| 字段 | 核对方法 |
| --- | --- |
| 退款号 / 商户退款号 | 固定使用原标识恢复请求；不换号重新退款 |
| 关联订单与通道 | 与原支付身份一致，不能换商户或换通道处理同一退款 |
| 退款金额 / 扣减金额 | 对应买家退还和商户账务，分别查看，不凭列表一列推算 |
| 申请时间 / 完成时间 | 创建记录和确认完成是不同时间 |
| 状态与原查询结果 | 明确失败才按原流程处理释放；未知继续保留原业务与资金归属 |

网络中断后重新打开原订单或退款记录即可开始核对。退款事实不通过任意新增、改金额或删除来整理历史。
