# 系统配置、应用与维护

超级管理员维护全站设置、执行环境和系统工具；获授权运营人员维护公告、日志等允许范围。商户在相应业务模块使用已开放能力，没有平台维护权限。

## 从哪里进入

| 任务 | 管理员入口 | 商户侧结果 |
| --- | --- | --- |
| 全站业务政策 | 系统管理 → 系统设置 `/admin/system/settings`，超级管理员 | 在收款、认证、结算等对应页面生效 |
| 实际任务调度 | 系统管理 → 计划任务 `/admin/system/cron`，超级管理员 | 已授权任务产生的业务结果 |
| 登录与运行记录 | 登录日志 `/admin/system/log`；运行日志 `/admin/system/runtime-log`，后者仅超级管理员 | 本人账户安全记录及业务记录 |
| 清理与升级准备 | 数据清理 `/admin/system/clean`；系统更新 `/admin/system/update`，超级管理员 | 维护后的站点服务 |
| 模板与应用 | 应用管理 → 模板配置 `/admin/app/template`、应用市场 `/admin/app/app-store`、本地插件 `/admin/app/plugin-list`、扩展配置 `/admin/app/addon`，超级管理员 | 实际已支持的页面与业务能力 |
| 收款码展示 | 其他功能 → 聚合收款码样式 `/admin/other/onecode` | 商户聚合收款中选择样式 |

## 修改一项全站设置

1. 选择业务分类，读取当前值，区分未配置、关闭和已有脱敏凭据。记录本次要改变的行为。
2. 核对字段单位与作用范围，修改对应项目。支付、组别或费用政策影响后续业务，原订单仍使用自己的材料和快照。
3. 使用该区块的保存按钮。普通设置、加密凭据、机器人和硬件可能分别保存，不能用一次成功提示推断所有区块都已更新。
4. 重新读取开关、数值和凭据状态。密钥留空保留、明确清除、替换新值各有含义，按页面操作选择。
5. 在模拟环境验证一条应允许和一条应受限的路径，观察实际业务结果。开关只是条件之一，还需产品、通道、绑定、授权及执行环境满足。

| 需要改变什么 | 对应分类与模块 |
| --- | --- |
| 品牌、站点文字、注册和展示 | 网站信息、商户相关、公告排版；模板与收款码样式 |
| 支付金额、商品、风控与投诉 | 支付相关、风控检测、交易投诉；[进件与风险](./risk-onboarding.md) |
| 结算与付款政策 | 结算规则、转账付款；[结算](./settlements.md)、[代付](./transfers.md) |
| 接收消息与验证身份 | 消息提醒、邮箱、短信、实名认证、OCR；[通知](./notifications.md)、[认证](./certification.md) |
| 登录应用、IP 和代理 | 快捷登录、IP地址、中转代理及高级设置；核对应用归属与实际部署能力 |

邀请返现政策 `/admin/system/referral-policies` 与订单名称限制 `/admin/system/order-subject-policies` 使用独立页面，保存后确认当前版本、生效范围和状态。

## 调度、日志与清理

在计划任务读取业务说明，设置开关、执行时间、周期或间隔及参数，保存后核对下次运行时间，再看真实运行状态、结果和日志。“待执行”不能解释成完成，调度计划也不额外授予付款、退款或发消息权限。

排查时先按日期、账号和原业务缩小日志范围。数据清理先选择截止条件并预览数量，确认后查看原操作实际结果；未知时重新读取和预览。登录日志清理与运行日志归档是不同操作，财务订单、账本和资金事实不通过此页随意清除。

## 模板、插件与系统更新

模板编辑后预览电脑和手机，确保金额、二维码、商品和按钮可见，再保存并验收。收款码样式改变展示，不开通通道或更改商户费率。应用目录存在、配置保存、安装、授权与实际执行分别看；新增能力需部署方提供当前版本支持的 Go 适配实现。

更新页读取版本和可信来源后准备更新包。“准备完成”不代表程序已切换，实际部署需备份数据库、配置和主密钥后按部署流程执行。保留真实资金事实，不用恢复旧数据库撤销已经发生的支付。
