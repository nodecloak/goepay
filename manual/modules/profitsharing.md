# 渠道分账与站内分账

商户维护自己获准的分账关系和订单，管理员配置或跨商户审核规则。渠道分账由支付机构执行；站内分账在 GOEPAY 内部处理余额，使用前应明确最终接收方位于哪一个系统。

## 从哪里进入

| 任务 | 管理员入口 | 商户入口 |
| --- | --- | --- |
| 渠道分账接收人与规则 | 分账管理 → 分账规则 `/admin/profitsharing/receiver` | 订单分账 → 分账规则 `/merchant/profitsharing/receiver` |
| 查询渠道分账 | 分账管理 → 分账记录 `/admin/profitsharing/order` | 订单分账 → 分账记录 `/merchant/profitsharing/order` |
| 站内规则 | 分账管理 → 站内分账规则 `/admin/profitsharing/internal` | 当前规则及权限决定可参与范围，无平台规则管理权 |
| 站内申请与审批 | 分账管理 → 站内分账审批 `/admin/profitsharing/internal-orders` | 在本人资金明细核对实际变动 |

## 建立并执行渠道分账

1. 确认支付机构和运营方已开放所需分账产品，原支付通道支持该能力。普通收款通道可用不等于已开通分账。
2. 在分账规则中先选择正确商户和通道，再选择接收方类型，填写机构要求的身份、名称以及比例或金额规则。
3. 保存后重新读取，检查规则和启用状态。机构要求接收方登记、关系确认或授权时，按原关系完成；本地保存不能代替上游确认。
4. 找到允许分账的原支付订单，核对原商户、通道、可分金额和接收人，执行当前产品提供的动作。
5. 在分账记录按原分账号查询，核对申请金额、确认金额、机构结果和时间。结果未知时继续查原分账，不能创建替代单。

## 站内分账的工作顺序

管理员先核对规则来源、参与商户、资金来源及接收范围，保存可检查的规则，再按页面能力启用。进入站内分账审批时，核对申请是否匹配有效规则、金额与授权范围，按允许动作处理，最后查看原申请和相关商户资金明细。

分账完成应有原业务状态与账务记录相互对应。仅启用规则不能证明全部历史订单已经分账；站内余额分配也不代表已给外部账户付款。

## 规则字段与后续动作

| 项目 | 核对重点 |
| --- | --- |
| 商户与通道 | 管理员跨商户打开详情后，再核对仍为原商户、原通道 |
| 接收方类型和身份 | 按对应产品要求填写，确认机构登记结果，避免只凭显示名称 |
| 比例 / 金额 | 明确计算基数、可分余额与上限，以服务端当前允许条件为准 |
| 启用状态 | 控制其允许范围内的后续行为，保存草稿和自动执行是不同能力 |
| 返还 / 完成等动作 | 仅在原产品和页面支持时执行，并继续查询原记录 |

修改或停用规则后重新读取版本和状态，再用新业务验收。已经发起的分账按原接收人和原业务号核对，停用规则不能撤销已完成的机构分账，也不能用站内记录补写渠道状态。
