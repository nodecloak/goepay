# 结算与提现

商户维护收款资料并申请提取可结算余额，管理员审核并按授权执行原申请。结算把平台内商户资金付给约定接收账户，需要分别看申请、审批、出款和账务结果。

## 从哪里进入

| 任务 | 管理员入口 | 商户入口 |
| --- | --- | --- |
| 查询和审核申请 | 结算管理 → 结算管理 `/admin/settle/list` | 结算管理 → 结算记录 `/merchant/settle/list` |
| 维护接收账户 | 在原申请核对收款资料快照 | 结算管理 → 结算设置 `/merchant/settle/settings` |
| 手动申请 | 处理商户已提交的申请 | 结算管理 → 申请提现 `/merchant/settle/apply` |
| 批量结算 | 结算管理 → 批量结算 `/admin/settle/batch` | 在自己的结算记录核对结果 |
| 自动结算 | 结算管理 → 结算计划 `/admin/settle/plans`，超级管理员 | 账户中心 → 自动结算参与设置 `/merchant/account/settlement-schedule` |

## 从收款资料到到账核对

1. **商户本人保存接收资料。** 选择已开放方式，填写账号、姓名和所需银行 / 应用资料。微信需核对 OpenID 所属 AppID。保存后重新读取脱敏资料和有效状态；普通联系手机号不能代替收款身份。
2. **商户查看申请条件和报价。** 在申请提现中核对可用余额、结算周期、最低金额、当日次数、预留、手续费和预计到账净额。冻结收入不属于随时可提现余额。
3. **提交原申请。** 核对申请总额、手续费、净额及收款资料后提交一次，记录申请号。此时创建申请并预占相应资金，尚未实际付款。
4. **管理员审核。** 在结算管理按申请号及商户查找，检查原资料快照、金额、余额与政策，按允许动作核准或拒绝。**审批通过不等于已经付款。**
5. **准备并执行原出款。** 核准后仍需匹配原收款快照的出款通道、独立资金预占及执行权限。准备成功表示尚未发送；管理员核对收款人和金额，完成本人资金确认后执行。
6. **共同核对结果。** 在原申请查看出款状态和原转账号，确认机构结果与资金明细一致。银行卡场景还需按原记录核对退票，不能仅依据一次处理中或受理提示判断最终到账。

## 关键金额与状态

| 项目 | 正确理解 |
| --- | --- |
| 申请总额 / 手续费 / 净额 | 总额等于手续费加净额；付款金额及扣账范围需分别核对 |
| 原收款资料快照 | 申请绑定的接收身份；当前资料修改不能替换历史申请快照 |
| 待审核 / 已核准 / 已拒绝 | 申请审批状态，不能单独证明机构付款结果 |
| 已准备、尚未发送 | 已建立出款关联，仍需执行；只在允许时取消未发送出款 |
| 处理中 / 结果待核实 | 原出款仍在核对，资金归属保留，只查询原业务 |
| 已核实成功 / 明确失败 | 按原结果结转或释放允许释放的预占，并核对资金明细 |

## 批量与自动结算怎么落地

批量结算先选规则和范围，准备后逐项核对商户、总额、费用与接收身份，再执行允许的项目。批次创建成功不表示全批完成；查看每项成功、失败、待处理或未知结果。取消剩余项不能撤回已发送或完成的付款。

自动结算需要管理员配置有效计划、商户明确参与、有效收款资料以及对应执行授权。先核对计划金额、次数、期限和参与对象，再由商户选择当前资料并保存参与状态。单独打开系统结算开关，或商户勾选参与，都不等于具备完整自动出款授权。

## 失败、修改账户与未知结果

明确拒绝或失败按原流程释放允许释放的预占；结果未知继续查询原申请绑定的原出款，不能先释放再转一笔替代款。人工确认完成需有实际付款证据。修改账户、退出计划或计划到期影响后续创建，既有申请仍按原资料、原资金来源处理。

保证金退还使用独立的保证金申请与审批，不作为普通提现操作。详见[会员与保证金](../merchant/services.md)和[管理员保证金审批](../admin/settlements.md#保证金审批)。
