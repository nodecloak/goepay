# 代付、批量付款与站内转账

管理员或获准商户使用独立付款能力向外部账户付款；站内转账只移动平台内商户余额。先选择业务类型，再填写接收身份，避免把收款权限当作出款授权。

## 从哪里进入

| 任务 | 管理员入口 | 商户入口 |
| --- | --- | --- |
| 单笔付款及记录 | 转账付款 → 付款记录 `/admin/transfer/list` | 代付管理 → 单笔付款 `/merchant/transfer` |
| 批量付款 | 转账付款 → 批量付款 `/admin/transfer/batches` | 代付管理 → 批量付款 `/merchant/transfer/batches`，按开放条件显示 |
| 创建红包 | 转账付款 → 创建红包 `/admin/transfer/red` | 代付管理 → 创建红包 `/merchant/transfer/red` |
| 站内转账 | 商户管理 → 站内转账 `/admin/merchant/internal-transfer` | 账户中心 → 站内转账 `/merchant/account/internal-transfer` |
| 统计与账务 | 转账付款下的付款账号、通道、商户代付统计 | 资金明细 `/merchant/record`，核对本人资金 |

## 先区分四种业务

| 目的 | 选择的流程 | 核对对象 |
| --- | --- | --- |
| 向外部支付宝、微信或银行账户付款 | 单笔 / 批量代付 | 原转账号、机构结果和资金归属 |
| 将结算余额付给约定账户 | [结算](./settlements.md) | 原结算申请及绑定的出款 |
| 向领取人发放红包 | 红包创建、领取与原付款核对 | 红包号、锁定领取身份、原转账 |
| 平台内商户互转余额 | 站内转账 | 来源和目标商户、双方资金明细 |

## 完成一笔外部付款

1. 在付款页面读取当前允许方式、通道、费用和资金条件。平台开关、商户独立付款授权、可执行通道和可用余额都需满足；公共默认收款池不提供这些权限。
2. 选择实际允许的付款方式和通道，填写收款账户、姓名、金额及所需应用或银行资料。微信接收身份需与应用匹配；银行产品还要核对该产品要求的银行信息。
3. 核对本金、费用、总扣减、余额、通道限额和确认页收款人。默认路由关闭、手动和可执行通道是不同设置，没有有效默认时不要自行选择列表首项代替授权。
4. 完成本人资金确认，提交一次并保存原业务号。进入原付款记录查看处理结果。
5. 区分待收款人确认、处理中、已核实成功、明确失败和未知；确认完成后对照关联资金明细。结果未知时只查询原转账，不换业务号再付同额款。

## 批量付款与红包

准备批次时逐行检查账号、姓名、金额和方式，再核对总笔数、合计、费用及通道。准备后读取服务端批次，确认项目无误再执行。逐项处理结果，不能把部分成功的批次整批再次导入。取消只影响允许取消的未发送剩余项。

红包创建前确认通道支持完整领取授权，核对金额、数量、期限及页面领取条件。记录创建成功不表示领取人到账。领取身份一旦锁定，使用原领取状态继续核对；不能换另一个账户替代原身份。历史领取或转账查询不需要为此重新开放全站新出款。

## 站内转账的核对步骤

先核对来源商户和目标商户号，不仅看名称；填写金额，读取费用和可用余额后确认。提交后以原业务号查看双方对应流水，确认一方扣减与另一方入账的关系。站内余额到账不会生成外部银行卡或支付机构付款事实。

看不到入口时检查当前商户功能开关、独立付款授权和有效组政策；已有原业务继续按页面允许能力查询。费用政策不可读取时，不把缺失费率解释成免费，也不把账面余额直接当作可付款金额。
