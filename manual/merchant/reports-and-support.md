# 统计、投诉与进件

按功能阅读[统计与对账](../modules/reports.md)及[进件、风控与投诉](../modules/risk-onboarding.md)；本页说明商户自己的数据和处理范围。

## 交易统计与资金明细

**交易管理 → 每日交易统计 / 地区数据统计**查看自身交易分布；**资金明细** `/merchant/record`核对余额、冻结和费用。

选择一致的日期、状态和支付方式，再比较汇总。交易时间、结算时间及流水时间不一定相同；未知地区不会自动归到某省。导出文件只包含本人权限范围，仍应妥善保管。

## 处理交易投诉

**交易投诉**，路径 `/merchant/complain`。按订单、时间或状态找到记录，查看主题、内容、金额和处理进度，按当前开放能力提交资料或回复。

处理前核对原订单是否已支付、是否有退款。修改本地工单或回复不等于机构投诉已经关闭；需要退款时从原订单进入，不在投诉描述中写一句“已退”代替资金流程。

## 商户进件

**商户进件 → 进件商户管理 / 新增商户进件 / 商户管控记录**。

当前通用表单用于本地资料与人工审核。创建申请时填写经营名称、联系人、联系电话、进件渠道 ID 和备注等页面字段，保存后从原记录提交本地审核。查看原申请的处理历史，待补充时更正原资料再提交；本地“已通过”不表示支付机构已经批准入网。

确需机构进件时，先由运营方确认实际开放的产品、适配流程和机构资料要求。未接入的外部分支可能只有本地资料或不可用提示，本地保存、提交和人工通过都不会自动获得机构资格。真实获批后仍需核对子商户号、产品与通道绑定。

## 联系运营方时提供什么

提供商户号、平台订单号 / 商户订单号、原退款或结算号、发生时间、页面错误及已核对步骤。隐藏私钥、密钥、验证码、证件号码和完整收款账号；不要要求对方索取你的登录密码代查。
