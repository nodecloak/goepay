# 订单管理与异常处理

按功能从[收款与订单](../modules/transactions.md)开始，了解支付时序和跨角色处理步骤。

**入口：交易管理 → 订单管理**，路径 `/admin/trade/order`。

## 查到正确的订单

先按平台订单号或商户订单号查询；有多商户同号可能时同时加商户号。核对订单金额、实付金额、支付方式、实际通道、上游交易号、支付时间及通知状态，再打开详情或更多操作。

列表筛选与详情侧重不同信息。导出前核对当前时间、状态、商户和方式条件，不把列表当前页当成全部数据。

## 不同状态的更多操作

| 订单情况 | 可能出现的动作 | 操作前必须知道 |
| --- | --- | --- |
| 未支付 | 改已完成、手动补单、删除订单 | 手动改状态不等于支付机构真的扣款 |
| 已支付且未全退 | 改未完成、API退款、手动退款、冻结订单、重新通知、删除订单 | 退款、冻结与通知是不同动作 |
| 收入冻结 | 解冻订单、API退款、重新通知、删除订单 | 必须核对原冻结来源及可用额度 |
| 已全额退款等状态 | 按当前记录显示改状态、API退款或通知等入口 | 按钮显示不表示还有可退金额，执行仍由服务端校验 |
| 已归档 | 恢复订单 | 恢复展示不重新支付或入账 |
| 原退款结果未核实 | 核对原退款 | 恢复原请求，不新建替代退款 |

按钮会随权限、状态和原业务证据变化；不要把这张表当作强制执行权限。

## 手动补单

用户说已付款但本地仍未支付时，先查看机构侧证据与原单身份，再使用允许的手动补单 / 查询。系统查询原通道结果后确认，不应再向另一个通道创建订单。查询没有确认成功时，不用“改已完成”冒充验签回调。

## 改已完成与改未完成

这两项是管理操作，不是上游扣款或退款。操作前阅读确认框说明，保留原因并核对真实支付、退款、商户通知和资金明细。不要用来修补无法解释的账务差额。

## 冻结与解冻

冻结限制的是该订单收入的使用，原交易仍可能已支付。先核对订单、金额、商户和原因；解冻针对原冻结周期操作。资金确认开启时，按当前动作完成本人授权，操作后检查资金明细。

## 重新通知

平台已支付而商户业务系统未更新时，先核对商户通知地址与返回结果，再按权限重新通知。它不会再次向用户扣款。通知可能有冷却与次数限制，商户系统仍须验签和幂等处理。

## 删除与恢复

删除用于后台归档，不抹除原支付、退款和账务事实。需要恢复展示时使用对应归档筛选与恢复入口；不要靠删除重建来处理支付争议。

## 批量操作与预授权订单

批量处理前检查筛选范围、已选订单数及每条状态；预览、确认和实际执行结果分别查看。部分成功或结果未知时，按原批次逐条核对，不整批重新发起。

订单详情若提供预授权区域，应分别查看授权冻结、扣款和撤销结果。授权冻结不是普通收款已支付；扣款与撤销只能按服务端当前允许的动作及本人资金确认执行。任何未知结果先查原授权或原扣款，不另建一个普通支付或退款来替代。
