# 结算、批量结算与计划

按功能从[结算与提现](../modules/settlements.md)开始，查看商户申请和管理员执行如何衔接。

| 入口 | 路径 | 用途 |
| --- | --- | --- |
| 结算管理 | `/admin/settle/list` | 查看并处理结算申请 |
| 批量结算 | `/admin/settle/batch` | 按条件准备和核对结算批次 |
| 结算计划 | `/admin/settle/plans` | 管理有明确参与和授权范围的周期计划 |

## 处理一笔结算

1. 查看商户、申请金额、费用、可用余额及原收款资料版本。
2. 核对结算周期、最低金额、预留和方式限制。
3. 根据页面提供的动作审批、拒绝或执行。**审批通过不等于已经付款。**
4. 执行需要本人资金确认时，核对收款人、金额和原申请后授权。
5. 跟踪原业务状态，确认付款结果与资金明细一致。

## 批量结算

先按规则准备批次，查看每个商户的金额、费用和接收账户。准备批次不是全批次已经成功付款；逐项查看成功、失败、待处理或结果未知的记录。

取消仅取消当前允许取消的剩余项，不撤回已经完成的付款。导出批次用于核对，不用修改导出文件伪造完成状态。

## 结算计划如何生效

自动结算需要管理员明确配置计划、商户明确选择并参与、有效收款资料及相应执行授权。计划金额、次数、期限等边界应在授权前核对。单独开启系统设置中的结算开关，不等于已经授权所有自动出款。

修改、到期或撤销计划影响后续创建；已预留的原申请仍按其原来源核对。新增参与商户、切换收款账户或修改规则后，应重新确认当前授权范围。

## 拒绝、失败与未知

拒绝或明确失败按原流程释放允许释放的预占。上游结果未知时继续查询原申请，不能先释放余额再做另一笔付款。人工确认完成必须有实际付款证据，不能仅凭审批通过操作。

## 保证金审批

**商户管理 → 保证金审批**，路径 `/admin/merchant/deposit-review`。按商户和申请定位原记录，检查已缴、要求、可退、观察窗口及业务限制，按页面允许的审批动作确认或拒绝。审批后核对原保证金记录与资金明细，不把保证金审批当成普通结算或任意余额调整。
