# 退款处理与原单核对

按功能从[退款与售后退还](../modules/refunds.md)开始；本页说明管理员退款操作。

**入口：订单管理中的退款动作；交易管理 → 退款记录**，路径 `/admin/trade/refund`。

## 先选对处理方式

| 动作 | 用途 |
| --- | --- |
| API退款 | 按原支付通道向服务商申请退款，并跟踪原退款结果 |
| 手动退款 | 线下已完成实际退还后，由超级管理员本人按权限记录平台退款与账务；不调用支付机构退款接口 |
| 核对原退款 | 当提交结果未知或流程中断时读取、恢复原退款，不改变原退款号 |

手动退款要求先有已完成线下退还的事实与证据，再按当前确认框记录平台业务。它不会替你把款项退给用户，**不能仅因 API 退款慢，就再做一次手动退款**。

## 发起 API 退款

1. 在订单详情核对支付身份、原通道、实付、已退及剩余可退金额。
2. 选择 API 退款，填写本次退款金额与必要原因。
3. 确认目标商户和原订单；按要求完成资金密码 / TOTP。
4. 提交一次，记录退款号和页面结果。
5. 到退款记录查看原退款，核对状态、完成时间和资金变化。

## 读懂退款记录

退款号与商户退款号用来定位请求；关联订单用于回到支付事实；退款金额、扣减金额、申请时间和完成时间需要分别看。只有服务器确认的完成结果才表示退款成功，不用记录创建时间代替完成时间。

部分退款要结合累计已退金额核对。剩余可退金额以被核实的实际付款及既有退款为基础，不按当前通道费率重新猜算。

## 网络中断后

保留原订单和原退款号，进入“核对原退款”或原退款查询。未知状态下不换退款号、不换通道、不新建同金额退款。确认失败与确认成功之前，预占资金可能仍然保留，不能手工释放后再次退款。

退款记录属于业务事实，不提供任意新增、编辑金额或删除来“整理历史”。
