# 管理员首次开通

按功能从[商户与用户组](../modules/merchant-management.md)开始；本页串联管理员首次开通与交付验收。

目标：开通一个能登录、能看到正确通道与费率、能完成模拟收款的商户。首次开通建议使用超级管理员本人会话。

## 1. 检查站点基本资料

进入 **系统管理 → 系统设置 → 网站信息**，核对站点名称、联系信息和首页设置。确认登录地址、收银台地址及对接文档使用同一个预期站点。先完善[账户安全](../concepts/security.md)，再配置业务。

## 2. 准备支付通道

进入 **支付接口 → 支付通道**，添加或编辑已开通的支付宝、微信等通道。填写对应产品和服务商凭据，保存后重新读取，核对状态及支付方式。

随后进入 **支付方式**，确认需要的方式已开启，设备范围正确。方式有图标和名称不代表支付产品已经开通。详细步骤见[通道配置](./channels.md)。

## 3. 配置用户组

进入 **商户管理 → 用户组设置**。新增或编辑商户将使用的用户组，逐项选择支付宝、微信等支付方式的通道策略与分成比例。

**新建用户组的支付方式可能默认关闭，必须明确配置。** 如果选“继承”，还要确认部署已设置公共默认收款通道。公共通道池由部署管理员维护，新增商户不会自动获得所有通道或出款权限。见[默认通道与费率](./groups.md)。

## 4. 创建商户账号

进入 **商户管理 → 商户列表 → 新增商户**，选择商户账号方式，填写手机号或邮箱、登录密码和用户组；按业务需要补充结算资料和手续费扣除模式。

创建后记录商户号，通过安全方式交付登录信息。不要把后台密码当作 API 密钥。具体字段见[新增商户](./merchants.md)。

## 5. 商户本人核对

让商户从 `/merchant/login` 本人登录，检查：

- 商户号与目标一致，账号及收款状态正常。
- **支付通道**页展示预期方式、通道与费率。
- **API 信息**页能取得当前接入资料。
- 有需要时完成实名认证、授权域名及结算设置。

## 6. 串联模拟业务

在独立模拟环境依次验证：签名下单 → 收银台 → 模拟支付机构回调 → 订单已支付 → 资金明细 → 商户通知。再测试一次退款与一次结算审批，分别检查状态与资金记录。

## 开通检查表

| 项目 | 应看到的结果 |
| --- | --- |
| 通道与方式 | 通道配置有效，目标支付方式开放 |
| 用户组 | 各方式的路由、分成比例明确，未意外关闭 |
| 商户 | 已分配正确用户组，登录与收款状态符合业务要求 |
| 商户本人登录 | 正确身份、正确通道与费率，敏感资料可按权限操作 |
| 支付回调 | 订单只确认一次，实际金额与订单一致 |
| 商户通知 | 商户业务系统验签并完成幂等处理 |
| 售后与结算 | 可用、冻结、退款及结算记录能够对应 |

正式接入前由运营方按服务商规则安排验收。不要在生产后台把“测试”按钮、API 退款或付款作为纯查看操作。
