# 渠道分账与站内分账

按功能从[渠道分账与站内分账](../modules/profitsharing.md)开始，查看规则、执行与结果核对的完整路径。

| 入口 | 路径 | 处理范围 |
| --- | --- | --- |
| 分账规则 | `/admin/profitsharing/receiver` | 渠道分账接收人与规则总览 |
| 分账记录 | `/admin/profitsharing/order` | 跨商户查询原渠道分账 |
| 站内分账规则 | `/admin/profitsharing/internal` | 平台内部余额分配规则 |
| 站内分账审批 | `/admin/profitsharing/internal-orders` | 对应申请及执行记录 |

## 先分清是哪一种分账

**渠道分账**由支持分账的支付机构按该产品执行，通常涉及原订单、通道、接收方身份及产品开通。

**站内分账**是在 GOEPAY 内部按已授权规则处理商户余额，不代表支付机构已经给外部收款人打款。不要用一种记录补写另一种业务的状态。

## 管理渠道分账规则

1. 用商户号和通道筛选，确认当前操作对象。
2. 查看接收方身份、规则、启用状态和授权范围。
3. 按页面要求新增或编辑草稿，保存后重新读取核对。
4. 上游要求接收方登记或关系确认时，完成相应流程；只有本地草稿不代表已获机构授权。
5. 对具体订单发起允许的分账动作后，在原分账记录中跟踪结果。

## 跨商户总览怎么查

先锁定商户，再按通道、订单、接收方、状态或时间筛选。查看详情、查询或后续操作时，确认详情仍显示原商户与原通道，避免在另一商户上下文中处理同号业务。

## 修改与恢复

规则修改只按其生效范围影响后续行为。已经发起的分账按原接收人、原业务号和原账户核对，结果未知时不创建替代分账。完成分账、返还等动作只在产品和页面明确支持时操作。

自动分账与只保存规则是不同能力；不要把“已启用规则”解释为已对全部历史订单执行。
