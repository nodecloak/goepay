# 公告、管理员、日志与维护

按功能阅读[系统配置与维护](../modules/system.md)、[账号安全](../modules/account-security.md)和[消息与公告](../modules/notifications.md)，再查本页具体工具。

## 公告配置

**系统管理 → 公告配置**，路径 `/admin/system/anounce`。

新增公告时填写标题、正文、排序与颜色等页面字段，预览后保存。通过显示 / 隐藏控制发布范围，编辑后刷新核对。删除前确认目标公告，取消不会提交。

公告列表发布与系统设置中的商户弹窗、注册公告、页脚文案是不同入口，需要分别维护。

## 管理员列表

**系统管理 → 管理员列表**，路径 `/admin/system/admin-user`。

1. 新增管理员账号，填写用户名、显示名称和安全的登录资料。
2. 选择超级管理员或受限管理员；受限管理员按菜单分配权限。
3. 保存后用新账号本人登录，检查可见菜单及被禁止的操作。
4. 调整权限、停用或删除时先确认目标账号；权限撤销可能使既有会话失效。

登录密码、资金密码与 TOTP 是不同资料；资金密码及 TOTP 由本人在相应安全流程设置，不用一个空开关表示“已绑定”。

## 计划任务

**系统管理 → 计划任务**，路径 `/admin/system/cron`。

先阅读任务业务说明，设置开关、执行时间、周期 / 间隔和参数。一次性与周期任务的时间含义不同，保存后核对下次运行时间。

人工安排后显示待执行，**不等于任务已完成**。查看真实运行状态、结果与日志；保存调度规则不额外授予自动付款、退款或消息发送权限。

## 登录日志与运行日志

| 页面 | 查询内容 |
| --- | --- |
| 登录日志 `/admin/system/log` | 账号 / 商户、操作类型、来源 IP、时间等已有审计信息 |
| 运行日志 `/admin/system/runtime-log` | 指定日期的事件类型、内容及原运行记录 |

按目标和时间缩小范围后查看。运行日志清除会按页面规则归档旧记录，不代表支付、登录和财务审计被删除；没有记录的地区或方式不应推断补写。

## 数据清理

**系统管理 → 数据清理**，路径 `/admin/system/clean`。

1. 选择允许的截止时间或快捷预览。
2. 先查看预计影响的登录日志、过期会话、尝试计数、限流记录等数量。
3. 核对后确认一次，查看实际结果。
4. 结果未知或预览损坏时，重新预览和核对原操作，不反复提交删除。

财务订单、退款、结算、账本、付款和分账事实不通过此页随意删除。运行日志归档与登录数据清理也不是同一项操作。

## 系统更新

**系统管理 → 系统更新**，路径 `/admin/system/update`。

读取当前版本、更新来源和最新状态。配置可信更新来源后，可按权限准备更新包；**“准备完成”不等于程序已经更新部署**。实际程序切换由部署流程执行，维护前备份数据库、配置及主密钥。

不要用恢复旧数据库的方式撤销已有真实支付。未配置更新来源时，应按实际状态处理，不能把空列表理解成已完成在线升级。
