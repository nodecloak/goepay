# 易支付迁移向导

按功能从[从易支付迁移到 GOEPAY](../modules/migration.md)开始，先确认来源、目标与迁移后重新配置范围。

**入口：系统管理 → 易支付迁移**，路径 `/admin/system/migration`。仅超级管理员本人可执行，目标必须是符合检查要求的全新安装。

## 迁移前准备

在原系统暂停写入并取得一致的 MySQL SQL 备份，妥善离线保存。目标先初始化管理员，不能先创建演示商户、订单或资金业务。准备好 GOEPAY 数据库及原主密钥的备份方案。

## 按向导操作

1. 上传向导支持的 SQL 文件，文件上限 64 MiB；选择实际来源版本。
2. 运行预检查，阅读原生导入、仅归档和阻塞项。
3. 核对商户 / 订单数量、余额与转换范围。存在阻塞项时先解决，不手工篡改原余额或状态绕过检查。
4. 通过后按页面要求确认并执行原任务。
5. 网络结果未知时重新读取原任务，不再次上传执行一个相同迁移。
6. 查看完成报告，核对导入数量、期初余额和账务结果。

## 会迁移什么

| 数据 | 处理方式 |
| --- | --- |
| 可映射商户、可用余额、普通历史订单 | 原生导入；期初余额建账，历史已支付订单不再入账或补发通知 |
| 有明确成功证据的历史退款 | 导入只读历史，不产生新的可执行退款 |
| 完整源备份及未转换字段 | 加密归档；归档不等于成为新系统可执行配置 |
| 旧用户组、通道、站点设置、密码、API 密钥、插件及实名资料等 | 不自动成为有效配置或授权，需要重新核实和配置 |

导入商户保持停用并使用新的随机接入凭据。旧明文或弱密码不会直接成为新登录密码，旧通道也不会自动开始收款。

## 哪些情况会阻塞

目标已有业务数据；金额精度或状态无法可靠映射；存在未决退款 / 付款 / 结算、冻结或保证金义务；孤立记录、重复业务号、不支持语句或备份不完整。以预检查报告为准。

## 导入后仍要完成

重新配置用户组、通道、商户登录资料与必要服务，核对余额和历史记录，逐个启用商户并做模拟验收。向导不会替你切域名、修改原数据库、发起付款或启用资金任务。

准备任务过期不代表加密备份被自动删除。保管好数据库与原主密钥；丢失密钥后加密归档无法正常读取。
