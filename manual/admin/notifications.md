# 消息、短信、机器人与打印

按功能从[业务通知、消息提醒与打印](../modules/notifications.md)开始，区分商户后端通知、人工提醒和设备投递。

**入口：系统管理 → 系统设置 → 消息提醒 / 短信配置 / 邮箱配置**。商户消息及打印另有独立入口。

## 按顺序配置

**服务凭据 → 接收人或绑定 → 模板 / 事件 → 开启渠道 → 重新读取核对。** 管理员接收平台消息与商户接收自身事件分别配置，不要混用收件人。

## 各渠道需要什么

| 渠道 | 必要资料 | 重点检查 |
| --- | --- | --- |
| 邮件 | 可用 SMTP 账户、发件资料、接收邮箱 | 已配置账户启用，收件目标明确 |
| 微信模板 | 正确公众号 / 应用、模板 ID、模板字段与接收身份 | 模板及字段完整，应用身份一致 |
| 群机器人 | 平台支持的机器人类型、Webhook 等凭据 | URL 中可能含密钥，不复制到公开文档 |
| Telegram | 有效 Bot Token 及对应接收目标 | 若选择复用快捷登录 Token，确认是同一可信机器人 |
| QQ 机器人 | AppID / AppSecret 等所需凭据及有效绑定 | 保存凭据与开始绑定是两个动作 |
| 业务短信 | 已配置网关、事件专用模板、已验证手机 | 不用普通联系电话冒充已绑定接收人 |
| 云喇叭 | `agent_id`、`agent_secret`，对应设备及开放条件 | 缺少完整凭据不能只打开开关 |
| 小票打印 | 平台 APPID、APPSECRET；商户打印机序列号等 | 平台配置、商户设备与实际执行条件都满足 |

## 配置业务短信

余额不足、交易投诉和会员到期使用各自的业务模板，**不覆盖登录验证码模板**。

1. 在短信配置选择有效网关，填写该事件对应模板。
2. 开放商户短信渠道和目标业务事件。
3. 商户通过可信绑定流程维护接收手机，或使用已验证注册手机。
4. 管理员投诉短信另行填写明确接收手机；不要求先保存一个无关群机器人。
5. 保存后核对模板、事件和接收渠道状态。

测试发送会联系服务商，可能产生短信费用。培训使用模拟环境，不用真实手机号验证表单。

## 编辑和绑定管理员机器人

以 QQ 为例：先保存有效凭据，再点击开始绑定。绑定码仅在当前页面短期有效，按提示完成机构侧绑定，然后读取状态确认。取消绑定、解绑和替换凭据是不同动作；替换凭据会使旧绑定失效。

绑定过程结果未知时先读取当前绑定状态，不重新创建一轮绑定。不要把绑定码、Token 或带密钥的 Webhook 放进链接、截图和浏览器收藏。

## 配置云喇叭和小票

这些区块有独立凭据及保存边界，**点击普通设置保存不表示硬件配置已保存**。

保存平台云喇叭 / 打印配置后，再检查商户的消息提醒、设备序列号、份数和订单范围。当前页面关闭期间不应被解释成已播报或已打印；排队、受理、结果未知和完成要分别看。

## 没有收到提醒时

依次查业务是否真的发生 → 平台渠道与事件开关 → 商户个人设置 → 可信接收身份 → 模板 / 凭据完整性 → 原任务结果。短信、机器人和打印失败，不等于原支付失败；不要因此要求用户再付一次。
