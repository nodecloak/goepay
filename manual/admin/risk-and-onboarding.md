# 风控、投诉与进件

按功能从[进件、风控与投诉](../modules/risk-onboarding.md)开始；本页补充管理员的具体入口与处理要求。

## 风控与黑名单

**交易管理 → 黑名单管理**维护明确的限制项；**其他功能 → 风控记录**查看被拦截或需要核查的交易。

处理步骤：

1. 按商户、订单、时间和风险类型查到原记录。
2. 核对命中的字段、规则、次数与实际交易，不仅看用户口头说明。
3. 新增或调整黑名单时选择页面支持的类型，准确填写目标及原因。
4. 保存后重新读取，确认作用范围；解除限制前再次核对原因。
5. 对拦截后的原订单查单，不用重新下单来验证是否重复扣款。

频率、金额、商品名称及人机验证等政策在 **系统设置 → 风控检测 / 支付相关**维护。名单与规则修改不会撤回已经发生的支付。

## 投诉处理

| 入口 | 用途 |
| --- | --- |
| 交易投诉 → 投诉记录 | 查看商户、关联订单、金额、主题与处理进度 |
| 投诉统计 | 按当前条件了解投诉分布 |
| 同步任务 | 管理已接入上游的同步安排与运行状态 |

先核对原投诉、支付订单和实际退款，再记录处理意见。**修改投诉状态不等于已退款，保存本地回复也不一定已向机构发送。** 需要退款时从原订单走退款流程。

上游同步、自动回复或处罚必须有实际接入的插件和授权。未接入时只使用本地工单能力，不把本地“已处理”当作机构投诉已经关闭。

## 商户进件

进件渠道配置、进件商户管理、子通道管理和商户管控记录分别用于资料渠道、本地申请、子商户绑定及风险记录。通用资料流程保存本地草稿和人工审核状态，不自动向机构提交进件。

1. 配置进件资料渠道，填写名称、服务商与资料表单 JSON，保存后核对启用状态。
2. 在目标商户下创建申请草稿，填写经营名称、联系人、联系电话、渠道 ID 与备注等当前表单要求的资料。
3. 提交原记录进入本地审核，查看处理历史和意见。
4. 按允许动作标记待补充、通过或驳回。待补充时修改原草稿后再提交；本地“通过”不能代替机构审核结果。
5. 需要机构入网时，另行确认实际接入的产品、适配器及授权流程。取得真实上游资格后，再核对子商户号、产品、通道绑定和可用范围。

部分外部进件插件尚未接入。页面标为不可用时，不通过配置一个同名通道来绕过。子通道资料保存、启用和机构实际可交易资格应分别核验。

## 获取用户标识

**其他功能 → 获取用户标识**用于已配置应用的授权身份流程。标识必须与原应用 / AppID 对应，不把某个应用的 OpenID 填给另一应用的收款或结算。外部授权未开放时，由运营方先完成应用与回调配置。
