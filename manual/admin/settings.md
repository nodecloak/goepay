# 系统设置各分类

按功能从[系统配置、应用与维护](../modules/system.md)开始；认证、消息、结算等设置也在相应业务模块串联说明。

**入口：系统管理 → 系统设置**，路径 `/admin/system/settings`。页面按业务分类；普通设置、加密凭据和硬件区块可能有各自的保存按钮。

## 修改一项设置

1. 进入对应分类，先读取当前值，区分“未配置”“关闭”和已有脱敏凭据。
2. 只修改本次需要的项目，核对单位：元、天、百分比或次数。
3. 使用该区块的保存按钮。普通设置的保存不一定覆盖旁边的机器人或硬件凭据。
4. 看到成功提示后重新读取，确认值和开关都已保存。
5. 结果未知时先核对；版本冲突时重新读取并比较草稿。

## 全部分类速查

| 分类 | 主要内容 | 操作要点 |
| --- | --- | --- |
| 网站信息 | 名称、标题、联系信息、首页、品牌与验证码 | 公开内容先预览，地址使用本部署域名 |
| 商户相关 | 注册、验证、充值、聚合码、域名、自助退款、保证金 | 最低保证金是持续要求，不能当成单次充值下限 |
| 支付相关 | 金额、商品限制、通知失败处理、收银台与费用政策 | 修改后核对新订单；原订单保留原业务材料 |
| 交易投诉 | 投诉开放、本地处理及同步入口 | 上游自动化依赖已接入业务插件 |
| 风控检测 | 频率、金额、人机验证、黑名单及防御政策 | 分清平台规则与用户组覆盖 |
| 结算规则 | 开关、周期、金额、费用、方式 | 自动出款还需要独立计划和授权 |
| 转账付款 | 方式限制、默认路由与相关规则 | 关闭、手动、可执行通道的含义不同 |
| 快捷登录 | OAuth 应用、加密凭据与中转 | 登录应用身份不能随意替换支付应用身份 |
| 消息提醒 | 管理员接收、商户渠道、事件、微信模板、云喇叭与打印 | 先配完整凭据，再启用渠道；见[通知配置](./notifications.md) |
| 实名认证 | 认证方式、服务商、费用及强制要求 | 需要已开通的产品与凭据；见[认证配置](./certification.md) |
| OCR配置 | 阿里云 / 百度云识别凭据和开关 | OCR 识别不直接认证商户 |
| 公告排版 | 商户弹窗、注册公告、页脚 | 文案预览与公告列表发布不是同一个配置 |
| 邮箱配置 | 邮件账户与验证码频率 | 密码使用专门的保留 / 替换 / 清除操作 |
| 短信配置 | 网关、验证码及业务模板 | 业务短信不能复用验证码模板；发送测试可能计费 |
| IP地址 | 应用看到的来源及代理规则说明 | 来源信任与 IP 归属地显示是不同配置 |
| 中转代理 | 地址、协议、账户与加密密码 | 核对协议、目标和执行状态；不在不确定时反复连测 |
| 高级设置 | 当前实现提供的高级运营配置及部署说明 | 后台路径、缓存驱动等部署事项不由无效的表单字段改变 |

## 为什么开关开了仍不可用

开关只控制其中一个条件。通道或服务商权限、执行开关、接收人绑定、模板完整性、商户本人授权和用户组条件仍须满足。页面明确显示“不可用”“未接入”时，先解决缺失条件，不要反复保存同一个开关。

## 清空和保留的区别

需要清除的文本按页面允许的清空流程保存；密钥则使用明确的“清除原值”。留空、占位符和保留已有值不是同一件事。配置修改只作用于其允许范围，不能让新凭据接管已发出的历史业务。

## 邀请返现政策

独立入口 `/admin/system/referral-policies`。新增前核对页面提供的奖励来源、计算口径、条件、期限与预算边界，填写后先检查草稿，再按权限确认生效。编辑或撤销后刷新核对版本及状态；已产生奖励按其原记录核对，不把新规则回填成历史收益。

## 订单名称限制策略

独立入口 `/admin/system/order-subject-policies`。为明确的订单名称规则填写条件、适用范围和提示，保存后在模拟环境验证命中与不命中两类订单，再按允许流程启用。更改策略后查看新请求的实际提示；历史订单仍按原单处理。
