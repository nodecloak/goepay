Go SDK 与接入示例

本项目提供标准库实现的 Go SDK 源码，支持 V2 支付请求签名、API 回包验签及通知验证。

Go SDK 下载

下载 GoEPay_Go_SDK.zip。包含 Go 源码、go.mod、本地测试、README 和不发送真实请求的示例；无需第三方依赖。包内 go.mod声明 Go 1.22，本轮使用 Go 1.27.3 进行测试。

方法用途执行行为
SubmitURL构造 api/pay/submit签名跳转地址仅本地构造，不发送 HTTP
Create / Query统一下单 / 查询订单带 context 的表单 POST，验证签名回包
Refund / RefundQuery / Close申请退款 / 查询退款 / 关闭订单显式调用时发送，SDK 不自动重试
VerifyNotification验证 V2 回调的签名、时间窗及商户离线验证，不替代业务订单与金额核对及幂等处理

本 Go SDK 面向上述六个 V2 支付路径，要求顶层标量响应，遇数组或对象拒绝处理。商户订单列表、转账、V1、V1 MD5 通知不在其包装范围；这些接口可按对应协议自行对接，不应直接套用本客户端。

本地模块接入

下载包是源码交付，未声称已发布到公共模块仓库。将压缩包内的 GoEPay_Go_SDK目录放到项目 third_party/goepay-sdk，使用本地 replace。下面的保留示例模块名与包内 go.mod一致，v0.0.0仅用于本地模块引用：

go mod edit -replace=example.com/goepay-sdk=./third_party/goepay-sdk
go mod edit -require=example.com/goepay-sdk@v0.0.0
go test ./...

先在解压目录执行 go test ./...，再运行自己的接入测试。包内测试使用本机测试 HTTP 服务和临时生成的 RSA 密钥，不依赖生产账户。

Go 配置与离线构造示例

下面只构造地址，不发送支付请求。GOEPAY_API_URL填写接口根地址 {{.API}}；商户 ID 与密钥使用自己的配置。私钥文件内容必须为合法 PEM，不放在前端或公开目录。

package main

import (
    "log"
    "net/url"
    "os"
    "strconv"

    goepay "example.com/goepay-sdk"
)

func main() {
    pid, err := strconv.ParseInt(os.Getenv("GOEPAY_MERCHANT_ID"), 10, 64)
    if err != nil {
        log.Fatal("请配置商户 ID")
    }
    privateKey, err := os.ReadFile(os.Getenv("GOEPAY_MERCHANT_PRIVATE_KEY_FILE"))
    if err != nil {
        log.Fatal("无法读取商户私钥")
    }
    publicKey, err := os.ReadFile(os.Getenv("GOEPAY_PLATFORM_PUBLIC_KEY_FILE"))
    if err != nil {
        log.Fatal("无法读取平台公钥")
    }
    client, err := goepay.New(goepay.Config{
        BaseURL: os.Getenv("GOEPAY_API_URL"),
        MerchantID: pid,
        MerchantPrivateKeyPEM: privateKey,
        PlatformPublicKeyPEM: publicKey,
    })
    if err != nil {
        log.Fatal("请检查 Go SDK 配置")
    }
    params := make(url.Values)
    params.Set("type", "alipay")
    params.Set("out_trade_no", "merchant-order-001")
    params.Set("name", "示例商品")
    params.Set("money", "1.00")
    params.Set("notify_url", "https://merchant.example.com/payments/notify")
    params.Set("return_url", "https://merchant.example.com/payments/return")
    signedURL, err := client.SubmitURL(params)
    if err != nil {
        log.Fatal("构造请求失败")
    }
    _ = signedURL // 在应用中按需使用，避免记录带签名的完整地址。
    log.Print("仅构造签名地址，不发送请求")
}

pid、timestamp、sign_type和 sign由客户端填充，不应在业务参数中重复传入。API 方法需显式传入 context.Context；发生超时、响应验签失败或结果未知时，用原业务单号查询，不能自动新建资金请求。

Go 通知处理

在 GET 通知处理器内先检查请求方法，再使用 url.ParseQuery(r.URL.RawQuery)并处理解析错误，将完整查询集合交给 VerifyNotification；不要使用会掩盖重复参数或解析错误的取值方式。验签通过后，核对本地原订单的商户、订单号、金额及 TRADE_SUCCESS状态，在事务中幂等落库。处理成功或已正确处理的重复通知才返回 HTTP 200 和精确小写正文 success，不带空格或换行。

通知签名与时间窗不能代替订单业务检查，也不能自行保证“只处理一次”。具体字段和应答规则见支付结果通知，规范见Go 服务签名规则。
