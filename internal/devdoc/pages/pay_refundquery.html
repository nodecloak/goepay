订单退款查询

Go 版接口：按原退款单号恢复和核对退款结果，处理中与最终失败有不同响应。

请求地址

{{.API}}api/pay/refundquery

请求方式

POST，UTF-8，application/x-www-form-urlencoded。除页面跳转接口外，V2 不接受 GET。

请求参数说明

参数必填说明
pid是商户 ID，正整数，以商户后台 API 信息为准。
timestamp是当前 Unix 时间戳，十进制整数秒；请求时间与服务器相差不超过 300 秒。
sign_type是固定为 RSA；不会为 V2 请求自动改用 MD5。
sign是商户私钥生成的 SHA256WithRSA / PKCS#1 v1.5 签名，标准 Base64 字符串。
out_refund_no二选一商户退款单号，非空时优先。
refund_no二选一平台退款 ID，必须是整数；在本商户范围内反查。

所有请求参数先按签名规则签名，再进行表单编码。字段只允许唯一标量值；重复键、数组形式及歧义参数名会被拒绝。

处理规则

  • 只可查询属于当前商户的退款；接口调用原通道核验结果，核验不成功时返回错误说明。
  • 尚未终态时实际返回 code=-1、msg=refund processing、两个退款号，不含 status、money、reducemoney。这不是最终失败。
  • 终态查询完成时 code=0；status=1 表示成功，status=0 表示最终失败。不要将处理中缺少 status 解读为 status=0。

返回参数说明

参数类型说明
codeNumberV2：0 表示本次接口调用完成；-1 表示错误或需要继续核对，不等于资金最终状态。
msgString按返回分支出现的说明，客户端不应依赖固定中文文案。
timestampString平台签名时的 Unix 整数秒。
sign_typeStringRSA。
signString使用平台公钥验证的签名。
refund_no / out_refund_noString平台退款 ID 及商户退款单号。
statusNumber仅终态返回：1 成功，0 失败。
money / reducemoneyString仅终态返回的退款总额及商户承担金额。

先检查 HTTP 状态和响应格式，再验证平台签名及 timestamp，最后读取业务字段。平台密钥可用时，正常业务错误也会签名；裸 HTTP 参数/方法错误或签名基础设施不可用时，响应可能没有签名，不能把它当作可信成功结果。

处理中示例

{
  "code": -1,
  "msg": "refund processing",
  "refund_no": "21701",
  "out_refund_no": "REFUND_001",
  "timestamp": "1793400000",
  "sign_type": "RSA",
  "sign": "BASE64_SIGNATURE"
}

返回示例

{
  "code": 0,
  "refund_no": "21701",
  "out_refund_no": "REFUND_001",
  "money": "0.50",
  "reducemoney": "0.50",
  "status": 1,
  "timestamp": "1793400000",
  "sign_type": "RSA",
  "sign": "BASE64_SIGNATURE"
}

示例中的编号、时间和签名仅用于说明字段；请求时生成当前时间戳和真实签名，不能直接复制示例签名。

其他说明

当前 Go 响应不包含 trade_no、out_trade_no 或退款时间 addtime；请用本地已保存的原订单与退款关系关联。
