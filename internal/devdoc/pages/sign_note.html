Go 服务 V2 签名规则

以下规则对应当前 Go 服务的实际解析及签名实现。新 Go 对接可使用Go SDK，协议为 SHA-256 + RSA PKCS#1 v1.5。商户使用商户私钥签请求，使用平台公钥验响应及 V2 通知。

请求签名步骤

  1. 请求为 UTF-8 标量字段。先将商户 ID、Unix 秒 timestamp 和 sign_type=RSA放入参数集合。每个键只允许一个值；重复参数、数组式键、包含空格或点等歧义字符的键会被服务端拒绝。
  2. 剔除 sign、sign_type 以及值为空字符串的字段。其余参数按参数名的字节顺序升序排列；仅空白字符串在请求中仍参与签名，建议不要传这类值。
  3. 使用解码后的原始值拼接 key=value，以 &连接，参数值在这一步不做 URL 编码，不修改空格、大小写或金额的小数表示。
  4. 对拼串进行 SHA-256 哈希，并使用 RSA PKCS#1 v1.5 签名。标准 Base64 编码结果写入 sign。
  5. 最后将整个参数集合按表单规则 URL 编码发送。Go 可使用 url.Values.Encode()；不要在拼串之前编码，也不要手动拼接含 +、& 或 Base64 字符的请求。

待签名字符串示例

money=1.00&name=示例商品&notify_url=https://merchant.example.com/payments/notify&out_trade_no=merchant-order-001&pid=1001&timestamp=1793404800&type=alipay

这里的 & 是拼串分隔符。时间戳仅为说明，真实请求须使用当时的时间；金额字符串 1.00不能在签名后改成 1。

时间戳

RSA 请求必须携带正十进制 Unix 秒 timestamp，与服务端时间相差不超过 300 秒，边界包含 300 秒。保持服务器时间同步；使用毫秒、负数、非数字、过期或未来过远的值都会失败。Go SDK 对已签名 API 回包及 V2 通知也执行同样的新鲜度验证。

响应及 V2 通知验签

  1. 对顶层标量字段构建参数集合。JSON 数字使用原十进制表示，字符串保持原值，布尔值 true映射为 1，false及 null映射为空串。
  2. 排除 sign、sign_type、空串和仅空白字符串；这里的空白字符为 ASCII 空格、Tab、换行、回车、NUL、垂直制表符。数组和对象不参与顶层签名。
  3. 按参数名排序并使用原始值拼串，以平台公钥进行 SHA-256 / RSA PKCS#1 v1.5 验签，要求 sign_type=RSA且时间戳在有效窗口内。
  4. 验签之后仍要核对商户、原订单、应付金额及预期状态，并通过本地事务防止重复交付。新鲜时间戳不等于业务通知未被处理过。

接口协议中的列表 data 等数组和对象不受顶层 RSA 签名覆盖，必须使用 HTTPS 保护完整传输；资金状态应按原业务单号查询并核对。本站 Go SDK 的支付客户端只接收顶层标量回包，遇到嵌套回包会拒绝，不能将它用于文档中的商户列表接口。

错误响应也需区分来源

平台签名密钥可用时，Go 服务的 V2 业务成功及业务错误 JSON 都会添加签名。错误 HTTP 方法、无法解析的表单、网关失败或签名密钥不可用等情况可能产生未签名响应；这类内容只能作为未认证的错误信息，不能据此确认支付、退款或转账结果。

Go SDK 对携带签名的错误回包同样验签，未签名错误明确返回未认证结果。网络异常、验签失败及时间戳失败都应保留原业务单号核查，不自动重新发起资金操作。

注意事项

  • RSA 密钥至少 2048 位。商户私钥保存在商户服务端，平台公钥仅用于验签，不需要平台私钥。
  • 请求的空值规则与响应的空值规则不同；使用 Go SDK 可避免混用规则。
  • 异步通知由平台以 GET 发送。若回调 URL 原有查询参数，它们也属于回调验签集合；不得预占支付字段或签名字段，详见通知说明。
  • V1 订单的通知规则与 V2 不同。本文 Go SDK 仅支持 V2；已有 V1 对接参见V1 MD5 签名规则。
