V1 接口文档

Go 版接口：本节说明 V1 支付、查询与退款接口的路径、参数及签名规则。

建议新接入使用V2 RSA 接口与Go SDK。V1 和 V2 的鉴权及通知规则不同，请按所选接口版本实现。

协议约定

所有入口接受 GET 或 POST 表单，UTF-8，金额为十进制元字符串。V1 支付入口按商户签名策略允许 MD5 或 RSA；RSA 请求仍需当前 timestamp。api.php 使用 pid/key 鉴权且要求商户策略允许 MD5，不能用 RSA 签名替代 key。

页面跳转支付

{{.API}}submit.php，V1 接口路径。提交 pid、type、out_trade_no、name、money、notify_url、return_url、sign、sign_type；按需附加 param、method 等产品参数。常规通道路径要求 notify_url 与 return_url。成功为浏览器收银台/支付跳转，不返回统一 JSON 成功体。type 留空可进入收银台；平台强制收银台时同样由用户选择。

api接口支付

{{.API}}mapi.php，V1 接口路径。常规下单要求 notify_url；return_url 可选。type 通常必填，付款码 method=scan 例外且必须 POST。正常受理返回 code=1、trade_no、payurl；强制收银台可返回 pay_type、url、jump_url。业务错误 code=-1，支付资料不等于付款完成。

订单号最长 128 字节且只允许字母、数字及 . _ - |；金额须正且最多两位小数；商品名按 UTF-8 边界截到 127 字节。推荐通知地址 https://merchant.example.com/payments/notify，回跳地址 https://merchant.example.com/payments/return。

签名算法

MD5：排除 sign、sign_type 和空字符串；其余键按字典升序拼成 k=v&k=v，原值不先 URL 编码，末尾直接追加商户 key 后取小写 MD5。纯空白值与字符串 0 均参与；传输时再进行表单编码。RSA 仅在商户策略允许时可用于两个 V1 支付入口，使用与 V2 请求相同的 SHA256WithRSA 及 300 秒窗口。

支付结果通知

由 submit.php/mapi.php 创建的订单使用 V1 订单协议：通知和回跳固定 MD5，不带 timestamp，即使该次下单请求采用 RSA。字段包括 pid、trade_no、out_trade_no、type、name、money、trade_status=TRADE_SUCCESS 和非空 param；地址自带查询参数也参与签名。异步通知为 GET，须核对原订单、金额并幂等处理，HTTP 200 正文精确返回 success。浏览器回跳不代替查单和异步通知。

api入口act

{{.API}}api.php，V1 接口路径；所有 act 都必须携带 pid 与 key。推荐 POST，避免将密钥写入浏览器历史和 URL 日志。商户不存在、key 错误或商户仅允许 RSA 时返回 code=-3；其他业务错误通常 code=-1。响应为 JSON，不添加 V2 平台 RSA 响应签名。

act额外参数结果
ordertrade_no 或 out_trade_no读取本商户单笔订单，trade_no 优先。
query无读取本商户资料及统计。
ordersoffset、limit、status；V1 可用 page本商户分页订单列表。
refund订单号、money、建议 out_refund_no对原订单申请退款，受 API 权限与原通道规则限制。
close订单号关闭原未付订单。
settleoffset、limit读取本商户结算记录。

api查询单个订单

act=order，成功 code=1。返回 trade_no、out_trade_no、api_trade_no、pid、name、type、money、status、param、buyer、clientip、addtime、endtime，附带 bill_trade_no、payurl 空字符串；部分退款时有 refundmoney，存在预授权时可能有 authorization_release_state。状态 0—4 详见订单查询。未付款 endtime 始终为空字符串。

api查询商户信息

act=query，成功 code=1。返回 pid、key、active=1、money、type、account、username、orders、order_today、order_lastday；采用另一统计字段投影时末两字段为 orders_today、orders_lastday。这两个日期字段为按创建日期区间统计的已付订单数。V1 响应含 key，须仅在受信任服务端使用，勿公开记录或传给浏览器。

api批量查询订单

act=orders，成功 code=1、data 数组。默认 limit=20，按部署的投影配置也可为 10，最多返回 50；offset 默认 0。V1 接口允许从 1 开始的 page，但 page 与 offset 不能同传。status 允许 0—4。每项字段见订单列表字段；部分投影配置附带 count（本页条数，不是订单总数）。

api提交订单退款

act=refund，参数为 trade_no 或 out_trade_no、money 和建议固定的 out_refund_no；省略 out_refund_no 时，约 10 分钟内同一订单、同一金额的重复请求视为同一笔退款。确认处理分支成功 code=0，而不是V1 查询接口的 1；未知结果可能 code=0 或 -1，须用同一 out_refund_no 重新提交以读取原退款结果，不能改退款单号重发；上游明确拒绝时返回 code=-1、msg=refund failed 与 status=0，成功终态返回 status=1。具体门控、金额上限和结果规则见退款接口。api.php 没有 act=refundquery，退款查询应由允许 RSA 的商户使用 V2 接口。

api关闭订单

act=close，trade_no 或 out_trade_no。确认关单返回 code=0、trade_no；失败或结果未知 code=-1，请查询原订单。已付款不能通过关闭退款。

api查询结算记录

act=settle，offset 默认 0、limit 默认 10 且最多 50。成功 code=1、msg、data；每项 id、uid、out_settle_no、money、status、addtime、endtime。status 为保存的结算状态字符串，不应将其强转为支付 status 数字。仅展示记录，不发起结算。

接入检查

  1. 保持现有商户订单号和回调幂等关系，确认商户凭据策略。
  2. 新业务使用 V2 路径、商户 RSA 私钥与平台公钥。
  3. 按创建订单的 V1/V2 协议选择通知算法，不能只看下单请求 sign_type。
  4. 验证查单、退款未知恢复及签名边界后再切换业务入口。
