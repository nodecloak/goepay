查询商户信息

Go 版接口：读取当前已认证商户的状态、账务可用余额及订单统计，不返回商户私钥。

请求地址

{{.API}}api/merchant/info

请求方式

POST，UTF-8，application/x-www-form-urlencoded。除页面跳转接口外，V2 不接受 GET。

请求参数说明

参数必填说明
pid是商户 ID，正整数，以商户后台 API 信息为准。
timestamp是当前 Unix 时间戳，十进制整数秒；请求时间与服务器相差不超过 300 秒。
sign_type是固定为 RSA；不会为 V2 请求自动改用 MD5。
sign是商户私钥生成的 SHA256WithRSA / PKCS#1 v1.5 签名，标准 Base64 字符串。

所有请求参数先按签名规则签名，再进行表单编码。字段只允许唯一标量值；重复键、数组形式及歧义参数名会被拒绝。

返回参数说明

参数类型说明
codeNumberV2：0 表示本次接口调用完成；-1 表示错误或需要继续核对，不等于资金最终状态。
msgString按返回分支出现的说明，客户端不应依赖固定中文文案。
timestampString平台签名时的 Unix 整数秒。
sign_typeStringRSA。
signString使用平台公钥验证的签名。
pidNumber当前商户 ID。
statusNumber能通过此入口读取的启用商户返回 1。
pay_statusNumber商户支付开关状态，实际下单还须通过平台及通道策略。
settle_statusNumber按当前商户结算权限解析的 0/1 标记。
moneyString账务可用余额，单位元；不等同转账当前可出账额度。
settle_type / settle_account / settle_nameNumber / String / String结算方式及收款资料；settle_type 不是转账余额页的 T+0/T+1 字段。
order_numNumber订单总数。
order_num_today / order_num_lastdayNumber按订单创建时间统计的今日/昨日订单数，包含未付订单。
order_money_today / order_money_lastdayString对应创建日期区间内当前 paid 订单的商品金额合计，单位元。

先检查 HTTP 状态和响应格式，再验证平台签名及 timestamp，最后读取业务字段。平台密钥可用时，正常业务错误也会签名；裸 HTTP 参数/方法错误或签名基础设施不可用时，响应可能没有签名，不能把它当作可信成功结果。

处理规则

  • 今日/昨日边界为业务时区东八区。统计基于订单创建时间，不是支付完成时间，也不是退款后净收入。
  • 本 V2 响应不返回 key；商户签名私钥只能从商户密钥管理流程安全获取。
  • 需要判断可出账余额时使用转账可用余额并满足相应权限，不能仅依据 money 发起资金操作。

返回示例

{
  "code": 0,
  "pid": 1001,
  "status": 1,
  "pay_status": 1,
  "settle_status": 1,
  "money": "100.00",
  "settle_type": 0,
  "settle_account": "",
  "settle_name": "",
  "order_num": 20,
  "order_num_today": 3,
  "order_num_lastday": 5,
  "order_money_today": "1.00",
  "order_money_lastday": "5.00",
  "timestamp": "1793400000",
  "sign_type": "RSA",
  "sign": "BASE64_SIGNATURE"
}

示例中的编号、时间和签名仅用于说明字段；请求时生成当前时间戳和真实签名，不能直接复制示例签名。
