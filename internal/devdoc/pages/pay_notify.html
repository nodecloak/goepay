支付结果通知

Go 版接口：平台确认订单已支付后，向商户通知地址发起带签名的 GET 请求；浏览器回跳用于结果展示。

通知类型

异步通知发往下单的 notify_url；浏览器回跳发往 return_url。推荐路径为 https://merchant.example.com/payments/notify 与 https://merchant.example.com/payments/return，商户可使用 Go 或其他语言实现接收端。

请求方式

GET，所有参数在 URL 查询字符串中。V2 订单使用平台 RSA 签名；不要误按 JSON POST 或钱包原始通知解析。

请求参数说明

参数说明
pid商户 ID。
trade_no / out_trade_no平台订单号及商户订单号。
type订单支付方式。
name商品名称；异步通知配置隐藏名称时为 product，不能据此替代订单识别。
money原商品订单金额，十进制元字符串。
trade_status支付完成通知固定 TRADE_SUCCESS。
param原下单扩展字符串，只有非空时附带。
timestamp / sign_type / signV2 的当前 Unix 整数秒、RSA、平台签名。每次重试更新时间及签名。

通知不包含 api_trade_no、addtime、endtime、buyer；需要这些信息时按原订单号调用订单查询。通知地址已有的查询参数也被保留并参与签名，验签必须使用收到的全部标量字段。

返回内容说明

商户验签并持久化幂等业务处理后，返回 HTTP 200，正文精确为 success。不要附带空格、换行、JSON、HTML 或 BOM；平台读取最多 4096 字节，其他响应均不确认。

Go 接收端处理顺序

  1. 严格解析唯一查询参数，使用平台公钥验证 RSA 签名与 300 秒时间窗口。
  2. 核对 pid、out_trade_no、trade_no、money、trade_status，与本地订单逐项匹配。
  3. 按商户订单号或平台订单号执行幂等处理；业务事务提交后再输出 success。
  4. 签名错误、未知订单、金额不一致或存储失败时，不返回成功确认。

Go 通知验签调用与本地测试见Go SDK 与示例。商户仍须实现本地订单核对、持久化与业务幂等，不要只检查 trade_status 而跳过这些步骤。

重试机制

通知可能重复或延迟，必须幂等。默认队列最多尝试 12 次，失败退避从约 2 秒逐步增加；若平台启用专用通知重试任务，节奏由该任务配置接管。网络失败或未精确确认会重试，实际执行时间受队列调度影响，不承诺准时送达。

页面跳转通知说明

仅已确认支付且配置 return_url 的订单可回跳，携带签名结果；回跳中的 name 保留实际商品名。前端跳转、用户截图和钱包提示不能代替服务端已验签通知或查单。

返回示例

GET /payments/notify?pid=1001&trade_no=GO202610310001&out_trade_no=ORDER_001&type=alipay&name=Example&money=1.00&trade_status=TRADE_SUCCESS&timestamp=CURRENT_UNIX_SECONDS&sign_type=RSA&sign=URL_ENCODED_SIGNATURE

HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8

success

其他说明

由 submit.php 或 mapi.php V1 入口创建的 V1 订单，回调使用 MD5 且无 timestamp，即使原请求使用了 RSA。按创建订单时的协议选择验签，详见V1 接口文档。本节其余 RSA 说明对应 V2 订单。
